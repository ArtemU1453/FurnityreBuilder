# Установка и работа без сети

PROMPT 32 §5–§8. Как приложение устанавливается на устройство, что
кэшируется, как обновляется и что именно работает без интернета.

## 1. Установка

Приложение — PWA: браузер может сохранить его на устройство и показать
значком рядом с обычными приложениями.

| Платформа | Как | Что получается |
| --- | --- | --- |
| Chrome, Edge (desktop) | значок установки в адресной строке | окно без адресной строки, значок в системе |
| Chrome (Android) | «Установить приложение» в меню | значок на домашнем экране, полноэкранный режим |
| Safari (iOS/iPadOS) | «Поделиться» → «На экран "Домой"» | значок на домашнем экране, полноэкранный режим |
| Firefox (desktop) | установки нет | работает как обычная страница, офлайн доступен |

Описание берётся из `public/manifest.webmanifest`: имя, короткое имя,
значки, цвет темы, `display: standalone`, `start_url` и `scope` — оба `/`.

**iOS манифест не читает.** Заголовок и полноэкранный режим там задаются
мета-тегами `apple-mobile-web-app-*` в `index.html`, а значок — ссылкой
`apple-touch-icon`. Поэтому в разметке есть и то, и другое.

Короткое имя — `Furniture`, одно слово: подпись под значком на домашнем
экране обрезается примерно после двенадцати знаков, и
«Furniture Builder» превращалось в «Furniture B…».

## 2. Требования

Установка и офлайн работают только по **HTTPS** (или на `localhost` —
браузер считает его защищённым контекстом). По обычному `http://`
service worker не регистрируется вовсе.

Приложение это проверяет само: `serviceWorkerAvailable()` смотрит
`window.isSecureContext` и молча ничего не делает там, где воркер
невозможен. Конструктор при этом работает — теряются только офлайн и
установка. Подробности для хостинга — `docs/DEPLOYMENT.md` §4.

## 3. Что кэшируется

Кэш собирается генератором `scripts/build-sw.mjs` из готового `dist/` —
поэтому список никогда не расходится со сборкой. Ярусов два, и это не
оптимизация, а надёжность.

| Ярус | Когда | Что | Размер |
| --- | --- | --- | --- |
| Оболочка | `install`, всё или ничего | HTML, CSS, главный чанк, значки, манифест | 702 КБ |
| Догрузка | `activate`, по одному файлу | шрифт для PDF, чанки экспорта PDF и XLSX | 1542 КБ |

`install` обязан выполнить `addAll` целиком: один сорвавшийся файл
отменяет установку. Значит в первый ярус можно класть только то, без чего
приложение вообще не откроется. Тяжёлое догружается после активации, по
файлу, с перехватом ошибки на каждом — сорванная догрузка не делает
установку неудачной.

Пока догрузка не закончилась, приложение уже работает офлайн; недоступен
окажется только экспорт.

## 4. Стратегии

Ресурсов ровно два вида, поэтому и правил два.

**Навигация — сеть первой.** Только так пользователь получает новую
выкладку. Сети нет — отдаётся сохранённая страница, и приложение
открывается офлайн. Если и её нет (совсем первое открытие без сети) —
короткая страница с объяснением, что приложение надо один раз открыть с
интернетом.

**Файлы с хешем в имени — кэш первым.** Совпало имя — совпало
содержимое: они неизменяемы по построению, спрашивать сеть не о чем.
Незнакомый файл берётся из сети и кладётся в кэш, но только если ответ
успешный и своего происхождения: класть туда 404 значило бы закрепить
ошибку навсегда.

Поиск в кэше идёт **по адресу, с `ignoreVary: true`**. Без этого офлайн
ломается на любом сервере, который шлёт `Vary` — а шлют его почти все:
`vite preview` отдаёт `Vary: Origin`, CDN обычно `Vary: Accept-Encoding`.
Записи кладёт `addAll`, чей запрос заголовка `Origin` не несёт, а
страница просит модульные скрипты запросом CORS, который несёт;
заголовки не совпадают, ответ не находится, и приложение остаётся без
своего же главного чанка, хотя тот лежит в кэше. Игнорировать `Vary`
здесь безопасно именно потому, что имена содержат хеш содержимого.

> Это не гипотеза: ошибка была найдена тестом
> `tests/e2e/pwa.spec.ts` и исправлена в PROMPT 32.

## 5. Обновление версии

Имя кэша содержит версию приложения и отпечаток списка файлов. Любая
пересборка, изменившая хоть один файл, меняет имя; `activate` удаляет все
кэши приложения с другим именем. Устаревший бандл после выкладки не
переживает активацию.

Порядок такой:

1. открытая вкладка замечает новый `sw.js`;
2. новая версия скачивается и **ждёт** — не подменяя работающее
   приложение;
3. приложение показывает «Доступна новая версия» с кнопкой «Обновить»;
4. по нажатию странице отправляется `SKIP_WAITING`, воркер сменяется,
   срабатывает `controllerchange`, страница перезагружается;
5. `activate` новой версии удаляет старый кэш.

**Почему обновление не молчаливое.** Подменить бандл под работающей
вкладкой нельзя: она уже загрузила старые модули, и отложенный импорт
экспорта после подмены попал бы в файл, которого больше нет. Это ровно та
поломка «новая выкладка → битый старый бандл», которой обновление и
должно избегать.

**Почему на первом визите перезагрузки нет.** `clients.claim()` присылает
`controllerchange` и тогда, когда воркер впервые берёт страницу под
контроль. Перезагружаться в этот момент не от чего — приложение только
что загружено с сервера. Регистрация запоминает, был ли контроллер до
неё, и перезагружает только при настоящей смене версии.

> Без этой проверки первое открытие сайта заканчивалось мгновенной
> самопроизвольной перезагрузкой. Найдено тестом в PROMPT 32.

## 6. Что работает без сети

Проверено `tests/e2e/pwa.spec.ts` на настоящей сборке с отключённой
сетью.

| Возможность | Офлайн |
| --- | --- |
| Открытие приложения | ✅ |
| Создание и правка проекта | ✅ |
| Расчёты: геометрия, деталировка, фурнитура, раскрой | ✅ |
| Трёхмерная сцена | ✅ |
| Планировщик помещения | ✅ |
| Производственные разделы и чертежи | ✅ |
| Сохранение и открытие проекта | ✅ |
| Экспорт PDF | ✅ после догрузки |
| Экспорт XLSX | ✅ после догрузки |
| Импорт проекта файлом | ✅ |

Сеть не нужна ничему из этого по существу: считает и рисует само
устройство. Единственное, что требует сети, — самое первое открытие
сайта и получение новой версии.

## 7. Данные и обновление

Кэш приложения и проекты пользователя — разные области, и они не
пересекаются:

| Область | Что в ней | Кто трогает |
| --- | --- | --- |
| Cache Storage | код приложения | service worker |
| IndexedDB | проекты и превью | приложение |

В `sw.js` нет ни одного обращения к IndexedDB — это не соглашение, а
проверка: `npm run check:release` откажет, если оно появится. Поэтому
обновление приложения не может потерять проекты; отдельно это
подтверждает тест «обновление приложения не трогает проекты
пользователя», который стирает весь кэш и убеждается, что проект на
месте.

## 8. Как убедиться самому

1. Открыть приложение по HTTPS.
2. Инструменты разработчика → Application → Service Workers: воркер
   должен быть `activated and is running`.
3. Application → Cache Storage: один кэш `furniture-builder-v…`.
4. Network → Offline, перезагрузить страницу.
5. Приложение открывается; создать проект, посчитать, сохранить,
   выгрузить PDF.

Если на шаге 2 воркера нет — проверьте, что страница открыта по HTTPS
или с `localhost`. Это самая частая причина.
