# Интерфейс редактора

> **PROMPT 26.** Каркас редактора описан здесь по состоянию на PROMPT 22.
> После сведения интерфейса в одну систему тулбар, навигация и строка
> состояния переехали в оболочку приложения, производственная
> документация стала отдельным разделом, а помещение перестало быть
> третьим видом холста. Актуальное устройство — `UX_ARCHITECTURE.md`;
> компоненты — `UI_SYSTEM.md`.


Что показано на экране, где именно и почему (PROMPT 22 §2–§3, §24–§29).
Архитектуру описывает `docs/EDITOR_ARCHITECTURE.md`.

---

## 1. Раскладка

```
┌──────────────────────────────────────────────────────────┐
│ Тулбар: имя проекта · статус производства · действия      │
├───────────────┬────────────────────────┬─────────────────┤
│ Параметры     │ Холст: 3D или схема    │ Инспектор       │
│ (<main>)      │ (схема изделия)        │ (выбранный      │
│               │                        │  объект)        │
├───────────────┴────────────────────────┴─────────────────┤
│ Строка состояния: ошибки · производство · сохранение      │
└──────────────────────────────────────────────────────────┘
```

Порядок в разметке совпадает с порядком на экране. Раскладывать колонки
сеткой в одном порядке, а в разметке держать другой — значит развести
порядок табуляции с визуальным: клавиатурный обход начинает прыгать по
экрану. Единственная перестановка — телефонная (§3 ниже), и там прыгать
уже некуда: колонка одна.

Холст с PROMPT 23 открывается трёхмерной сценой; переключатель
«3D / Схема» отдаёт тот же холст плоской SVG-схеме. Это сегментированный
контрол, а не вкладки: вкладка обещает разное содержимое, а здесь одно и
то же изделие, показанное двумя способами. Подробности —
`docs/3D_RENDERER_ARCHITECTURE.md`.

Интерфейс PrivetMaket не копировался. Раскладка выведена из того, что
уже есть в проекте: холст показывает `DebugSchemaView`, панель параметров
— команды, инспектор — выделение.

## 2. Панели

Тулбар: имя проекта, короткий статус производства, «Мои проекты»,
«Отменить», «Вернуть», «Сохранить», «PDF», «XLSX», текстовое состояние
сохранения (`role="status"`).

«Мои проекты» — переключатель библиотеки, а не отдельный экран со своим
адресом: маршрутизации в приложении нет, и заводить её ради одной панели
значило бы построить вторую навигацию рядом с существующим
переключателем видов. Пока библиотека открыта, рабочая область скрыта
атрибутом `hidden`, а не размонтирована: иначе переключение туда и
обратно каждый раз пересоздавало бы контекст WebGL. Устройство самой
библиотеки — `docs/PROJECT_LIBRARY.md`.

Боковая панель (`<main id="main">`) — разделы, каждый со своим
заголовком: **Габариты**, **Сетка**, **Двери**, **Ящики**, **Корпус**,
**Модификаторы**, **Материалы**, **Производственная документация**,
**Результат расчёта**.

**Разделов «наполнение», «полки», «кромка», «задняя стенка», «цоколь»
отдельными панелями нет** — не потому что забыты, а потому что этими
свойствами управляют уже существующие разделы: полки и ящики — часть
наполнения ячейки (инспектор), задняя стенка и цоколь — часть корпуса,
кромка — часть материала. Задание §3 прямо запрещает показывать
функции, которых нет; оно не требует заводить панель на каждое слово из
списка, если действие уже доступно в другом месте.

## 3. Адаптивность

| Ширина | Раскладка |
| --- | --- |
| > 1100 px | три колонки: параметры, холст, инспектор |
| 760–1100 px | две колонки: параметры и холст; инспектор во всю ширину под ними |
| < 760 px | одна колонка; холст поднят наверх (`order: -1`) |

Мобильная версия — та же раскладка в один столбец, а не отдельный
интерфейс. Панели теряют ограничение по высоте: собственная прокрутка
внутри колонки на телефоне только мешает.

## 4. Состояние производства

Показано дважды и в обоих местах из одного источника
(`validateProductionReadiness`): коротко в тулбаре («Готово»,
«Замечания», «Нужно подтверждение», «Ошибки») и словами в строке
состояния («Готово к производству», «Требуется подтверждение правил»,
«Изготовление невозможно»).

Устаревшим этот статус быть не может: он не кэшируется, а вычисляется от
текущего проекта при каждой отрисовке. Поэтому подписи «актуально на
момент N» в интерфейсе нет.

## 5. Сохранение

Четыре состояния: `saved`, `unsaved`, `saving`, `error`. Различие между
«сохранено» и «есть правки» определяется сравнением ссылки на проект —
состояние иммутабельно, поэтому ссылка меняется ровно тогда, когда
меняется модель.

Автосохранения нет намеренно: молчаливая запись поверх сохранённого — это
потеря работы, если пользователь экспериментировал. PROMPT 25 §24
подтвердил это решение: раз механизма автосохранения нет, вводить его не
следует. При открытии вкладки восстанавливается последний сохранённый
проект (самый свежий по `updatedAt`); если хранилище недоступно
(приватный режим), строка состояния говорит об этом прямо, а не делает
вид, что всё сохранено.

Сохранение — единственный момент, когда меняется `updatedAt`, и
единственный, когда строится превью проекта. Записанную версию
принимает `markSaved`, который НЕ трогает историю: «отменить
сохранение» не значит ничего, а сброс истории отнял бы возможность
отменить только что сохранённую работу.

## 6. Ошибки

Строка состояния показывает количество ошибок и предупреждений и текст
первой из них. Текст — кнопка: нажатие переводит выделение на затронутый
объект (`issue.target.partId` / `issue.target.nodeId`), чтобы от
сообщения можно было дойти до детали, а не искать её глазами.

## 7. Доступность

* каждый выбираемый объект холста — `role="button"` с `tabIndex={0}`,
  `aria-pressed` и текстовым именем («Боковина левая, 16 на 2000
  миллиметров»); выбор доступен по Enter и Пробелу;
* инспектор — область с постоянным именем «Свойства объекта». Область,
  которая переименовывается при каждом щелчке, бесполезна: в списке
  ориентиров её каждый раз зовут по-разному;
* состояние сохранения объявляется через `role="status"`
  `aria-live="polite"`;
* ссылка «Перейти к содержимому» — первая в порядке табуляции;
* состояние никогда не передаётся одним цветом: выделение дублируется
  `aria-pressed`, статус производства — словами, ошибка — текстом.
