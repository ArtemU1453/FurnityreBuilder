# Design System

Собственная система проекта. Следует принципам обязательного design standard
(`apple-design` skill, версия `d23d7f88`), но **не является визуальной копией**
ни Apple, ни исследовательского референса, ни любого другого продукта.

Профессиональный инструмент: плотность выше, чем в потребительском приложении,
декоративность ниже. `FUNCTION > DECORATION`.

---

## 1. ОСНОВАНИЯ

1. Рабочая область — главное. Хром не должен её отбирать.
2. Каждое значение намеренно (Craft). Магических чисел нет — только токены.
3. Одинаковые элементы ведут себя одинаково (Familiarity).
4. Цвет несёт смысл: материал, выделение, проблема. Не украшение.
5. Прозрачность и глубина объясняют иерархию, а не создают «стекло ради стекла».

---

## 2. ТОКЕНЫ: ФОРМАТ

CSS custom properties на `:root`, типизированный экспорт в TS для JS-логики.
Единый источник — `src/design-system/tokens.ts`, из него генерируется CSS.
Хардкод цвета или отступа в компоненте — ошибка ревью.

## 3. ЦВЕТ

### 3.1 Принцип

Нейтральная шкала несёт всю структуру; насыщенный цвет применяется точечно.
Два акцента: **действие** (синий) и **выделение объекта** (тот же синий, другая роль).
Семантика — только для статусов.

### 3.2 Нейтральная шкала

```
--n-0    #FFFFFF
--n-25   #FCFCFD
--n-50   #F7F8FA
--n-100  #EFF1F4
--n-200  #E2E5EA
--n-300  #CBD0D8
--n-400  #9BA3AF
--n-500  #6F7885
--n-600  #4E5663
--n-700  #363D48
--n-800  #232932
--n-900  #14181F
--n-950  #0B0E13
```

### 3.3 Акцент

```
--accent-50   #EDF4FF
--accent-100  #DBE8FF
--accent-300  #8FB6FF
--accent-500  #2F6FED     ← основной
--accent-600  #1F58C9
--accent-700  #17429A
```

### 3.4 Семантика

```
--success-500  #1F9D5B
--warning-500  #C8830E
--danger-500   #D0392B
--info-500     #2F6FED
```

Каждый цвет имеет пары `-surface` (фон плашки) и `-border`,
подобранные под контраст текста ≥ 4.5:1 в обеих темах.

### 3.5 Роли (то, чем пользуются компоненты)

```
--bg-canvas        рабочая область схемы
--bg-app           фон приложения
--bg-surface       панель, карточка
--bg-surface-raised всплывающий слой
--bg-sunken        поле ввода, углубление
--text-primary     основной текст
--text-secondary   подписи
--text-tertiary    вспомогательное
--text-inverse     на акценте
--border-subtle    разделители
--border-default   границы контролов
--border-strong    активные границы
--focus-ring       кольцо фокуса
```

### 3.6 Темы

Светлая — базовая. Тёмная переопределяет **только роли**, не палитру.
Переключение: `system` / `light` / `dark`, выбор хранится локально.

Смена темы анимируется коротким кроссфейдом 180 мс — skill прямо предупреждает
о резких скачках яркости.

### 3.7 Цвета схемы

Схема — не интерфейс, у неё своя палитра:

```
--part-fill        заливка детали (производная от Material.displayColor)
--part-stroke      контур детали
--part-edge-2mm    маркировка кромки 2 мм
--part-edge-04mm   маркировка кромки 0.4 мм
--dim-line         размерная линия
--dim-text         текст размера
--snap-guide       линия привязки
--select-outline   контур выделения
--issue-outline    контур детали с проблемой
```

Материал в схеме показывается приглушённо: заливка `displayColor` с прозрачностью
0.35 на светлой теме. Фотореализм не цель — важна читаемость конструкции.

## 4. ТИПОГРАФИКА

### 4.1 Гарнитура

```css
--font-ui: system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
--font-num: ui-monospace, 'SF Mono', 'Roboto Mono', Menlo, Consolas, monospace;
```

Системный шрифт по умолчанию — он уже несёт оптический размер и кернинг,
не требует загрузки и не создаёт внешней зависимости.
Моноширинный — **только для числовых размеров**: колонки цифр в деталировке
и на размерных линиях должны выравниваться.

Для PDF в репозитории лежит свободный шрифт с кириллицей — он используется
только генератором PDF, не интерфейсом.

### 4.2 Шкала

Tracking и leading зависят от размера — фиксированный `letter-spacing` запрещён.

| Токен | Размер | Line-height | Tracking | Вес | Применение |
| --- | --- | --- | --- | --- | --- |
| `--t-display` | 28px | 1.15 | −0.02em | 600 | заголовок экрана |
| `--t-title` | 20px | 1.25 | −0.01em | 600 | заголовок панели |
| `--t-heading` | 16px | 1.35 | −0.005em | 600 | заголовок секции |
| `--t-body` | 14px | 1.5 | 0 | 400 | основной текст |
| `--t-body-strong` | 14px | 1.5 | 0 | 550 | акцент в тексте |
| `--t-label` | 13px | 1.4 | 0.005em | 500 | подписи полей |
| `--t-caption` | 12px | 1.4 | 0.01em | 400 | вспомогательное |
| `--t-micro` | 11px | 1.35 | 0.02em | 500 | бейджи, единицы |
| `--t-num` | 13px | 1.3 | 0 | 500 | числа, `tabular-nums` |

Размеры — в `rem` относительно корневого 16px, чтобы системное увеличение текста
масштабировало интерфейс, а не ломало его.

Иерархия строится тройкой размер + вес + межстрочный. Начертаний в интерфейсе
три: 400, 500/550, 600. Больше — не нужно.

## 5. РАЗМЕРНАЯ СЕТКА

База 4px. Плотность профессионального инструмента.

```
--sp-0  0      --sp-1  4      --sp-2  8      --sp-3  12
--sp-4  16     --sp-5  20     --sp-6  24     --sp-8  32
--sp-10 40     --sp-12 48     --sp-16 64
```

Высоты контролов:

```
--h-control-sm  28
--h-control-md  32     ← база
--h-control-lg  40
--h-toolbar     48
--h-row         32     строка таблицы деталировки
```

**Зона попадания** любого интерактивного элемента — минимум 44×44 px, даже если
визуально он меньше. Достигается прозрачным паддингом, а не увеличением рисунка.
Для тонких элементов схемы (разделитель, размерная линия) — невидимая
hit-полоса 12 px.

## 6. РАДИУСЫ, ГРАНИЦЫ, ТЕНИ

```
--r-xs 4    --r-sm 6    --r-md 8    --r-lg 12   --r-xl 16   --r-full 9999
```

Правило вложенности: внутренний радиус = внешний − отступ. Концентричность —
признак аккуратности (Craft).

```
--border-hairline 1px    --border-emphasis 1.5px    --border-focus 2px
```

Тени — от глубины слоя, а не от вкуса:

```
--shadow-0  none
--shadow-1  0 1px 2px rgb(11 14 19 / .06), 0 1px 1px rgb(11 14 19 / .04)
--shadow-2  0 2px 8px rgb(11 14 19 / .08), 0 1px 2px rgb(11 14 19 / .05)
--shadow-3  0 8px 24px rgb(11 14 19 / .12), 0 2px 6px rgb(11 14 19 / .06)
--shadow-4  0 16px 48px rgb(11 14 19 / .18), 0 4px 12px rgb(11 14 19 / .08)
--shadow-drag 0 12px 32px rgb(11 14 19 / .22)
```

`--shadow-drag` применяется только к объекту, поднятому пальцем, — тень
сообщает «объект оторван от плоскости».

## 7. ПОВЕРХНОСТИ И ГЛУБИНА

Пять уровней:

| Уровень | Поверхность | Материал |
| --- | --- | --- |
| 0 | рабочая область | сплошной `--bg-canvas` |
| 1 | боковые панели | сплошной `--bg-surface`, граница `--border-subtle` |
| 2 | плавающий тулбар над схемой | полупрозрачный + `backdrop-filter: blur(20px) saturate(160%)` |
| 3 | поповер, выпадающий список | `--bg-surface-raised` + `--shadow-3` |
| 4 | модальный диалог | `--shadow-4` + затемнение фона |

Правила:
- **Полупрозрачный слой никогда не кладётся на другой полупрозрачный** — читаемость рушится.
- Полупрозрачен только уровень 2, потому что он плавает над схемой и должен
  показывать, что под ним есть содержимое.
- Боковые панели непрозрачны: под ними ничего нет, размытие было бы декорацией.
- Крупная поверхность = сильнее размытие и глубже тень, чем у мелкой плашки.
- Вместо жёсткой линии под липким заголовком — градиентная маска затухания
  там, где содержимое реально подходит под плавающий хром.
- Модальность = затемнение. Параллельная панель = без затемнения, чтобы не рвать поток.
- При `prefers-reduced-transparency` уровень 2 становится непрозрачным,
  `backdrop-filter` снимается.

## 8. ИКОНОГРАФИЯ

- Собственный набор, обводка 1.5 px, сетка 20×20, `currentColor`.
- Никаких сторонних иконочных шрифтов и CDN.
- Инлайн-SVG в компонентах — иконки участвуют в теме и не грузятся сетью.
- Иконка без подписи допустима только у общеизвестных действий
  (отмена, зум, вид). Всё остальное подписывается: если нужен tooltip,
  чтобы понять кнопку, — сопоставление слабое.
- Иконки в интерфейсе не путаются с обозначениями на схеме: у схемы своя
  графика (размерные стрелки, штриховки), с иным весом линии.

## 9. СОСТОЯНИЯ КОМПОНЕНТОВ

Полная матрица `REST → HOVER → PRESSED → ACTIVE → FOCUS → DISABLED → LOADING → ERROR → SUCCESS`.

### 9.1 Кнопка

| Состояние | Primary | Secondary | Ghost | Danger |
| --- | --- | --- | --- | --- |
| REST | `accent-500`, текст inverse | `bg-surface` + `border-default` | прозрачная, текст secondary | `danger-500`, текст inverse |
| HOVER | `accent-600` | `n-50`, `border-strong` | `n-100`, текст primary | затемнение 8 % |
| PRESSED | `accent-700` + `scale(.97)` | `n-100` + `scale(.97)` | `n-200` + `scale(.97)` | + `scale(.97)` |
| ACTIVE (вкл.) | `accent-100` фон, `accent-700` текст | — | `accent-50` фон | — |
| FOCUS | кольцо 2 px `--focus-ring`, отступ 2 px | то же | то же | то же |
| DISABLED | `n-200` фон, `n-400` текст, без hover/press | то же | текст `n-400` | то же |
| LOADING | спиннер вместо иконки, ширина фиксирована, текст сохраняется | | | |
| ERROR | не состояние кнопки — ошибку показывает форма | | | |
| SUCCESS | галочка 1.2 с, затем возврат к REST | | | |

PRESSED появляется **на pointerdown**, а не на click.
Ширина кнопки при переходе в LOADING не меняется — layout не должен дёргаться.

### 9.2 Числовое поле (главный контрол приложения)

| Состояние | Оформление |
| --- | --- |
| REST | `--bg-sunken`, `--border-default`, число `--t-num` справа, единица «мм» — `--t-micro`, `--text-tertiary` |
| HOVER | `--border-strong` |
| FOCUS | `--border-focus` акцентная + кольцо; текст выделен целиком |
| ACTIVE (идёт drag связанной размерной линии) | подсветка фона `accent-50`, значение обновляется в реальном времени |
| DISABLED | `n-100`, текст `n-400` |
| ERROR | граница `danger-500`, под полем — строка с причиной и допустимым диапазоном |
| WARNING | граница `warning-500`, строка-пояснение; ввод **не блокируется** |
| SUCCESS | отдельного состояния нет — успех это отсутствие ошибки |

Шаговые стрелки — только по hover/focus, чтобы не засорять плотную панель.

### 9.3 Селект, сегментированный переключатель, вкладки

| Состояние | Оформление |
| --- | --- |
| REST | текст secondary, фон прозрачный |
| HOVER | фон `n-100` |
| PRESSED | `scale(.98)` |
| ACTIVE | «пилюля» `bg-surface` + `--shadow-1`, текст primary; пилюля **переезжает** к новой вкладке пружиной, а не мигает |
| FOCUS | кольцо |
| DISABLED | текст `n-400`, курсор `not-allowed` |

### 9.4 Ячейка схемы

| Состояние | Оформление |
| --- | --- |
| REST | контур `--part-stroke` 1 px |
| HOVER | контур `--accent-300` 1.5 px |
| PRESSED | заливка `accent-50` немедленно |
| SELECTED | контур `--accent-500` 2 px + заливка 8 % |
| MULTI-SELECTED | то же + счётчик выделенных на тулбаре |
| FOCUS | дополнительное внешнее кольцо (видно поверх выделения) |
| ISSUE | контур `--issue-outline`, пунктир; иконка проблемы в углу |
| DRAG-TARGET | заливка `accent-50`, контур пунктиром |
| DRAG-TARGET-INVALID | нейтральный серый, курсор `no-drop` (не красный) |

### 9.5 Панель, sheet, диалог

| Состояние | Оформление |
| --- | --- |
| ЗАКРЫТА | не в DOM (панель) / `hidden` (sheet) |
| ОТКРЫВАЕТСЯ | масштаб + смещение + рост blur от точки-источника |
| ОТКРЫТА | уровень 3 или 4 |
| ПЕРЕТАСКИВАЕТСЯ (sheet) | следует за пальцем 1:1, тень усиливается |
| ЗАКРЫВАЕТСЯ | обратный путь; прерываема в любой момент |

### 9.6 Уведомления

| Тип | Оформление | Поведение |
| --- | --- | --- |
| status (сохранение) | строка в статус-баре | без анимации появления, меняется текст |
| success | тост, `success` акцент | 4 с, можно смахнуть |
| warning | плашка в панели проблем | остаётся до устранения |
| error | плашка + подсветка объекта в схеме | остаётся; клик — переход к объекту |

Модальный диалог — только для действительно необратимого. Удаление секции
обратимо через undo, значит диалог не нужен: достаточно тоста с «Отменить».
Частые подтверждения приучают кликать не глядя — skill прямо предупреждает.

## 10. КОМПОНОВКА ЭКРАНА

```
┌──────────────────────────────────────────────────────┐
│ Тулбар: проект · undo/redo · виды · экспорт          │  48px, уровень 2
├───────────┬──────────────────────────┬───────────────┤
│ Структура │                          │ Свойства      │
│ (дерево   │      Рабочая область     │ выделенного   │
│  секций)  │      (схема, уровень 0)  │ объекта       │
│  240px    │                          │   300px       │
├───────────┴──────────────────────────┴───────────────┤
│ Статус: размеры · проблемы · сохранение              │  28px
└──────────────────────────────────────────────────────┘
```

- Схема всегда занимает максимум. Панели сворачиваются, схема не сворачивается.
- < 1100 px — правая панель становится выдвижной.
- < 760 px — панели превращаются в нижние sheet; схема остаётся на весь экран.
- Тулбар плавает над схемой на узких экранах, экономя высоту.

**Мобильный.** Не «урезанная версия», а другой режим: просмотр и правка
размеров доступны полноценно, сложное структурное редактирование — через
пошаговые sheet. Экспорт работает везде.

## 12. ДОСТУПНОСТЬ

| Требование | Реализация |
| --- | --- |
| Контраст текста | ≥ 4.5:1 обычный, ≥ 3:1 крупный; проверяется тестом токенов в CI |
| Контраст нетекстовых элементов | ≥ 3:1 для границ контролов и контуров выделения |
| `prefers-reduced-motion` | см. `MOTION_SYSTEM.md` §8 |
| `prefers-reduced-transparency` | уровень 2 → непрозрачный, blur снят |
| `prefers-contrast: more` | почти сплошные фоны, границы 1.5 px, тени убраны |
| Фокус | `:focus-visible` виден на всех интерактивных элементах, включая элементы SVG |
| Клавиатура | полный сценарий проходится без мыши (`INTERACTION_MODEL.md` §5) |
| Screen reader | каждая деталь схемы — `role="button"` с `aria-label` вида «Полка, 568 на 480 мм, секция A»; изменения объявляются через `aria-live="polite"` |
| Масштаб текста | до 200 % без потери функциональности; отступы в `rem` |
| Цвет | никогда не единственный носитель смысла: проблема = цвет + иконка + текст |
| Движение | никогда не единственный носитель смысла |
| Целевые зоны | ≥ 44×44 px |

## 13. ЧЕГО В СИСТЕМЕ НЕТ

| Отсутствует | Почему |
| --- | --- |
| Декоративный glassmorphism | `FUNCTION > DECORATION`; прозрачность только там, где объясняет слои |
| Градиенты на кнопках и панелях | шум, мешает читать плотную информацию |
| Более трёх начертаний | избыточная иерархия |
| Анимация появления hover | hover обязан быть мгновенным |
| Иконки без смысла | каждая должна что-то значить |
| Внешние шрифты, иконки, CSS-фреймворки с CDN | требование автономности |
| Скругления > 16 px на рабочих поверхностях | съедают полезную площадь |
| Баннеры, промо, реклама, апселл | продукт бесплатный и без рекламы |
