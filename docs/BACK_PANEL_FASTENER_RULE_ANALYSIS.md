как основа для количества крепежа.

function perimeterOf(part: Part): Mm {

## §4 — соответствует ли модель реальному контуру

### Периметр посчитан верно, но контур крепления — не только периметр

Задняя стенка лежит в z[0…3]. Внутренние вертикали — две перегородки —
занимают z[3…600], то есть их задние торцы **упираются в стенку по всей
высоте**:

| Опора | Длина линии контакта |
| --- | --- |
| периметр панели | 8000 мм |
| задний торец перегородки 1 | 2168 мм |
| задний торец перегородки 2 | 2168 мм |
| **итого линий контакта** | **12 336 мм** |

Накладная задняя стенка в реальной сборке крепится и к перегородкам —
иначе середина панели остаётся неприжатой, а перегородка теряет
поперечную фиксацию.

**Вывод: существующий периметр НЕ может напрямую использоваться для
количества крепежа.** Он занижает контур на 4336 мм — на **35 %** в этом
изделии. Чем больше секций, тем больше занижение.

### Какие стороны входят в расчёт

Все четыре, безусловно. Верх, низ, обе боковые. Правило `2·(x+y)` не
различает стороны вовсе.

Это тоже вопрос к источнику: крепится ли накладная стенка по всем
четырём сторонам одинаково, и совпадает ли шаг по вертикали и по
горизонтали.

### Способ монтажа читается только ради текста

В модели четыре способа:

```ts
export type BackPanelMount =
  | { kind: 'none' }
  | { kind: 'overlay'; thickness }
  | { kind: 'inset-groove'; thickness; grooveDepth; grooveOffsetFromRear }
  | { kind: 'inset-flush'; thickness };
```

Правило читает `mount.kind` **только чтобы подставить слово в
предупреждение**. На расчёт способ не влияет.

Между тем разница принципиальная: **стенка в пазу (`inset-groove`) по
сторонам, попавшим в паз, крепежа не требует вовсе** — её держит паз. Для
неё «периметр × шаг» даёт не приблизительное, а заведомо неверное число.

**Вывод: правило обязано ветвиться по способу монтажа.** Сегодня не
ветвится.

## UNCONFIRMED

| Вопрос §4 | Ответ |
| --- | --- |
| какой крепёж используется | не подтверждён |
| расстояние между точками | **не подтверждено** — главный блокер |
| правила по углам | не подтверждены |
| максимальный шаг | не подтверждён |
| различие по материалу стенки | не подтверждено |
| весь периметр или отдельные стороны | **не подтверждено**, и от ответа зависит ветвление по монтажу |
| крепление к внутренним вертикалям | **не подтверждено**; сейчас не учитывается вовсе |

## DESIGN DECISION

| Решение | Обоснование |
| --- | --- |
| Периметр не переделывать | как периметр он верен. Неверно было бы выдать его за контур крепления |
| Длины внутренних опор не добавлять | пока не подтверждено, что к ним вообще крепят, поле было бы догадкой |
| Ветвление по монтажу не вводить | без шага ветвить нечего |
| Формулу `2·(x+y)` оставить | она описывает то, что называет: периметр детали |

## IMPLEMENTATION GAP

1. **Шаг крепления** — блокер.
2. Подтвердить, крепится ли стенка к внутренним вертикалям. Если да —
   добавить их длины к контуру (**это не мелочь: +35 % в контрольном
   изделии**).
3. Подтвердить поведение при `inset-groove` и `inset-flush`; добавить
   ветвление.
4. Подтвердить правила по углам и различие сторон.

Пункт 1 — необходимое условие; пункты 2–4 определяют, будет ли результат
верным, а не только ненулевым.

### Предупреждение будущему автору

Соблазн «периметр уже считается, осталось поделить на шаг» — **ловушка**.
Полученное число будет меньше нужного на длину внутренних опор и вовсе
неверным для стенки в пазу.
