## 0. Главное о доказательствах: читать до таблиц

**Референс из этой среды недоступен.** Проверено сегодня заново, четвёртой
независимой проверкой:

| Способ | Результат |
| --- | --- |
| `curl https://privetmaket.ru/` | код `000`, туннель обрывается |
| `curl https://privetmaket.ru/garderob` | код `000` |
| `curl http://privetmaket.ru/` | код **403** от шлюза |
| `WebFetch` | `EGRESS_BLOCKED: blocked by the network egress proxy` |
| Диагностика шлюза | `connect_rejected: gateway answered 403 to CONNECT (policy denial)` |

Отказ политики, а не сбой сети. То же зафиксировано на PROMPT 33,
PROMPT 52 и при составлении `PRIVETMAKET_FUNCTIONAL_SPEC.md`.

### Что это означает для источников (§4)

Иерархия источников PROMPT 65-B §4 доступна не вся:

| Уровень | Источник | Доступен? |
| --- | --- | --- |
| 1 | поведение интерфейса референса | **НЕТ** |
| 2 | документация и справка референса | **только пересказом поисковика** |
| 3 | загружаемые чертежи/примеры | **НЕТ** |
| 4 | явно названная фурнитура на референсе | **НЕТ** |
| 5 | документация производителя названной фурнитуры | недостижима (нечего называть) |
| 6 | документация выбранного совместимого стандарта | частично (PROMPT 65-A) |

Поэтому ниже введены **классы доказательства**, и ни одна строка не
записана выше своего класса:

| Класс | Что значит |
| --- | --- |
| `D1 — НАБЛЮДЕНО` | интерфейс референса виден собственными глазами. **Таких строк ноль.** |
| `D2 — ПЕРЕСКАЗ` | название страницы референса и её краткое изложение поисковым индексом. Формулировки не сверены, атрибуция внутри сводки не гарантирована |
| `D3 — РЕПОЗИТОРИЙ` | старые документы этого репозитория. §0 запрещает выводить из них правила конструкции |
| `D0 — НЕ НАБЛЮДАЛОСЬ` | ничего не найдено |

> **§0 соблюдён буквально.** Ни одна величина ниже не переведена из
> «видно» в «реализуемо». Там, где поисковая сводка смешивает страницу
> референса с посторонними статьями, это отмечено — и такая строка не
> может служить основанием для кода.

## 3. Важнейшая находка аудита

Она не про ящик.

> **Из спецификации фурнитуры, которую выдаёт приложение, изделие
> невозможно собрать: корпусного крепежа в ней нет.**

Обычный шкаф с дверями и полками даёт сегодня такую спецификацию:

```
Полкодержатель   16 шт
Направляющая      2 шт   (если есть ящик)
Ручка             1 шт   (если выбрана)
```

и всё. Ни конфирматов, ни петель, ни крепежа задней стенки. Человек,
пришедший с этим списком в магазин, не купит то, чем корпус скрепляется.

Причём **механика уже написана**: `findCarcassJoints` находит все стыки
«вертикаль — горизонталь» и печатает их количество в предупреждении.
Не хватает ровно одного числа — сколько крепежа на стык:

```ts
/** Количество крепежа на один стык. `UNKNOWN (T-HW-03)`. */
export const CARCASS_FASTENERS_PER_JOINT: number | undefined = undefined;
```

То же у задней стенки: периметр считается, шаг крепления неизвестен. То
же у петель: створки находятся, порог «сколько петель на какую высоту»
неизвестен.

**Три числа** — крепёж на стык, шаг по периметру задней стенки, пороги
петель по высоте — превращают пустую спецификацию в пригодную к закупке.
Это меньше работы, чем короб ящика, и влияет на **каждое** изделие, а не
на те, где есть ящик.

## 7. Аудит правил `T-DRW-*` (§13)

Для каждого: текущая формулировка, источник, описывает ли оно
РЕАЛИЗОВАННОЕ поведение или НАБРОСОК будущего, подтверждено ли, чего не
хватает.

Введены четыре ярлыка состояния, которых §13 требует, и дальше они
используются во всей документации:

| Ярлык | Значение |
| --- | --- |
| `IMPLEMENTED` | код это делает сегодня |
| `CONFIRMED BUT NOT IMPLEMENTED` | правило подтверждено источником, кода нет |
| `UNCONFIRMED DESIGN SKETCH` | формула записана, источником не подтверждена. **Читать как план, не как поведение** |
| `UNKNOWN` | ни правила, ни наброска |

| ID | Формулировка | Источник | Описывает | Состояние | Чего не хватает |
| --- | --- | --- | --- | --- | --- |
| `T-DRW-01` | Модель и длина направляющей: ряд длин и правило выбора по глубине | реестр `UNKNOWNS.json` | реализованное поведение частично: **количество** считается (2 на ящик), артикул и длина — нет | `IMPLEMENTED` (количество) + `UNKNOWN` (модель) | каталог с рядом длин и правилом подбора |
| `T-DRW-02` | Тип направляющих и боковой зазор короба | реестр | **больше ничего не описывает** | `SPLIT` (PROMPT 65-A) | — разделено на `T-DRW-06` и `T-DRW-07` |
| `T-DRW-03` | Ряд номинальных длин и правило округления | реестр | набросок | `UNCONFIRMED DESIGN SKETCH` | подтверждение ряда 250…600 шаг 50 и правила округления |
| `T-DRW-04` | Формула фасада ящика: зазоры | реестр | **реализованное поведение**: `DEFAULT_OVERLAY` применяется | `IMPLEMENTED`, значения не подтверждены | величины зазоров именно для ящиков |
| `T-DRW-05` | Ограничение количества ящиков в ячейке | реестр | реализованное: предела нет, границу ставит только вместимость | `IMPLEMENTED` (сознательное отсутствие предела) | подтверждение, что предел вообще нужен |
| `T-DRW-06` | Боковой зазор 12.7 мм на сторону | PROMPT 65-A: данные изделий Hettich, Accuride 3832 | правило конструкции | **`CONFIRMED BUT NOT IMPLEMENTED`** | ничего; ждёт короба, чтобы примениться |
| `T-DRW-07` | Конструкция короба: высота боковины, положение по Y, дно, задняя стенка, передняя стенка, глубина | PROMPT 65-A | набросок | `UNCONFIRMED DESIGN SKETCH` | шесть величин; см. `FR04_DRAWER_MODEL_ANALYSIS.md` §6 |

### Что изменил этот аудит в `T-DRW-*`

Одно уточнение, и оно касается `T-DRW-07`: пересказ страницы сборки
референса называет состав короба — **две боковины, передняя и задняя
стенка, фасад, тонкое дно**. Это снимает развилку «три стенки против
четырёх», которую PROMPT 65-A не смог разрешить, и указывает на вариант с
четырьмя стенками и накладным фасадом.

Уточнение записано как `D2` и **не переводит `T-DRW-07` в
`confirmed`**: состав деталей — не размеры. Шесть величин по-прежнему не
подтверждены.

### Состояние `ARCHITECTURE.md`

§13 требует, чтобы неподтверждённые будущие формулы нельзя было принять
за реализованное поведение. Блок «Ящик» в `ARCHITECTURE.md` приведён в
порядок в PROMPT 65-A: над ним стоит предупреждение, а каждая строка
формулы помечена своим `T-DRW-*`. Проверено в этом аудите повторно —
формулировка соответствует ярлыкам выше.
