# План приёмки выпуска

PROMPT 35 §2. Что проверяется перед выпуском, как именно и что считается
доказательством. Документ описывает МЕТОД; результат конкретного прогона —
`FINAL_RELEASE_ACCEPTANCE.md`.

Главное правило приёмки: **предыдущие отчёты — входные данные, а не
доказательство.** Статус `READY`, поставленный на прошлом этапе, здесь
ничего не подтверждает; каждый критерий проверяется заново.

## 1. Пользовательские сценарии

Восемь сценариев, каждый проходится на production-сборке и проверяет
РЕЗУЛЬТАТ действия, а не отсутствие падения.

| Сценарий | Что проверяется | Как | Ожидание |
| --- | --- | --- | --- |
| A — первый проект | Габариты, секции, полки, сохранение | `tests/e2e/acceptance.spec.ts` | Каждое действие меняет число деталей в подписи сцены; проект сохраняется |
| B — сложное изделие | Неравные секции, сетка, дверь, ящики, цоколь | там же | Ни `NaN`, ни `Infinity`, ни `undefined` в подписи; больше десяти деталей; деталировка не пуста |
| C — сохранение и перезагрузка | Проект не становится другим | там же | Габарит, число деталей и число секций совпадают до и после |
| D — отмена и повтор | Эквивалентность состояний | там же | Два шага назад и два вперёд возвращают ровно те же числа деталей |
| E — производство | Все разделы об одном изделии | там же | Четыре раздела открываются и не пусты |
| F — экспорт | Реальные файлы с именами | там же | Обе загрузки без ошибки; имя с расширением; якорь в документе |
| G — 3D | Сцена следует за моделью | там же | Правка габарита меняет подпись сцены; щелчок открывает инспектор |
| H — помещение | Расстановка и проёмы переживают перезагрузку | там же | Проём на месте после `reload` |

## 2. Приёмка расчёта

Свойства, обязательные при ЛЮБЫХ числах — в отличие от регрессии, которая
сторожит конкретные значения.

| Критерий | Как | Ожидание |
| --- | --- | --- |
| Нет `NaN` и бесконечностей | Обход всех чисел результата рекурсивно | Ноль неконечных величин |
| Детерминированность | Два прогона, сравнение JSON | Побайтовое совпадение |
| Уникальность идентификаторов | Множество против длины — узлы и детали | Совпадают |
| Прослеживаемость деталей | Каждая деталь ссылается на живой узел или на корпус | Мёртвых ссылок нет |
| Ячейка не деталь | Идентификатор ячейки не встречается среди деталей | Не встречается |
| Нет двойного счёта | Сумма количеств спецификации против числа построенных деталей | Равны |
| Источник у позиции | `sourcePartIds` не пуст и по длине равен количеству | Выполняется |
| Раскрой ничего не теряет | Размещённые + неразмещённые против всех | Равны |
| Отказ объясняется | У каждой неразмещённой детали причина с размерами | Выполняется |
| Источник у фурнитуры и присадки | `ruleId` и `reason` заполнены | Выполняется |
| Молчания нет | Статус хуже «готово» сопровождается сообщением | Выполняется |

Проверяется на семи фикстурах: `carcass`, `sections`, `shelves`, `doors`,
`drawers`, `complex`, `stress`.

## 3. Согласованность слоёв

| Критерий | Как | Ожидание |
| --- | --- | --- |
| Сцена = геометрия по составу | Число объектов-деталей против числа деталей | Равны |
| Сцена = геометрия по размерам | Размеры каждого объекта против детали | Совпадают до 0.001 мм |
| Файл = проект | `toJson → fromJson → toJson` | Побайтовое совпадение |
| Файл = расчёт | Производство до и после кругового пути | Побайтовое совпадение |

Отдельной «правды» у слоя быть не может: рендерер размеров не считает,
он читает готовые.

## 4. Приёмка хранения

| Критерий | Как | Ожидание |
| --- | --- | --- |
| Новый проект | Сценарий A | Сохраняется |
| Существующий проект | Сценарий C | Возвращается тем же |
| Сложный проект | Круговой путь на фикстуре `complex` и `stress` | Не меняется |
| Импорт | `tests/unit/persistence/hardening.test.ts` | Проверяется целиком |
| Битый файл | Там же | `DeserializationError` с текстом |
| Чужая версия схемы | Там же | `MigrationError`, не молчание |
| Обновление приложения | `tests/e2e/pwa.spec.ts` | Проекты на месте после стирания кэша |

## 5. Приёмка производства

| Раздел | Критерий |
| --- | --- |
| Детали | Размеры, количество, материал, кромка, источник |
| Фурнитура | Количество, правило, причина, зависимость от геометрии |
| Присадка | Правило и причина у каждой операции; ноль операций — с объяснением |
| Раскрой | Лист, рез, поворот, неразмещённые, использование |
| Спецификация | Группировка, итоги, отсутствие дублей |

## 6. Приёмка экспорта

Проверяются РЕАЛЬНЫЕ файлы, а не факт «файл не null».

| Формат | Как | Ожидание |
| --- | --- | --- |
| PDF | `tests/unit/export/pdf.test.ts` + сценарий F | Открывается, страницы на месте, кириллица читается |
| XLSX | `tests/unit/export/xlsx.test.ts` (читается `exceljs`) + сценарий F | Открывается, листы и таблицы соответствуют расчёту |
| Соответствие расчёту | `tests/unit/integration/export-content.test.ts` | Значения совпадают с производственным результатом |

## 7. Приёмка мобильной версии

Ширины 320 / 375 / 390 / 430 плюс планшет и десктоп,
`tests/e2e/mobile.spec.ts`. Проверяется не только отсутствие
горизонтальной прокрутки, но и достижимость: лист параметров
открывается и закрывается, шаги доступны, сцена занимает экран.

## 8. Приёмка доступности

Подписи у полей, роли, порядок и видимость фокуса, объявление ошибок,
Esc в диалогах, полное прохождение сценария с клавиатуры, Ctrl+Z и
Ctrl+Shift+Z. Уважение `prefers-reduced-motion`.

## 9. Приёмка работы без сети

Открыть, дождаться регистрации воркера, отключить сеть, перезагрузить,
создать проект, посчитать, сохранить, выгрузить PDF и XLSX —
`tests/e2e/pwa.spec.ts`. Частичная работа записывается как `PARTIAL`, не
как `PASS`.

## 10. Приёмка производительности

Сравнение с зафиксированными бюджетами `PERFORMANCE_BUDGET.md`. Пороги
взяты ДО измерения и не подгоняются под результат.

## 11. Безопасность и сохранность данных

Проверка импортируемого файла, размер до чтения, битый JSON, загрязнение
прототипа, небезопасный HTML и адреса, секреты в сборке, внешние
обращения — `check:brand`, `check:release`, `hardening.test.ts`.

## 12. Ворота выпуска

Двенадцать обязательных ворот. Отказ хотя бы одного критического ворота
запрещает статус `READY` — независимо от того, насколько хорош остальной
результат.
