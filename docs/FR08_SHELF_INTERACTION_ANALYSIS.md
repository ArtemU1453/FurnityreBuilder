## Доменное понятие (§3)

```ts
export type LeafFill =
  | { readonly kind: 'empty' }
  | { readonly kind: 'shelves'; readonly shelves: readonly Shelf[] }
  | { readonly kind: 'drawers'; readonly drawers: readonly Drawer[] }
  | …
```

Полка — это **вид наполнения плюс список отдельных деталей** (ответ `E`:
`C` + `A`). Каждая `Shelf` имеет свой `id`, `placement`, `mounting` и
попадает в деталировку.

**Количество полок — это `fill.shelves.length`.** Отдельного поля
«сколько полок» в модели нет, второго места, где хранилось бы число, —
тоже.

**Источник истины один и он в домене.** Проблема `FR-08` целиком в
интерфейсе: два органа управления пишут в одно состояние с разной
семантикой, а прочитать это состояние там, где человек смотрит, нельзя.

## Пути (§2)

### Шаг 5 «Полки» — поле «Полок в выбранной ячейке»

| | |
| --- | --- |
| **Требует выделения** | да |
| **Ввод** | число ≥ 0 |
| **Команда** | `SetFill` |
| **Изменение модели** | `count <= 0 ? { kind: 'empty' } : createShelvesLeaf(ids, count).fill` |
| **Как представлено количество** | напрямую — длина списка |
| **Что делает с существующими** | **заменяет целиком**: новые `Shelf` с новыми `id` |
| **Может добавить** | да (0 → N) |
| **Может заменить** | да (N → M) |
| **Может убрать** | да (N → 0 → `empty`) |
| **Уживается с другим путём** | пишет то же поле |

### Шаг 6 «Наполнение» — переключатель «Пусто / полки / ящики»

| | |
| --- | --- |
| **Команда** | `SetFill` |
| **Изменение модели** | `createShelvesLeaf(ids, Math.max(1, текущее)).fill` |
| **Как представлено количество** | косвенно: сохраняет уже заданное, иначе 1 |
| **Что делает с существующими** | сохраняет число, но пересоздаёт `Shelf` с новыми `id` |
| **Может добавить** | да (0 → 1) |
| **Может заменить** | нет — число не меняет |
| **Может убрать** | да, через «Пусто» |

### Инспектор — «Добавить полки»

С PROMPT 59 делегирует в `setCellFillKind('shelves')`, то есть ведёт
себя ровно как переключатель шага 6.

### Шаг 4 «Ячейки» — поле «Полок в каждой ячейке»

Другая область: параметр **создания** новых отделений при делении, а не
правка существующего. В `FR-08` не входит.

### Клавиатура и телефон

Отдельных путей нет: те же органы управления, тот же обработчик. На
телефоне панель шага и инспектор — выдвижные листы.

## Что измерено на собранном приложении

| Проверка | Результат |
| --- | --- |
| Инспектор показывает ЧИСЛО полок | **нет** — только «Наполнение: полки» |
| «Добавить полки» на отделении с 3 полками | **3 → 3**: кнопка не делает ничего |
| Поле шага 5 на отделении с ЯЩИКАМИ | **показано, значение `0`** |
| Ввод `2` в это поле | **ящик уничтожен молча**: фасадов ящиков 1 → 0, полок 0 → 2 |
| Отмена 0 → 3 | 0 — один шаг |
| Повтор | 3 |
| Отмена 3 → 5 | 3 — один шаг |

## Три настоящих дефекта

**1. Состояние не видно там, где человек смотрит (§8).** Инспектор
сообщает вид наполнения, но не количество. Чтобы узнать «сколько здесь
полок», надо уйти на шаг 5.

**2. Кнопка, которая ничего не делает (§9).** «Добавить полки» на
отделении, где полки уже есть, сохраняет прежнее число — то есть
молча не делает ничего. Подпись обещает добавление.

**3. Поле шага 5 врёт про чужое наполнение и уничтожает его (§18 E).**
На отделении с ящиками поле показывает `0`, что читается как «здесь нет
полок»; на деле там ящик. Ввод любого числа заменяет ящик полками без
вопроса.

Отмена при этом работает правильно и атомарно — менять её архитектуру не
требуется (§14).

## Выбранная модель (§4)

**«В этом отделении N полок.»** Один вопрос — один ответ, в одном месте.

## Решение

| Что | Решение по §6 |
| --- | --- |
| Поле «Полок в выбранной ячейке» (шаг 5) | **авторитетно для количества** — оно и остаётся единственным местом, где задаётся число |
| Переключатель «полки» (шаг 6) и кнопка «Добавить полки» (инспектор) | **`C` — меняют назначение**: это действие «сделать отделение полочным» (0 → N), а не управление числом. Предлагаются только когда полок ещё нет |
| Количество в инспекторе | **показывается**, но не правится: параметр настраивается шагом (решение PROMPT 59 не отменяется) |
| Поле шага 5 на чужом наполнении | **не показывается**: вместо `0` — объяснение, что в отделении стоит другое |

### Семантика (§9)

| Переход | Где | Подпись |
| --- | --- | --- |
| 0 → N | инспектор «Добавить полки», затем число на шаге 5 | «Добавить полки» |
| N → M | шаг 5, поле | «Полок в выбранном отделении» |
| N → 0 | шаг 5, `0` — или инспектор «Очистить ячейку» | «0 — отделение без полок» |

Кнопка «Добавить полки» больше не появляется там, где полки уже есть:
её работа — 0 → N, и другого значения у неё нет.

## Правила геометрии не трогаются (§11)

Раскладка полок, равномерное распределение, отступы, опоры, кромка и
присадка не меняются. Обе прежние ветки уже звали одну и ту же
доменную фабрику `createShelvesLeaf`, поэтому расхождения в геометрии
между путями **нет** и документировать нечего.
