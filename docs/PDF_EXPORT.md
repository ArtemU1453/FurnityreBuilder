# Экспорт PDF

Реализация: `src/export/pdf.ts`. Общая архитектура —
`docs/EXPORT_ARCHITECTURE.md`.

---

## 1. Состав документа

| Раздел | Формат | Источник данных |
| --- | --- | --- |
| Титульный лист | A4 | `metadata`, `totals`, ошибки и предупреждения |
| Общие размеры, материалы, кромка | A4 | `dimensions`, `materials`, `edgeBanding` |
| Спецификация деталей | A4, таблица | `parts` |
| Фурнитура | A4, таблица | `hardware` |
| Присадка | A4, таблица | `drilling` |
| Чертёж детали | A4, по одному листу на деталь с отверстиями | `drawings` |
| Карта раскроя | **A3**, по листу на заготовку | `sheets` |
| Неразмещённые детали | A4, если они есть | `unplaced` |
| Требует подтверждения | A4 | `confirmations` |

Титульный лист несёт статус расчёта крупно и первым: документ, по
которому нельзя работать, обязан объявлять это на входе, а не в
примечании на последней странице.

## 2. Кириллица

Стандартные 14 шрифтов PDF не содержат кириллицы — производственная
документация на русском без встроенного шрифта невозможна в принципе,
каким бы способом ни собирался файл.

Встраивается Liberation Sans (SIL OFL), лежащий в репозитории
(`public/fonts/`). `pdf-lib` + `@pdf-lib/fontkit` делают подмножество:
в документ попадают только использованные глифы, поэтому файл на десяток
страниц весит десятки килобайт, а не полмегабайта.

Шрифт передаётся генератору параметром (`createProductionPdf(data, {font})`),
а не читается им из файловой системы или сети: одна и та же функция
работает и в браузере, и в тесте.

**Тест.** «шрифт встроен как Type0 с кодировкой Identity-H»,
«без шрифта документ не собирается молча».

## 3. Вёрстка

**Спецификация (§14).** Переносы страниц, повторяющиеся заголовки
таблиц, отсутствие обрезанных строк и наложений, читаемость при печати.

**Доменное правило.**

- Курсор вёрстки (`Layout`) сам заводит новую страницу, когда до нижнего
  поля остаётся меньше высоты строки.
- Заголовок таблицы печатается заново на каждой новой странице: таблица,
  у которой шапка осталась на предыдущем листе, читается наугад.
- Текст, не влезающий в колонку, обрезается с многоточием по фактической
  ширине глифов (`widthOfTextAtSize`), а не по числу символов: наложение
  двух колонок читать нельзя.
- Длинные абзацы переносятся по словам.
- Подпись детали на карте раскроя ставится, только если физически
  помещается внутрь прямоугольника.
- Шрифт назначается странице один раз, а не при каждом рисовании: иначе
  `pdf-lib` заводит в ресурсах отдельный ключ со случайным суффиксом на
  каждый вызов — лишние байты и случайность там, где документ обязан
  быть предсказуемым.

**Тест.** «страницы имеют формат A4, карты раскроя — A3», «ровно один
шрифт на страницу».

## 4. Чертежи деталей

Лист выпускается только для деталей, у которых есть отверстия: лист с
прямоугольником и двумя размерами не несёт ничего сверх строки
спецификации и только раздувает документ.

На чертеже: контур детали в масштабе, отверстия пласти окружностями в
том же масштабе, под чертежом — таблица отверстий с локальными
координатами. Координаты те же, что в разделе «Присадка», поэтому
чертёж и таблица не могут разойтись.

**Ограничение.** Отверстия в торцах на чертеже пласти не показываются
(им нужна отдельная проекция); в таблице под чертежом они есть.

**Сегодня чертежей нет ни одного**: параметры присадки не подтверждены
(`T-DRILL-01…05`), операций не создаётся, и деталей с отверстиями не
существует. Раздел заработает вместе с присадкой.

## 5. Карта раскроя

Формат A3: лист 2750 мм, ужатый до ширины A4, делает подписи деталей
нечитаемыми. Рисуются контур листа, рабочая область после обрезной
кромки (пунктирная рамка тем же тоном, что и на технической схеме) и
детали с подписью «имя, размер, поворот».

Координаты берутся из `CuttingLayout` напрямую — nesting внутри
экспортёра не пересчитывается (§6).

## 6. Статус и предварительность

| Статус | Пометка на титуле |
| --- | --- |
| `VALID` | «Расчёт выполнен без замечаний» |
| `VALID_WITH_WARNINGS` | «Расчёт выполнен с предупреждениями» |
| `NEEDS_CONFIRMATION` | «ПРЕДВАРИТЕЛЬНЫЙ ДОКУМЕНТ. Часть производственных правил не подтверждена» |
| `INVALID` | «ПРЕДВАРИТЕЛЬНЫЙ ДОКУМЕНТ. Расчёт содержит ошибки — изготавливать по нему нельзя» |

Экспорт при `INVALID` не запрещается: документ нужен ровно для того,
чтобы увидеть, что не так, — список ошибок в нём и находится.

## 7. Известные ограничения

- Детерминизм PDF — структурный, не побайтовый: `pdf-lib` генерирует
  случайные ключи ресурсов и идентификатор файла при каждом сохранении.
- Ориентация страниц фиксирована (A4 книжная, A3 книжная); выбора
  пользователем нет.
- Нумерации страниц и колонтитулов нет.
- Разрыв строки внутри ячейки таблицы не поддерживается — длинное
  значение обрезается многоточием.
