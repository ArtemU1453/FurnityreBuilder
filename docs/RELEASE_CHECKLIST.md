# Чек-лист выпуска

PROMPT 31 §24. Список того, что должно быть верно ПЕРЕД выкладыванием
очередной версии. Пункт считается пройденным только если его проверил
кто-то или что-то, а не «вроде бы так и есть».

Порядок не случайный: сначала машина проверяет то, что умеет, и лишь
потом человек тратит время на то, чего машина не умеет. Если падает
любой пункт из блока «Машина», к блоку «Человек» переходить незачем.

## Машина

Одна команда закрывает большую часть: `npm run verify`. Она выполняет
пункты 1–7 подряд и останавливается на первом упавшем.

| # | Пункт                              | Команда                        | Ожидание                       |
| - | ---------------------------------- | ------------------------------ | ------------------------------ |
| 1 | Реестр предположений сходится      | `npm run check:assumptions`    | маркеры и записи совпадают     |
| 2 | Линтер, включая границы слоёв      | `npm run lint`                 | ноль ошибок                    |
| 3 | Типы                               | `npm run typecheck`            | ноль ошибок                    |
| 4 | Модульные тесты                    | `npm run test`                 | все проходят                   |
| 5 | Сборка                             | `npm run build`                | успешна                        |
| 6 | Независимость от бренда            | `npm run check:brand`          | ноль упоминаний, ноль внешних обращений |
| 7 | Размер сборки                      | `npm run check:bundle`         | главный чанк ≤ 260 КБ gzip, `pdf`/`xlsx` отложены |
| 8 | E2E на собранном приложении        | `npx playwright test --project=chromium` | все проходят       |
| 9 | E2E dev-режима                     | `npx playwright test --project=chromium-dev` | все проходят   |

Два E2E-набора запускаются **по отдельности**: вместе они поднимают два
сервера и мешают друг другу (`ERR_CONNECTION_REFUSED`). Путь к браузеру
задаётся переменной `PLAYWRIGHT_CHROMIUM_PATH`.

`npx vitest run` **не проверяет типы**. Пропускать пункт 3 нельзя: без
него ошибки типов доезжают до сборки.

## Что НЕ является поводом откладывать выпуск

Чтобы чек-лист не превращался в бесконечный:

- **Пустой раздел присадки.** Правила не подтверждены источником;
  приложение честно говорит об этом и не выдумывает координат. Выпуск
  этим не блокируется — блокировался бы обратным: выдуманными
  отверстиями.
- **Неразмещённая деталь в раскрое.** Если деталь больше листа, верный
  ответ — сказать об этом, а не разрезать её самовольно.
- **Размер `pdf-lib`.** Он отложен и на первую отрисовку не влияет.
