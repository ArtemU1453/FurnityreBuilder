# Что продукт умеет на самом деле

PROMPT 34 §18. Один документ, к которому сводятся все остальные. Он
существует ровно затем, чтобы разные части проекта не утверждали разное:
интерфейс, домен, расчёт, хранение, производство и экспорт по каждой
возможности отвечают здесь одинаково или расхождение названо явно.

## Как читать

| Колонка | Что означает |
| --- | --- |
| UI | Возможность доступна пользователю на экране |
| Домен | Модель её выражает |
| Расчёт | Геометрия и производственный конвейер её обрабатывают |
| Хранение | Переживает сохранение, перезагрузку и обновление приложения |
| Производство | Попадает в деталировку, фурнитуру, раскрой |
| Экспорт | Попадает в PDF и XLSX |
| Тесты | Закреплено проверкой |

Итоговые статусы: `READY`, `PARTIAL`, `NOT_SUPPORTED`,
`NEEDS_CONFIRMATION`, `DIFFERENT_BY_DESIGN`.

Правило заполнения: **`READY` ставится только при «да» во всех
колонках.** Одно «нет» — уже `PARTIAL`, каким бы малым оно ни казалось.

## Уточнение PROMPT 51

Строка «Вырез в цоколе» показывала «Домен ❌». Это неверно: тип
`PlinthCutout` есть в `domain/furniture/types.ts`, поле — в
`persistence/schema.ts`, а `geometry/plinth.ts` несёт явный флаг
`cutoutNotImplemented`. Модель возможность **выражает**; не строит её
расчёт. Итоговый статус не изменился — `NEEDS_CONFIRMATION`.

Остальные 59 строк перепроверены выборочно на коммите `e10be44` и
подтверждены.
