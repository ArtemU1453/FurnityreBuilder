# Экспорт XLSX

Реализация: `src/export/xlsx.ts` и `src/export/zip.ts`. Общая
архитектура — `docs/EXPORT_ARCHITECTURE.md`.

---

## 1. Листы книги

| Лист | Строки | Источник |
| --- | --- | --- |
| `Сводка` | проект, габариты, статус, итоги, неподтверждённые правила, предупреждения, ошибки | `metadata`, `dimensions`, `totals`, `confirmations` |
| `Детали` | № · ID · Деталь · Тип · Кол-во · Длина · Ширина · Толщина · Материал · Кромка · Текстура | `parts` |
| `Фурнитура` | № · ID · Название · Категория · Кол-во · Ед. · Назначение · Источник | `hardware` |
| `Присадка` | № · Деталь · ID · Операция · Назначение · Грань · X · Y · Мир X/Y/Z · Ø · Глубина · Направление · Тип | `drilling` |
| `Раскрой` | № · Лист · ID листа · Размер листа · Деталь · X · Y · Ширина · Высота · Поворот · Пропил · Использование · Отход | `placements` + `unplaced` |
| `Материалы` | № · ID · Материал · Категория · Толщина · Позиций · Деталей · Площадь · Листов | `materials` |
| `Кромка` | № · Материал кромки · Толщина · Длина · Сторон | `edgeBanding` |

Неразмещённые детали идут тем же листом «Раскрой», а не отдельным
файлом: деталь, которую не на чем распилить, обязана попасться на глаза
там же, где смотрят раскрой.

## 2. Почему без библиотеки

XLSX — это ZIP из нескольких XML-файлов. Всё, что нужно для записи:
контейнер без сжатия (метод STORE) и CRC32 — полторы сотни строк.
Взамен получено то, чего готовая библиотека не даёт даром:

- **побайтовый детерминизм** — ни отметки времени, ни версии упаковщика,
  ни порядка записей, зависящего от хеш-таблицы;
- **отсутствие транзитивных зависимостей** у приложения, которое обязано
  работать офлайн;
- **контроль над типами ячеек** — число остаётся числом.

Даты записей архива зафиксированы на начале эпохи DOS (1 января 1980).
Отсутствие сжатия увеличивает файл примерно на размер заголовков —
десятки килобайт для деталировки.

`exceljs` установлен **только как devDependency** и используется
исключительно тестами для ЧТЕНИЯ готовой книги: проверять собственный
писатель собственным читателем — самообман.

## 3. Качество книги

**Спецификация (§15).** Корректные имена листов и колонок, числа
числами, ширина колонок, закреплённая шапка, фильтры, отсутствие
дубликатов, верные количества.

**Доменное правило.**

- Размер, количество, координата и процент пишутся как `<v>` — числовая
  ячейка. Иначе по деталировке нельзя ни отсортировать, ни
  просуммировать.
- Текст пишется как `inlineStr`: общая таблица строк (sharedStrings) для
  документа такого размера — лишний файл и лишний источник рассинхрона.
- Каждому листу задана ширина колонок, закреплена первая строка
  (`pane state="frozen"`) и включён автофильтр на всю таблицу.
- Заголовок набран жирным (единственный стиль в книге).
- Нечисловые «числа» (NaN, Infinity) в ячейку не попадают: такой файл
  открывается повреждённым.
- Управляющие символы вычищаются из строк — XML их не допускает.

**Тест.** Книга открывается `exceljs`; проверяются состав и порядок
листов, заголовки, число строк против `ProductionBOM`, типы ячеек,
закреплённая шапка, автофильтр и совпадение значений со строками
`ProductionExportData`.

## 4. Единицы

Длины — миллиметры, число с точностью до десятой. Площадь — квадратные
метры, длина кромки — погонные метры (производственные единицы, в
которых материал заказывают). Процент использования листа — число,
а не строка с «%»: знак единицы стоит в заголовке колонки.

Правила округления общие с PDF (`src/export/format.ts`): одно и то же
значение в обоих документах выглядит одинаково.

## 5. Известные ограничения

- Нет формул, условного форматирования и объединённых ячеек.
- Нет вкладки с картой раскроя как изображением — только координаты.
- Один документ на проект: разделения по изделиям нет, пока проект
  содержит одно изделие.
