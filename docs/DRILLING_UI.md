# Drilling UI

Раздел присадки: операции сверления, конфликты и правила, по которым
операции получены.

Правила и параметры — `DRILLING_RULES.md`. Чертёж с отверстиями —
`PRODUCTION_DRAWINGS.md`. Экран целиком — `PRODUCTION_UI.md`.

---

## 1. ЧТО ПОКАЗЫВАЕТСЯ

Таблица операций из `DrillingPlan.operations`:

| Колонка    | Поле                                         |
| ---------- | -------------------------------------------- |
| Операция   | `id`                                         |
| Деталь     | имя позиции деталировки                      |
| Грань      | `face`                                       |
| X, Y       | `x`, `y` — координаты в системе грани        |
| Ø          | `diameter`                                   |
| Глубина    | `depth`                                      |
| Тип        | `through` — насквозь или глухое              |
| Назначение | `purpose`                                    |
| Правило    | `ruleId`, причина — во всплывающей подсказке |

Выбранная деталь сужает список до её операций; кнопка «Все детали»
возвращает полный. Это тот же выбор, что во всех остальных разделах, а не
отдельный фильтр присадки (`PRODUCTION_TRACEABILITY.md`).

---

## 2. НОЛЬ ОПЕРАЦИЙ — ЭТО НЕ ПУСТАЯ ТАБЛИЦА

В текущей сборке **все** правила присадки имеют статус
`needs-confirmation`: ни одно не подтверждено референсом, поэтому
координат отверстий не существует, и `DrillingPlan.operations` пуст.

Раздел говорит об этом словами:

> **Операций не рассчитано.** Ни одно правило присадки не подтверждено
> референсом, поэтому координат отверстий не существует. Что именно
> неизвестно — в списке выше и в разделе «Сводка».

Пустая таблица без объяснения выглядела бы как поломка интерфейса, а не
как честное «мы не знаем нормы». Подставить «обычные» 35 мм чашки петли
значило бы выдать догадку за производственное правило.

---

## 3. КОНФЛИКТЫ НЕ ПРЯЧУТСЯ

`DrillingPlan.errors` и `.warnings` показываются над таблицей всегда,
разными тонами, и не сворачиваются. Туда попадают:

- пересечение отверстий;
- отверстие за пределами детали;
- недопустимая глубина для глухого отверстия;
- неизвестная грань;
- правило фурнитуры, которое не может дать координату без подтверждения.

Прятать за нажатием то, что делает деталь неизготовимой, нельзя (§17).

## 4. ТРАССИРУЕМОСТЬ ОПЕРАЦИИ

```
HardwareItem  →  DrillingRule  →  DrillingOperation  →  ProductionPart
                 (ruleId)          (reason)             (productionPartId)
```

Все четыре звена уже есть в `DrillingOperation`: `sourceHardwareId`,
`sourceNodeId`, `ruleId`, `reason`. Интерфейс их читает и показывает —
`ruleId` колонкой, `reason` подсказкой; ни одного нового поля ради
показа не заведено (§18).

Отверстие, выбранное на чертеже, подсвечивается и получает выносные
размеры до краёв детали — те самые `x` и `y`, что в таблице.
