# E2E Scenarios

Сквозные сценарии в настоящем браузере: что проверяет каждый файл и
почему именно это.

Матрица покрытия — `QA_MATRIX.md`. Стратегия — `TESTING_STRATEGY.md`.

---

## 1. КАК ЗАПУСКАТЬ

Два проекта Playwright, и запускать их нужно **раздельно**: совместный
запуск поднимает оба сервера и приводит к отказу соединения.

```bash
npx playwright test --project=chromium        # production-сборка, порт 4173
npx playwright test --project=chromium-dev    # dev-сервер, порт 4174
```

`chromium-dev` существует ради технической схемы: `DebugSchema`
исключается из production-сборки, и проверить её можно только на dev.

## 4. ОШИБОЧНЫЕ СОСТОЯНИЯ

`negative.spec.ts`. Каждый сценарий проверяет четыре свойства: ошибка
объяснена словами, данные не потеряны, приложение не повреждено, к
рабочему состоянию можно вернуться.

| Сценарий                     | Ожидаемое поведение                                                   |
| ---------------------------- | --------------------------------------------------------------------- |
| Нулевая ширина               | «Изготовление невозможно», другие разделы работают, отмена возвращает |
| Отрицательная высота         | ошибка названа, поле принимает исправление                            |
| Нулевая толщина плиты        | объяснено, деталей нулевого размера нет                               |
| Невозможные ширины секций    | «не заполняют доступное пространство», отмена возвращает набор        |
| Дверь на ячейку с ящиками    | кнопка выключена — физический конфликт                                |
| Испорченный файл             | сообщение об ошибке, текущий проект не тронут                         |
| Чужая структура файла        | отвергнут, приложение работоспособно                                  |
| Файл из будущей схемы        | отвергнут с причиной                                                  |
| Неподтверждённые правила     | видны, не выдаются за готовность                                      |
| Деталь не помещается на лист | «Не размещено» с причиной `TOO_LARGE`                                 |

## 5. РЕСУРСЫ И НАГРУЗКА

`resources.spec.ts`:

- 10 полных обходов разделов — холсты, слушатели `window` и объектные URL
  не растут;
- 6 переключений вида холста — контекст WebGL не теряется, загрузок
  геометрии в GPU остаётся одна;
- два экспорта — ровно по одному объектному URL на документ;
- проект из 40+ деталей — ввод габарита доходит до сцены, производство
  считается, карта раскроя строится;
- выбор детали в производстве не запускает пересчёт.

## 6. ПРАВИЛА ДЛЯ НОВЫХ СЦЕНАРИЕВ

1. **Проверять состояние, а не отсутствие падения.** «Не упало» — не
   утверждение.
2. **Сужать локаторы до панели.** Одни и те же подписи встречаются на
   экране несколько раз: «Ширина» есть и у изделия, и у помещения.
3. **Не дублировать то, что проверяется без DOM.** Раскладка, разбор
   строк и трассируемость — модульные тесты; в браузере проверяется то,
   чего без него не проверить.
4. **Подписи брать из приложения.** Варианты наполнения строчные
   («полки», «ящики»), потому что приходят из доменного словаря.
