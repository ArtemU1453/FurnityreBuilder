# Проект и помещение

PROMPT 25. Как проект из библиотеки попадает в помещение, чем на него
ссылается экземпляр и что происходит, когда проект удалён.

Смежные документы: `FURNITURE_INSTANCE.md` (что такое экземпляр),
`ROOM_MODEL.md` (модель помещения), `ROOM_PLANNER.md` (планировщик),
`PROJECT_LIBRARY.md` (библиотека).

## 1. Ссылка — это пара

```ts
interface FurnitureInstance {
  readonly id: InstanceId;      // сам экземпляр
  readonly projectId: ProjectId; // какой проект
  readonly furnitureId: FurnitureId; // какое изделие внутри него
  …
}
```

`projectId` + `furnitureId` — ОДНА полностью квалифицированная ссылка
«какой проект и какое изделие в нём», а не два независимых поля.

PROMPT 24 хранил только `furnitureId`, и это было верно для своего
мира: проект был один, помещение жило внутри него, и второй координаты
у ссылки быть не могло. PROMPT 25 создаёт мир, в котором проектов много,
и ровно поэтому ссылка получает вторую составляющую. Это не второй вид
ссылок, а тот же самый, дополненный до полного.

Ключ, по которому ищутся габарит и геометрия экземпляра, — та же пара:

```ts
instanceKey(instance) === `${instance.projectId}/${instance.furnitureId}`
```

Отсюда следует, что два разных проекта могут содержать изделия с
совпадающими внутренними идентификаторами и не путаться — например,
проект и его копия, у которой внутренние id намеренно сохранены.

## 2. Мебель не копируется в помещение

Экземпляр хранит ссылку и положение. Ни размеров, ни материалов, ни
деталей в нём нет — это свойство модели с PROMPT 24, и библиотека его не
меняет. Следствие остаётся прежним: правка изделия немедленно меняет все
его экземпляры, и синхронизировать нечего, потому что копии нет.

## 3. Как проект попадает в помещение

1. Пользователь выбирает проект в списке планировщика (список — из
   библиотеки, а не из открытого документа: в помещение ставят готовые
   изделия, и большинство сделаны не в этом же документе).
2. Проект загружается из хранилища, если ещё не загружен
   (`useLinkedProjects`).
3. Первое свободное место ищет `findPlacement` — угол, затем стена
   (`src/room/autoplace.ts`); в начало координат мебель не ставится,
   потому что оно лежит на осевой линии стен.
4. Выполняется существующая команда `AddFurnitureInstance`.

Один и тот же проект размещается сколько угодно раз: каждый экземпляр
получает собственный `InstanceId`, а ссылка у всех одна и та же.
Перемещение одного экземпляра не двигает остальные.

## 4. Проверка ссылки: кто что может подтвердить

Команда `AddFurnitureInstance` проверяет наличие изделия ТОЛЬКО когда
`instance.projectId` совпадает с идентификатором открытого документа.
Чужой проект живёт в библиотеке, которой документ не видит; тихо
отказать значило бы сделать размещение из библиотеки невозможным.

Ссылочную целостность чужих экземпляров проверяет `validateRoom`, и
результат — видимая ошибка, а не молчаливый отказ:

| Код | Когда |
|---|---|
| `ROOM_INSTANCE_FURNITURE_NOT_FOUND` | проект известен, изделия в нём нет |
| `ROOM_INSTANCE_PROJECT_NOT_FOUND` | самого проекта нет: удалён или не загружен |

Различие важно: для пользователя это разные события и разные действия.
Одно чинится внутри проекта, другое — возвращением проекта в библиотеку.

## 5. Удалённый проект (вариант C)

Удаление проекта разрешено; его размещения остаются и помечаются
недоступными. Обоснование выбора — `PROJECT_LIBRARY.md` §3.

Практически это выглядит так:

- перед удалением карточка сообщает, сколько раз проект размещён в
  открытом помещении;
- после удаления `useLinkedProjects` помечает идентификатор в `missing`
  и больше не пытается его загрузить (иначе неудача превратилась бы в
  бесконечный цикл);
- планировщик показывает количество недоступных проектов, а
  `validateRoom` даёт ошибку с объяснением;
- расстановка при этом НЕ теряется: вернув проект (импортом того же
  файла — идентификатор сохраняется), пользователь получает её обратно.

## 6. Геометрия связанных проектов

`furnitureGeometries` в `App` строится одинаково для открытого проекта
и для всех связанных: цикл по `[project, ...linked.projects.values()]`.
Второго пути «построить геометрию чужого проекта» не появляется.

Проект загружается один раз на идентификатор и держится в памяти, пока
он нужен помещению. Иначе каждое движение мышью по планировщику читало
бы базу.

Планировщик по-прежнему НЕ считает мебель во время жеста: ему нужен
только габарит (`GeometryResult.boundingBox`), а от того, что шкаф
подвинули, его детали не меняются.
