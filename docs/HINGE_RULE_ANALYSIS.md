# PM-06 — петли дверей: разбор

PROMPT 66 §3. Что уже доступно расчёту и почему правило нельзя свести к
одной высоте.

Базовый коммит `20c40d0`. Кода не менялось.

---

## FACT — что происходит сегодня

`hingeRule` (`src/hardware/rules/hinges.ts`), статус
`needs-confirmation`, `unknownId: T-DOOR-05`.

Правило **находит створки и знает их размеры**, но количество не
выдаёт. На контрольном изделии:

```
Петли не рассчитаны: пороги количества петель по высоте створки
референсом не подтверждены (T-DOOR-05).
Створок, которым нужны петли: 1, высоты: 2164 мм.
```

Спецификация фурнитуры изделия с дверью: **ни одной петли**.

## FACT — какие данные уже доступны (§3, последний абзац)

Замер створки на контрольном изделии:

| Параметр | Доступен? | Значение в замере |
| --- | --- | --- |
| высота створки | **да** | 2164 мм |
| ширина створки | **да** | 574.6 мм |
| толщина створки | **да** | 16 мм |
| материал створки | **да** | ссылка на `Material` |
| вид материала | **да** | `chipboard` |
| сторона петель | **да** | `hingeSide` |
| накладной / вкладной | **да** | `OverlaySpec.mode` |
| число створок на проём | **да** | |
| **масса створки** | **НЕТ** | см. ниже |
| **тип петли** | **НЕТ** | модель не хранит |

### Находка: массу створки модель посчитать не может

```ts
export interface Material {
  readonly id: MaterialId;
  readonly name: string;
  readonly kind: MaterialKind;
  readonly thickness: Mm;
  readonly displayColor: string;
  readonly grain: Grain;
  readonly sheet?: SheetFormat;
}
```

**Плотности у материала нет.** Объём створки вычисляется, масса — нет.

Это важно именно здесь: §3 требует «не сводить правило к высоте, если
официальный источник требует несколько параметров». Каталоги петель
обычно задают количество по **совокупности** высоты, ширины и массы
створки. Если подтверждённое правило потребует массу, потребуется
доработка домена: поле плотности у `Material`, и вместе с ним —
подтверждение плотности каждого вида материала, то есть **ещё один
источник**.

Поэтому нельзя обещать, что `PM-06` закрывается одной таблицей из
каталога. Возможен сценарий, где таблица найдена, а применить её всё
равно нельзя.

## FACT — тип петли в модели отсутствует

Реестр фурнитуры содержит одну обезличенную позицию «Петля» без
характеристик:

```ts
{ id: HW_HINGE, kind: 'hinge', name: 'Петля', unit: 'pcs', spec: {} }
```

Нет ни угла открывания, ни типа наложения, ни семейства. Правило
количества у разных семейств разное, поэтому применить одну таблицу ко
всем петлям нельзя — §3 требует это зафиксировать явно, и здесь оно
зафиксировано.

## CONFIRMED RULE

**Нет.** Источник не получен: все домены производителей петель закрыты
(`ASSEMBLY_HARDWARE_RULE_SOURCE_AUDIT.md`).

## UNCONFIRMED

| Вопрос §3 | Ответ |
| --- | --- |
| зависимость количества от высоты | **не подтверждена** |
| диапазоны высот | не подтверждены |
| нужна ли масса | **неизвестно, и это блокер сам по себе**: модель массу не считает |
| нужна ли ширина | неизвестно |
| зависит ли от материала | неизвестно |
| зависит ли от типа петли | **почти наверняка да**, и модель типа не хранит |
| зависит ли от конструкции двери | неизвестно |

## DESIGN DECISION

| Решение | Обоснование |
| --- | --- |
| Правило не сводить к высоте | §3 запрещает, а данные подсказывают, что параметров больше одного |
| Плотность материала не добавлять | поле без подтверждённых значений — приглашение выдумать их. Добавляется вместе с правилом, которое его потребует |
| Тип петли не вводить | вводить перечисление семейств, не зная ни одного подтверждённого правила по ним, — догадка о структуре |
| Обезличенную позицию «Петля» оставить | она честна: это категория, а не модель |

## IMPLEMENTATION GAP

Что должно появиться, чтобы реализация стала возможной:

1. **Таблица производителя** «высота × ширина × масса → число петель» —
   главный блокер.
2. Если таблица требует массу: плотность каждого вида материала —
   **второй, независимый источник**.
3. Если таблица привязана к семейству: поле типа петли в модели и
   решение, что считать значением по умолчанию.

Пункты 2 и 3 выясняются **только после** пункта 1: до него неизвестно,
понадобятся ли они вообще.

### Что НЕ является блокером

Обнаружение створок, их размеры, сторона петель, накладной/вкладной
режим — всё уже работает. Реализация упирается исключительно в правило.
