## Как проверялось

Аудит шёл на **production-сборке**, а не на макетах и не на чтении
кода: 26 объективных проверок интерфейса (подписи, единицы, имена
кнопок, фокус, клавиатура, перебор по ширине на четырёх экранах) плюс
отдельные проходы по пустым состояниям, разрушающим действиям,
состоянию загрузки и поведению диалогов.

Субъективных критериев в аудите нет. «Некрасиво» не проверяется, а
значит и не чинится — его можно только обсуждать. Проверялось то, что
даёт ответ числом или текстом на экране.

## Primary Actions

**PASS.** На всех четырёх экранах у каждой кнопки есть имя (безымянных
— ноль). Доступные действия есть везде: конструктор 13, производство
23, помещение 2, библиотека 4. Отключённые кнопки объяснены либо
подписью, либо структурой рядом.

## Field Labels

**PASS.** У каждого поля на каждом экране есть доступное имя — метка,
обёртка или `aria-label`. Полей, у которых подписью служил бы только
`placeholder`, не найдено ни одного.

## Units

**PASS.** Все четыре размерных поля несут «мм». Единица стоит в самом
поле, а не в подписи, и не теряется при правке; расчёт и документы
используют те же миллиметры.

## Validation Feedback

**PASS.** Проверено настоящим недопустимым вводом: нулевая ширина и
отрицательная высота объясняются словами, называют поле по-русски
(«Ширина», а не `width`), не портят модель и не показывают исключений.
После исправления расчёт возвращается.

## Navigation

**PASS.** Все четыре раздела открываются, помечаются активными, тупиков
нет. Проект переживает обход всех разделов — подпись сцены до и после
совпадает посимвольно.

## Empty States

**PASS.** Помещение без комнаты: «Помещение ещё не создано» и что
именно создастся. Библиотека предлагает создать проект. Оба отвечают на
«что это», «почему пусто» и «что дальше».

## Loading States

**PASS.** Экспорт называет, что происходит, и не даёт запустить второй:
наблюдение изнутри страницы показало `Скачать PDF` → `Формируется PDF…
disabled=true` → `Скачать PDF`.

Первые два измерения этого места дали ложный отрицательный результат —
опрос из Playwright встал в очередь за самим нажатием. Ошибка была в
измерении, и она исправлена, а не записана в дефекты.

## Error States

**PASS.** Архитектура PROMPT 45 на месте: сообщение человеческим языком,
стек не подменяет текст, есть безопасное действие, данные для отчёта
показываются целиком перед копированием.

## Save State

**PASS — после исправления.**

Здесь аудит нашёл главное. Подсказка `STORAGE_STATUS[*].hint` не
показывалась **нигде и ни для одного состояния**. Три подсказки были
написаны и лежали мёртвым кодом.

Больнее всего это било по отказу записи. Отказ воспроизведён настоящим
`QuotaExceededError`: человек видел «Не удалось сохранить» — и не видел
единственного совета, который спасал работу, «выгрузите проект файлом».
После перезагрузки правки не возвращались.

Исправлено: подсказка показывается рядом с состоянием, когда нет более
конкретной подробности. Проверено во всех трёх состояниях:

| Состояние | Что видит человек |
| --- | --- |
| Новый проект | «Проект не сохранён» + «живёт в этой вкладке, пока вы не нажмёте „Сохранить“» |
| Есть правки | «Есть несохранённые изменения» + «автосохранения нет намеренно: запись поверх сохранённого потеряла бы работу» |
| Сохранено | «Сохранено» — и никакой подсказки: объяснять нечего |
| Отказ записи | «Не удалось сохранить» + «выгрузите проект файлом, чтобы не потерять работу» |

Показ соответствует фактической архитектуре: автосохранения в продукте
нет, и интерфейс об этом прямо говорит, а не изображает его.

## Destructive Actions

**PASS.** Удаление проекта спрашивает подтверждение и называет
последствие: «Проект будет удалён без возможности вернуть. Сохраните
его файлом, если он ещё нужен». Диалог закрывается по Escape.
Подтверждение стоит только там, где потеря необратима, — на обычные
действия его нет.

## Mobile UX

**PASS.** 375, 390 и 430 px: лист параметров открывается и закрывается,
правка доходит до модели, разделы переключаются, сохранение работает,
исключений нет ни на одной ширине.

## Responsive Layout

**PASS.** 360, 430, 834 и 1440 px — перебор по горизонтали **0 px** на
каждом из четырёх разделов. Закреплено сценарием
`tests/e2e/responsive-widths.spec.ts` (8 проверок).

Снимков экрана в наборе нет намеренно: расхождение в один пиксель
красит прогон чаще, чем находит дефект.

## Accessibility Baseline

**PASS — именно baseline, не соответствие WCAG.**

Формального аудита доступности не проводилось, и заявлять соответствие
стандарту было бы неправдой. Проверено следующее:

| Проверка | Результат |
| --- | --- |
| Ссылка пропуска навигации | есть |
| Видимый фокус | первый Tab даёт `outline: 2px` |
| Достижимость главного действия с клавиатуры | «Сохранить» — за 18 нажатий Tab |
| Имена кнопок | безымянных нет ни на одном экране |
| Связь полей с подписями | у всех полей есть доступное имя |
| Фокус в диалоге | входит внутрь и не теряется после закрытия |
| Закрытие диалога | Escape работает |
| Состояние не только цветом | текущий шаг помечен `aria-current`, серьёзность — словом |

**Accessibility baseline verified.**

## Confirmed UX Issues

| ID | Severity |
| --- | --- |
| UX-01 — подсказка состояния записи не показывалась нигде | HIGH IMPACT |
| UX-02 — `StatusBar` принимал свойство, которое не показывал, а документация обещала обратное | MINOR CLARITY |

Две находки автоматической проверки разобраны и признаны **не
проблемами**: отключённая «Назад» на первом шаге (структура рядом уже
всё объясняет) и мнимое отсутствие состояния загрузки у экспорта
(ошибка измерения). Обе записаны в реестр с разбором, а не вычеркнуты.

## Resolved UX Issues

Обе. UX-01 закрыт двумя сценариями `tests/e2e/save-state.spec.ts` —
без исправления оба падают именно на отсутствующих подсказках,
проверено снятием правки. UX-02 закрыт удалением мёртвого свойства и
приведением документации к тому, что компонент делает.

## Remaining High-Impact UX Issues

**NONE.**

## Что сознательно НЕ делалось

* **Никакого редизайна.** Информационная архитектура, компоненты,
  расположение — не тронуты.
* **Ни одного нового элемента интерфейса.** Обе правки *убирают*
  лишнее и договаривают уже написанное: UX-01 показывает текст, который
  давно был написан и не отображался; UX-02 удаляет свойство, которое
  ничего не делало.
* **Ни одной подсказки там, где структура ясна.** Отключённая «Назад»
  на первом шаге осталась без тюльтипа намеренно.
* **Apple Design Skill в этой сессии не подключён** — `ListSkills` по
  запросам design, apple, ui, ux возвращает пустой список. Названные
  принципы (иерархия, ясность, отклик, сдержанность,
  последовательность) применялись как обычные принципы проектирования.
  Интерфейс Apple не копировался, их символика не добавлялась.
