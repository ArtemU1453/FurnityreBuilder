# Модель взаимодействия

Основано на обязательном design standard проекта — `apple-design` skill
(фиксированная версия `d23d7f88`). Ниже — не пересказ, а рабочие правила
для мебельного конструктора.

---

## 1. ЧЕТЫРЕ ЗАКОНА

1. **Отклик на pointer-down.** Визуальная реакция появляется в момент нажатия,
   а не по `click`. Ни один интерактивный элемент не ждёт отпускания.
2. **Непрерывная обратная связь.** Во время drag / изменения значения UI
   обновляется на каждом кадре, а не только по завершении.
3. **Прерываемость.** Любую анимацию можно перехватить и развернуть.
   Ввод не блокируется никогда.
4. **Точность важнее эффекта.** Там, где решается производственный размер,
   резиновость и инерция отключаются. Это мебель, а не лента.

Закон 4 — единственное, чем этот проект отходит от skill, и он это допускает:
rubber-band не применяется там, где нарушит точность.

---

## 2. ОБЩИЙ КОНТРАКТ ЖЕСТА

Один класс контроллера на все drag-взаимодействия.

```ts
interface DragController<T> {
  onPointerDown(e: PointerEvent): void;   // capture, снимок базы, открыть транзакцию
  onPointerMove(e: PointerEvent): void;   // rAF-обновление чернового слоя
  onPointerUp(e: PointerEvent): void;     // commit одной командой
  onPointerCancel(e: PointerEvent): void; // откат к базе
  onKeyDown(e: KeyboardEvent): void;      // Esc = cancel
}
```

Обязательная последовательность на `pointerdown`:

```ts
el.setPointerCapture(e.pointerId);          // трекинг не теряется за границей элемента
base = snapshotDomainValue();               // база — из ДОМЕНА, не из DOM
grabOffset = pointerPos - elementOrigin;    // точка захвата сохраняется
history.open(transactionId);
```

**Точка захвата.** Элемент никогда не прыгает центром под указатель.
Полка, за которую взялись у края, остаётся взятой за край.

**Порог начала.** Движение считается drag после 4 px (мышь) / 8 px (touch).
До порога — это клик. Порог меньше рекомендованных skill 10 px, потому что
в конструкторе высокая точность позиционирования, и 10 px при большом зуме
это уже десятки миллиметров.

**История скорости.** Кольцевой буфер из 5 последних `(position, timestamp)`.
Скорость на отпускании = медиана по буферу, а не последняя дельта —
последняя дельта шумит и даёт случайные броски.

**Отмена.** `Esc` во время drag, `pointercancel`, потеря окна — возврат
к `base` с пружинной анимацией, транзакция закрывается без записи в историю.

## 3. ЕДИНИЦЫ И ПРИВЯЗКА

Экранные пиксели → миллиметры через масштаб viewport:

```
deltaMm = deltaPx / viewport.scale
```

Правила округления при drag:

| Модификатор | Шаг привязки |
| --- | --- |
| без модификатора | 1 мм |
| `Shift` | 10 мм |
| `Alt` | 0.1 мм (точный режим) |
| привязка включена | к «магнитам»: центр, кратность 32 мм, равные доли, край соседа |

**Магниты.** Притяжение в радиусе 6 px экрана (не миллиметров — иначе на разных
зумах ведёт себя по-разному). Срабатывание магнита даёт немедленную визуальную
подсветку линии привязки. Удержание `Ctrl` временно отключает все магниты.

Магнит **не является** rubber-band: значение мгновенно встаёт на привязку,
без пружины и отскока. В производственной геометрии пружинящее значение —
это ложь о размере.

## 4. КАРТА ВЗАИМОДЕЙСТВИЙ

Для каждого элемента: pointerdown → pointermove → pointerup → keyboard →
hover → focus → cancel → commit → undo.

### 4.1 Ячейка (секция)

| Событие | Поведение |
| --- | --- |
| `hover` | контур 1.5 px акцентного цвета, курсор `pointer`; **без анимации входа** — hover должен быть мгновенным |
| `pointerdown` | немедленная заливка выделения (не ждём up), фокус переходит на ячейку |
| `pointerup` | ячейка выбрана, панель свойств открывается с анимацией от границы ячейки (spatial consistency, §8) |
| `Shift+click` | добавить в выделение диапазон |
| `Ctrl/Cmd+click` | добавить/убрать одну |
| `keyboard` | `Tab` — по ячейкам, стрелки — по соседям в дереве, `Enter` — открыть свойства, `Delete` — очистить наполнение |
| `focus` | тот же контур, что и hover, плюс внешнее focus-кольцо 2 px с отступом 2 px |
| `commit` | команда `SelectNodes` — **в историю не пишется** (выделение это сессия) |
| `undo` | не применимо |

### 4.2 Разделитель (перегородка / полка-разделитель) — перетаскивание

Главное взаимодействие конструктора.

| Событие | Поведение |
| --- | --- |
| `hover` | утолщение линии до 3 px, курсор `col-resize` / `row-resize`, hit-зона расширена до 12 px |
| `pointerdown` | `setPointerCapture`; снимок обеих смежных ячеек; открытие транзакции; линия становится акцентной; появляются **обе** размерные метки соседних ячеек |
| `pointermove` | разделитель следует за указателем **1:1** с сохранением точки захвата. Обновляется: позиция линии (`transform`), два числа в метках, поля в панели свойств. Домен не трогается |
| граница | **жёсткий стоп** на `minCellSize`. Не rubber-band. При упоре — метка соседней ячейки краснеет и показывает минимум. Это честнее, чем упругость: размер физически невозможен |
| `pointerup` | одна команда `MoveDivider`; полный пересчёт геометрии; пружинное «доведение» к привязанному значению, если оно рядом |
| `keyboard` | при фокусе на разделителе: стрелки ±1 мм, `Shift`+стрелки ±10 мм, `Home`/`End` — к минимуму/максимуму, `Enter` — ввод числа |
| `cancel` | `Esc` — возврат к базе |
| `commit` | один шаг истории на весь drag |
| `undo` | восстанавливает позицию **и** выделение разделителя |

**Почему без rubber-band.** Skill рекомендует упругие границы. Здесь это
запрещено законом 4: если пользователь тянет полку за физический предел, показ
«она немного зашла дальше» — дезинформация о конструкции. Вместо упругости —
мгновенный стоп плюс явное объяснение причины.

### 4.3 Размерная линия габарита — перетаскивание

| Событие | Поведение |
| --- | --- |
| `pointerdown` | захват маркера габарита, транзакция открыта |
| `pointermove` | габарит меняется 1:1. Изделие перестраивается в **preview-режиме**: пересчёт геометрии не чаще кадра, вне истории (`ARCHITECTURE.md` §7). Значение в поле панели меняется синхронно |
| бюджет кадра | при > 8 мс на пересчёт preview переходит на контурный режим: габаритная рамка + затронутые детали. Отклик не пропадает никогда |
| `pointerup` | команда `SetDimension`, полный пересчёт, валидация |
| `keyboard` | стрелки ±1 / ±10 мм |
| ограничения | мягкие: за рекомендованным пределом изделие продолжает строиться, метка становится предупреждающей. Пользователь не теряет управление (Agency) |

### 4.4 Числовое поле размера

| Событие | Поведение |
| --- | --- |
| `focus` | текст выделяется целиком — типовое ожидание при правке размера |
| ввод | схема обновляется **на каждом валидном промежуточном значении**, без debounce. `123` при вводе → сразу видно 123 мм |
| невалидный промежуточный ввод | (`""`, `12-`) — схема удерживает последнее валидное значение, поле не подсвечивается ошибкой во время набора |
| `blur` / `Enter` | нормализация, clamp, коммит |
| `Esc` | возврат к значению на момент фокуса |
| колесо мыши над полем | ±1 мм (±10 с `Shift`) — только при наличии фокуса, иначе перехватывает прокрутку страницы |
| стрелки | ±1 / ±10 мм |
| `commit` | один шаг истории на всю серию правок в рамках одного фокуса (коалесценция) |

**Debounce запрещён** на пути «поле → схема». Единственный дебаунс в системе —
автосохранение (800 мс), и он не влияет на отображение.

### 4.5 Перетаскивание наполнения (полка/ящик/штанга из палитры в ячейку)

| Событие | Поведение |
| --- | --- |
| `pointerdown` на карточке палитры | карточка сжимается до 0.97, поднимается «призрак» под указателем с сохранением точки захвата |
| `pointermove` | призрак следует 1:1; ячейка-кандидат под указателем подсвечивается; показывается предварительный контур на месте будущего элемента |
| недопустимая цель | подсветка нейтральная (не красная), курсор `no-drop`. Красный — для ошибок, не для «сюда нельзя» |
| `pointerup` над целью | команда `SetFill`; призрак пружинно «садится» на итоговую позицию с передачей скорости (velocity handoff) |
| `pointerup` вне цели | призрак возвращается в палитру пружиной, скорость передаётся |
| `Esc` | немедленный возврат |
| `keyboard` | альтернатива без мыши: выбрать ячейку → `Enter` → выбрать наполнение из списка. Drag не должен быть единственным способом |

### 4.6 Планировщик — перемещение мебели в помещении

| Событие | Поведение |
| --- | --- |
| `pointerdown` | захват предмета, точка захвата сохраняется |
| `pointermove` | предмет следует 1:1; привязка к стенам и к граням соседней мебели в радиусе 8 px; показ размерных цепочек до стен |
| граница помещения | **допустима лёгкая резиновость** — здесь речь о компоновке, а не о производственном размере. Коэффициент по формуле skill, `constant = 0.55` |
| `pointerup` | момент проекции (`project()` из skill) для броска; посадка пружиной с передачей скорости, `bounce ≈ 0.2` |
| поворот | ручка поворота, шаг привязки 15°, `Shift` — без привязки |
| `keyboard` | стрелки ±10 мм, `Shift`+стрелки ±100 мм, `R` — поворот на 15° |

Планировщик — единственное место, где резиновость и инерция разрешены,
потому что там перемещают предмет в пространстве, а не назначают размер детали.

### 4.7 Viewport (зум и панорама схемы)

| Событие | Поведение |
| --- | --- |
| колесо | зум к позиции курсора (не к центру) |
| `Ctrl`+колесо | то же (жест pinch трекпада) |
| пробел + drag / средняя кнопка | панорама 1:1 |
| два пальца | панорама и зум одновременно |
| границы | резиновость по формуле skill; отпускание — пружинный возврат с передачей скорости |
| `keyboard` | `+`/`−` зум, `0` — вписать в экран, `1` — 100 % |
| прерываемость | инерция панорамы прерывается касанием мгновенно, без «доигрывания» |

### 4.8 Панель свойств (sheet / sidebar)

| Событие | Поведение |
| --- | --- |
| открытие | анимация исходит от выбранного объекта: `transform-origin` в точку объекта, вход = масштаб + смещение + рост blur |
| перетаскивание (мобильный sheet) | 1:1 за ручку; во время drag — только `transform` |
| отпускание | решение открыть/закрыть по **знаку скорости**, а не по позиции. Проекция момента определяет точку посадки |
| перехват | закрывающийся sheet можно схватить и вернуть; анимация стартует от текущего визуального положения |
| закрытие | по тому же пути, что и открытие (spatial consistency) |
| `keyboard` | `Esc` — закрыть, фокус возвращается на объект, который её открыл; ловушка фокуса только для модальных диалогов, не для параллельных панелей |

### 4.9 Кнопка / переключатель / вкладка

| Состояние | Поведение |
| --- | --- |
| `hover` | смена фона, без задержки |
| `pointerdown` | `scale(0.97)` за 100 мс — мгновенно, до отпускания |
| увод указателя во время нажатия | нажатие снимается; возврат указателя — восстанавливается (cancel-by-dragging-away) |
| `pointerup` в пределах | действие |
| `focus-visible` | кольцо 2 px, только для клавиатуры |
| `disabled` | нет hover, нет press, курсор `not-allowed`, `aria-disabled` |

## 5. КЛАВИАТУРА

Полный сценарий проектирования должен проходиться без мыши.

| Клавиши | Действие |
| --- | --- |
| `Tab` / `Shift+Tab` | по интерактивным элементам |
| Стрелки | навигация по дереву секций; при фокусе на маркере — изменение значения |
| `Enter` | открыть свойства выделенного / подтвердить ввод |
| `Esc` | отменить жест, закрыть панель, снять выделение |
| `Delete` / `Backspace` | очистить наполнение ячейки |
| `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z` | undo / redo |
| `Ctrl/Cmd+S` | экспорт проекта в файл (сохранение локальное и автоматическое) |
| `Ctrl/Cmd+D` | дублировать выделенную секцию |
| `1`…`4` | переключение видов (фасад / разрез / план / 3D) |
| `0` | вписать в экран |
| `?` | список горячих клавиш |

Порядок фокуса соответствует визуальному порядку. Ловушки фокуса — только в
модальных диалогах. Ни один жест не является единственным способом действия.

## 6. ПРЯМОЕ РЕДАКТИРОВАНИЕ НА СХЕМЕ

Требование §15 задания: `USER → МЕБЕЛЬ`, а не `USER → ФОРМЫ → МЕБЕЛЬ`.

- Двойной клик по размерной линии превращает её в поле ввода **на месте**,
  без открытия панели.
- Значение, введённое на схеме, и значение в панели — одно и то же состояние.
  Ни одно из них не «главнее».
- Перетаскивание границы меняет число в панели в тот же кадр.
- Выделение детали на схеме синхронно выделяет строку в деталировке, и наоборот.

Одна модель — несколько представлений. Расхождений между ними быть не может
по построению: оба читают `Part[]` из одного пересчёта.

## 7. ОБРАТНАЯ СВЯЗЬ

Четыре вида (по skill): статус, завершение, предупреждение, ошибка.

| Ситуация | Канал |
| --- | --- |
| Нажатие | мгновенная деформация 0.97 |
| Захват объекта | подъём тени, лёгкое увеличение |
| Срабатывание привязки | подсветка линии магнита; на устройствах с поддержкой — тик вибрации 10 мс |
| Достигнут предел | стоп + красная метка со значением предела |
| Проект сохранён | ненавязчивый индикатор состояния, без модальных окон |
| Ошибка валидации | подсветка конкретной детали в схеме + строка в списке проблем |
| Экспорт готов | тост с именем файла |

**Вибрация — только на реальных событиях** (привязка, предел, завершение экспорта)
и только если устройство поддерживает. Никогда не как декорация.

## 8. ПРОСТРАНСТВЕННАЯ СОГЛАСОВАННОСТЬ

- Панель свойств ячейки раскрывается **от этой ячейки**.
- Правая боковая панель уходит вправо, нижний sheet — вниз.
- Всплывающее меню масштабируется от кнопки, которая его вызвала,
  а не от центра экрана.
- Диалог подтверждения появляется в центре и затемняет фон — потому что
  прерывает работу; параллельная панель фон не затемняет.

## 9. СТАБИЛЬНОСТЬ ВЫДЕЛЕНИЯ

Проблема: после изменения габарита геометрия пересчитывается целиком, и
выделение «слетает», если оно ссылалось на индекс детали.

Решение: `PartId` детерминированно выводится из пути в дереве секций и роли:

```
part:{furnitureId}/{nodePath}/{role}/{index}
```

Пересчёт при неизменной структуре даёт те же идентификаторы → выделение,
фокус и открытая панель сохраняются. Это же свойство делает undo предсказуемым.

---

## 10. ПРЕРЫВАЕМОСТЬ — ЧЕКЛИСТ РЕАЛИЗАЦИИ

1. Ни один обработчик не ставит `pointer-events: none` на время анимации.
2. Анимации стартуют от **текущего визуального значения**, читаемого из
   пружинного движка, а не от логической цели.
3. CSS `@keyframes` и `transition` не используются для жестовых взаимодействий —
   только для не-жестовых микро-состояний (hover, press).
4. При развороте жеста скорость переносится в новую цель, а не обнуляется.
5. Движение по X и Y — две независимые пружины.
6. Тест: схватить закрывающуюся панель и вернуть её — не должно быть рывка.

## 11. БЮДЖЕТЫ

| Метрика | Бюджет |
| --- | --- |
| pointerdown → первый видимый отклик | < 16 мс (один кадр) |
| кадр во время drag | < 16 мс |
| полный пересчёт геометрии | < 5 мс (типовое изделие) |
| открытие панели свойств | ощущается мгновенно, response 0.3 |
| экспорт PDF типового проекта | < 2 с, с индикатором прогресса |

Превышение бюджета кадра — дефект, а не «особенность».
Проверяется в E2E-трассировке (`IMPLEMENTATION_PLAN.md`, этап 32).
