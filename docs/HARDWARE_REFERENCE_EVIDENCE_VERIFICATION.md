# Приложенный справочник фурнитуры как доказательство: проверка

Базовый коммит `99bbe28`. **Продуктовый код не менялся.**

Опись самого файла — в
[`HARDWARE_REFERENCE_XLSX_FORENSICS.md`](HARDWARE_REFERENCE_XLSX_FORENSICS.md).
Здесь решается один вопрос: **что из этого источника можно применить** к
PM-18, PM-17, PM-06 и FR-04.

**Итог: ничего. Все четыре возможности остаются BLOCKED.** Ни одна
гипотеза не исключена, ни одно правило не подтверждено, ни одна строка
`src/` не изменена.

## 1. Шкала уровней доказательства (§9)

Уровни определены здесь явно, потому что без определения они означали бы
что угодно.

| Уровень | Что это | Что с ним можно делать |
| --- | --- | --- |
| **L1** | утверждение без происхождения и без числа: назначение, преимущество, общее описание | ничего; можно только процитировать в `docs/` |
| **L2** | число из одного источника без независимого подтверждения — перечень типоразмеров или диапазон | нельзя реализовать: чтобы получить значение, придётся выбрать его внутри диапазона, а это новое допущение |
| **L3** | число, подтверждённое **вторым независимым источником** по реальному изделию | можно реализовать как значение по умолчанию с пометкой источника |
| **L4** | правило, воспроизводимое из геометрии **без единого нового числового допущения** | можно реализовать как правило расчёта |

**L4 присваивается только тогда, когда для реализации не требуется ни
одного нового числа.** Диапазон «250–600 мм» уровнем L4 быть не может
никогда: чтобы им воспользоваться, нужно решить, какое из 351 значения
брать, — и это решение источником не покрыто.

### 1.1. Уровень каждого утверждения источника

| Уровень | Сколько утверждений | Какие |
| --- | --- | --- |
| **L1** | 46 | все FACT, APPLICATION, MARKETING, INSTALLATION, UNSUPPORTED |
| **L2** | 13 | F-02, F-06, F-10, F-14, F-18, F-22, F-26, M-02, M-09, M-10, M-13, M-16, M-22 — типоразмеры, диапазоны и нагрузки |
| **L3** | **1** | F-02 частично: типоразмер **7×50** для конфирмата — он же стоит в заказе 52987 («Винт-конфирмат 7\*50») |
| **L4** | **0** | — |

Единственное утверждение, дошедшее до L3, — существование типоразмера
конфирмата 7×50. Это не правило: оно не говорит, **сколько** их ставить
и **куда**.

**Утверждений уровня L4 в файле нет ни одного.**

## 2. PM-18 — корпусный крепёж (§3)

### 2.1. Правило выбора крепежа

Источник (F-04a): «Основная стяжка каркасов из ДСП/МДФ под прямым углом»
— о конфирмате.

Сейчас `src/hardware/rules/fasteners.ts` жёстко ставит
`kind: 'confirmat'` на любой найденный стык и не читает
`ConstructionScheme.jointType`. Формально источник это поведение как
будто поддерживает.

**Но подтверждением правила выбора это не является**, и вот почему:

| Что проверялось | Результат |
| --- | --- |
| Говорит ли источник «всегда конфирмат»? | нет, сказано «основная», без условия и без исключений |
| Совпадает ли это с единственным заказом известного происхождения? | **нет** |

В заказе 52987 на одном изделии стоят одновременно:

| Крепёж | Штук |
| --- | --- |
| Рафикс со штоком | **48** |
| Минификс | **40** |
| Конфирмат 7×50 | **28** |
| Шкант 8×30 | 24 |
| Шкант 8×50 | 4 |

Конфирмат здесь — **третий по количеству**, а не «основной». То есть
слово «основная» в источнике описывает роль вообще, а не правило выбора
для конкретного стыка. Какой стык получает конфирмат, какой — рафикс, а
какой — минификс, источник не говорит ни словом.

**Правило выбора: NOT CONFIRMED.**

### 2.2. Правило количества на стык

| Что искалось в источнике | Найдено |
| --- | --- |
| количество крепежа на один стык | **нет** |
| зависимость количества от длины стыка | **нет** |
| зависимость от толщины плиты | **нет** |
| минимальное и максимальное число на стык | **нет** |
| отступ крайних точек от торца | **нет** |

`CARCASS_FASTENERS_PER_JOINT` остаётся `undefined`. Менять его не на что.

### 2.3. Решение

**PM-18: BLOCKED.** Источник не добавил ни правила выбора, ни правила
количества. Ни одна строка `src/hardware/` не изменена.

## 3. PM-17 — крепление задней стенки (§4)

### 3.1. Что источник говорит о задней стенке

Ровно одно утверждение на весь файл:

> F-20, «Крепежные элементы», D6: «Крепление фурнитуры (петель,
> направляющих), **задних стенок ХДФ/ДВП**.» — о **саморезе мебельном**
> 3.5×16 / 4×16 / 4×30.

Всё. Ни шага, ни количества, ни отступа от края, ни правила
сегментации панели.

### 3.2. Это утверждение противоречит единственному реальному заказу

| Источник | Чем крепится задняя стенка изделия A |
| --- | --- |
| Приложенный файл (F-20) | **саморез мебельный** |
| Заказ 52987 (`efb792e6-*.xlsx`) | **гвоздь толевый 2×20 — 125 шт** и **скрепка-крабик для ХДФ — 32 шт** |
| Заказ 52987, позиция «саморез» | 40 шт, подписана «(для направл/петля/ножки)» — **явно не для задней стенки** |
| `df352deb-*.pdf` (спецификация того же заказа) | то же самое |

То есть в единственном производственном документе, происхождение
которого установлено, задняя стенка саморезами **не крепится вовсе**, и
это сказано прямо в подписи позиции.

**Разрешать это противоречие «по предпочтению» нельзя** (§7). Оно
фиксируется как есть: общее утверждение без происхождения против
конкретного заказа с происхождением. Ни то, ни другое не становится
правилом.

### 3.3. Проверка четырёх предрегистрированных гипотез

Гипотезы и их предсказания зарегистрированы заранее, до этого источника
(`docs/PM17_PRODUCT_B_EVIDENCE_SEARCH.md` §4):

| Гипотеза | Предсказание для изделия B | Что даёт приложенный файл | Статус |
| --- | --- | --- | --- |
| **H1** единый шаг 100 мм по контуру | 80 | ничего: шага в файле нет | **не исключена** |
| **H2** фиксированное число на панель | 24 | ничего: количества в файле нет | **не исключена** |
| **H3** шаг по внешнему периметру | 37 | ничего | **не исключена** |
| **H4** ряды по горизонталям + средние точки | 52 | ничего | **не исключена** |

**Исключено гипотез этим источником: 0. Выживших: 4.**

Это честный результат, а не неудача разбора: источник просто не
содержит величины, которая различала бы гипотезы. Заполнять пробел
пропорцией, отраслевой практикой или округлением запрещено и не
делалось.

### 3.4. Решение

**PM-17: BLOCKED.**

## 4. PM-06 — петли (§5)

Здесь источник даёт больше всего — и всё равно недостаточно. Параметры
модели и правило количества разделены строго.

### 4.1. Параметры модели петли

| Параметр | Источник | Уровень | Пригодно к реализации? |
| --- | --- | --- | --- |
| Тип | «четырехшарнирная (накладная)» (M-01) | L1 | как значение перечисления — да, числа не требует |
| Диаметр чашки | **35 мм** (M-03) | **L2** | единственное однозначное число во всём файле по петле |
| Угол открывания | **95°–110°** (M-02) | L2 | **нет**: диапазон; выбрать значение — новое допущение |
| Регулировка | «в 3 плоскостях» (M-04b) | L1 | к расчёту не относится |
| Вариант с доводчиком | «Clip-on, встроенный демпфер» (M-05, M-06) | L1 | без единого числа |

Чего среди параметров **нет** и что нужно для присадки (`T-DRILL-01`):

| Нужно | Есть в источнике? |
| --- | --- |
| глубина чашки | **нет** |
| отступ центра чашки от края створки | **нет** |
| отступ крайней петли от торца фасада | **нет** |
| межосевое расстояние крепёжных отверстий планки | **нет** |
| диаметр и глубина отверстий планки | **нет** |
| зависимость присадки от толщины фасада | **нет** |

Диаметр чашки 35 мм — один параметр из семи. Присадку по нему построить
нельзя.

### 4.2. Правило количества петель на створку

| Что искалось | Найдено |
| --- | --- |
| число петель на створку | **нет** |
| пороги по высоте фасада | **нет** |
| пороги по массе фасада | **нет** |
| зависимость от ширины или толщины | **нет** |

Подтверждения нет и извне: **в заказе 52987 петель нет ни одной** —
изделие A без распашных фасадов. Второго источника по петлям не
существует вовсе.

### 4.3. Решение

Формулировка по §5 задачи:

> **HARDWARE MODEL PARAMETERS CONFIRMED / COUNT RULE NOT CONFIRMED /
> IMPLEMENTATION BLOCKED**

С двумя оговорками, без которых эта строка вводила бы в заблуждение:

1. «CONFIRMED» здесь означает **«заявлено источником»**, а не
   «подтверждено независимо»: у файла нет происхождения (§1.3
   forensics), а второго источника по петлям нет. Уровень — L2, не L3.
2. Однозначный параметр ровно один — чашка 35 мм. Остальное либо
   диапазон, либо текст.

`T-HW-01` (правило количества петель) и `T-DOOR-05` (пороги по высоте)
остаются `unknown`. `hingeRule` продолжает возвращать 0 петель.

**PM-06: BLOCKED.**

| --- | --- |
| ряд номинальных длин (`T-DRW-03`) | **нет**: «250-600» — диапазон, а не ряд. Настоящий ряд дискретен (250, 300, 350, 400…), и шага источник не называет |
| правило выбора длины по глубине ящика | **нет** |
| правило округления глубины до номинала | **нет** |
| боковой зазор короба (`T-DRW-06`) | **нет** ни числа |
| высота боковины короба (`T-DRW-07`) | **нет** |
| вертикальное положение короба в проёме | **нет** |
| состав короба и толщины его деталей | **нет** |
| формула фасада ящика (`T-DRW-04`) | **нет** |
| количество направляющих на ящик | **нет** |

Диапазон «250–600 мм» **не заменяет** ряд номиналов. Из него нельзя
получить «для глубины 369 берём 350»: чтобы так сделать, нужно знать шаг
ряда и правило округления, а их в файле нет. Это и есть граница между L2
и L4.

### 5.3. Решение

**FR-04: BLOCKED.** Короб ящика по-прежнему не строится, и это
по-прежнему честно: `DRAWER_BOX_NOT_IMPLEMENTED` сообщается на уровне
`info`, а не маскируется.

`T-DRW-03`, `T-DRW-04`, `T-DRW-05`, `T-DRW-07` остаются `unknown`.
`T-DRW-06` (зазор 12.7/13 мм) и `T-DRW-01` (модель и длина направляющей)
своих статусов не меняют: приложенный файл не добавил к ним ничего — он
лишь не противоречит им.
