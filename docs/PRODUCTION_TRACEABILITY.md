# Production Traceability

Как производственная строка связана с изделием — и почему связи не
изобретаются.

Экран — `PRODUCTION_UI.md`. Чертёж — `PRODUCTION_DRAWINGS.md`. Присадка —
`DRILLING_UI.md`. Раскрой — `CUTTING_UI.md`.

---

## 1. ЦЕПОЧКА

```
FurnitureProject
   └─ SectionNode (ячейка, полка, створка)
        └─ Part            физическая деталь изделия
             └─ ProductionPart   что изготовить
                  ├─ PartBOMItem      строка спецификации
                  ├─ DrillingOperation
                  ├─ HardwareItem
                  └─ CuttingPlacement
```

Все звенья существуют в данных с PROMPT 16–19 и заполняются расчётными
слоями:

| Связь                             | Поле                                                  |
| --------------------------------- | ----------------------------------------------------- |
| Позиция → физические детали       | `PartBOMItem.sourcePartIds`                           |
| Позиция → узлы модели             | `PartBOMItem.sourceNodeIds`                           |
| Позиция → производственные детали | `PartBOMItem.productionPartIds`                       |
| Операция → деталь                 | `DrillingOperation.productionPartId`, `.sourcePartId` |
| Операция → правило                | `DrillingOperation.ruleId`, `.reason`                 |
| Операция → фурнитура              | `DrillingOperation.sourceHardwareId`                  |
| Фурнитура → деталь                | `HardwareItem.sourcePartId`, `.sourceNodeId`          |
| Фурнитура → правило               | `HardwareItem.ruleId`, `.reason`                      |
| Размещение → деталь               | `CuttingPlacement.productionPartId`, `.sourcePartId`  |

`src/app/production/traceability.ts` только **читает** эти поля. Где связи
в данных нет, догадка не появляется: функция возвращает пустой список, а
интерфейс говорит, чего не хватает (§9).

---

## 2. ДВА ИДЕНТИФИКАТОРА, КОТОРЫЕ НЕЛЬЗЯ ПУТАТЬ

- `PartBOMItem.id` — `bom:…`, строка спецификации;
- `ProductionPart.id` — `pp:…`, производственная деталь.

`DrillingPlan.byProductionPart` и `CuttingPlacement.productionPartId`
ключуются **вторым**. Позиция знает свои производственные детали
(`productionPartIds`), и связь идёт через них.

До PROMPT 29 поиск шёл по `item.id` и не находил ничего никогда: страницы
чертежей в PDF не появлялись вовсе, а любая деталь выглядела «не
размещённой на листах». Подробности — `PRODUCTION_DRAWINGS.md` §4.

---

## 3. ОДНО ВЫДЕЛЕНИЕ НА ВСЕ РАЗДЕЛЫ

Выбранная позиция деталировки **выводится** из общего выделения, а не
хранится отдельно:

```
selectedParts (session store)
      ↓  PartBOMItem.sourcePartIds
selectedProductionItem
      ↓
Детали · Чертёж · Присадка · Раскрой · Спецификация
```

Поэтому деталь, выбранная в трёхмерной сцене, оказывается выбранной в
деталировке; выбранная в деталировке — подсвечена на карте раскроя;
выбранная на карте — открыта в подробностях. Второго состояния выбора не
заводится: оно рано или поздно разошлось бы с первым (§29).

Тот же приём, что у `selectedCellId` в конструкторе: производные
величины не хранятся.

## 4. ПЕРЕХОДЫ

| Из                           | В             | Что делает                                          |
| ---------------------------- | ------------- | --------------------------------------------------- |
| Деталь → 3D (§31)            | конструктор   | выделяет физическую деталь, сцена её подсвечивает   |
| Деталь → конструктор (§32)   | шаг «Ячейки»  | выделяет узел модели, из которого деталь получилась |
| 3D → производство (§30)      | деталировка   | строка детали уже выбрана: выделение общее          |
| Карта раскроя → деталь (§20) | подробности   | по `productionPartId` размещения                    |
| Фурнитура → деталь (§25)     | деталировка   | по `HardwareItem.sourcePartId`                      |
| Сводка → раздел (§3)         | нужный раздел | число на сводке — кнопка                            |

---

## 5. ГДЕ СВЯЗИ НЕ ХВАТАЕТ

Не у всех позиций есть узел модели. Каркасные детали — боковины, дно,
крышка, задняя стенка — порождаются самим корпусом, а не узлом дерева
секций, поэтому `sourceNodeIds` у них пуст.

Интерфейс говорит это прямо:

> Узел модели у этой позиции не записан, поэтому показать её место в
> изделии нельзя. Это не догадка интерфейса, а отсутствующая связь в
> данных.

Кнопка «Открыть в конструкторе» для таких позиций выключена. Показать
вместо этого «секция 1» было бы догадкой: боковина не принадлежит первой
секции, она принадлежит корпусу.

Это **не** `NEEDS_CONFIRMATION`: неизвестного правила здесь нет,
отсутствует связь, которой в модели и не должно быть. Заводить её ради
кнопки значило бы приписать детали место, которого у неё нет.

## 6. ЧТО ПРОВЕРЯЕТСЯ

`tests/unit/app/production-view.test.ts`: деталь находится по физической
детали, раскладка связывается по производственной детали, место берётся

только через записанный источник.

переходы в 3D и обратно сохраняют выделение.
