## Граница представления (§11)

```
ВНУТРЕННЯЯ МОДЕЛЬ            ГРАНИЦА             ЧТО ВИДИТ ЧЕЛОВЕК
PartRole, HardwareKind,   →  словарь домена  →   деталировка,
Grain, EdgeSpec,             и словари своих     спецификация,
ProductionPartType,          слоёв               раскрой, чертёж,
PartCategory, DrillFace,                         PDF, XLSX
UnplacedReason, …
```

**Обычная производственная поверхность может содержать:** размеры,
количества, материалы, человеческие имена деталей и фурнитуры,
состояния правил, предупреждения словами.

**Не может содержать:** значения перечислений, цепочки UUID, внутренние
ключи реестра фурнитуры, пути исходников, идентификаторы объектов —
**кроме** явного технического контекста.

**Что остаётся и почему.** Коды реестра предположений (`T-DRW-02`) и
коды диагностики (`MATERIAL_NOT_ASSIGNED`) сохранены: они отвечают на
«почему» и были заведены намеренно (PROMPT 58 §9). Но порядок изменён —
сначала смысл, потом источник:

| Было | Стало |
| --- | --- |
| `DRAWER_BOX_NOT_IMPLEMENTED: Короб ящика…` | `Короб ящика… [DRAWER_BOX_NOT_IMPLEMENTED]` |
| `Требует подтверждения: CONSTRUCTION T-DRW-02` | `Требует подтверждения: Конструкция [T-DRW-02]` |

### Почему словарь переехал в домен

`boundaries/element-types` не пускает `export` в слой `app`. Пока слова
жили в `app/vocabulary.ts`, PDF и XLSX физически не могли ими
пользоваться — и не пользовались. Это и было причиной, по которой
PROMPT 58 починил конструктор и не починил производство.

### Найденный по дороге дефект прослеживаемости

`partNameById` строилась по `item.id` (`bom:…`), а искали в ней по
`productionPartId` (`pp:…`). Совпадения не случалось **никогда**, и во
все листы — раскроя, присадки, неразмещённых — уходил запасной
вариант: сам машинный ключ. Карта перестроена по `productionPartIds`.
Это тоже представление: расчёт не затронут.

## Измерение (§14)

Метод тот же, что у PROMPT 61: таблица **«Детали»** раздела
«Производство», 8 строк спецификации × 9 колонок тела (без колонки «№»,
у которой содержимое — номер), **72 ячейки**; считаются ячейки,
содержащие хотя бы один латинский символ.

| | Ячеек с латиницей | Доля |
| --- | --- | --- |
| **BEFORE** (`b6b92a6`) | **23 из 72** | **32 %** |
| **AFTER** | **0 из 72** | **0 %** |

Сплошной обход всего видимого текста раздела «Производство»
(1440 × 900, изделие построено целиком) даёт три латинских фрагмента:
`T-DRW-`, `T-HW-`, `T-DRILL-` — префиксы кодов реестра предположений,
сохранённых намеренно. Значений перечислений, ключей фурнитуры и
идентификаторов объектов нет ни одного.
