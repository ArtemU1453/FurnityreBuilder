# Система координат

Реализация: `src/domain/coordinates.ts`. Проверки: `tests/unit/domain/coordinates.test.ts`,
`tests/unit/geometry/carcass.test.ts`.

Документ фиксирует то, что в мебельных расчётах чаще всего остаётся
неформализованным и потом оборачивается зеркальными деталями и ошибками
присадки.

---

## 1. ОСИ И НАЧАЛО

Тройка правая. Начало координат — **левый–нижний–задний угол габарита изделия**,
если смотреть на фасад.

| Ось | Направление | Габарит |
| --- | --- | --- |
| `x` | вправо | ширина `W` |
| `y` | вверх | высота `H` |
| `z` | от задней плоскости вперёд, к пользователю | глубина `D` |

```
            y (высота)
            ↑
            │      ┌─────────────┐
            │     ╱             ╱│
            │    ┌─────────────┐ │
            │    │             │ │
            │    │   ФАСАД     │ │
            │    │             │ ╱
            │    └─────────────┘
            └───────────────────────→ x (ширина)
           ╱
          ↙ z (глубина, к пользователю)
      начало координат: левый–нижний–задний угол
```

**Почему `y` вверх.** Совпадает с тем, как человек говорит о мебели: полка
выше, ящик ниже. Экран рисует `y` вниз — это забота слоя отрисовки, домен
про экран ничего не знает. Инверсия делается один раз, в матрице viewport.

**Почему `z` вперёд.** Глубина растёт в сторону пользователя, поэтому
«передняя кромка полки» — это большее `z`, а не меньшее. Фасад стоит
на максимальном `z`, задняя стенка — на минимальном.

---

## 2. ПОЛОЖЕНИЕ ДЕТАЛИ

`Part.position` — координата **минимального угла** детали `(min-x, min-y, min-z)`.
Никогда не центр.

```ts
const max = boxMax({ min: part.position, size: part.size });
```

Причина: минимальный угол устойчив при изменении размера. Центр «плавает»,
и любое изменение габарита превращается в пересчёт положения каждой детали.

`Part.size` — габарит детали по осям изделия, всегда положительный.
Отрицательных размеров в модели не бывает; попытка их создать — ошибка
валидации, а не «деталь, вывернутая наизнанку».

---

## 3. ГДЕ НАЧИНАЕТСЯ КОРПУС

Задняя стенка занимает место по оси `z` перед корпусом, а не за ним:
начало координат — задняя плоскость **изделия целиком**, включая стенку.

Для накладной задней стенки толщиной `Tb` (`resolveBackGeometry`
в `src/geometry/stages/carcass.ts`):

```
задняя стенка   z ∈ [0, Tb]
корпус          z ∈ [Tb, Tb + Dc]
```

где `Dc` — глубина корпусных деталей:

```
Dc = tolerances.depthIncludesBackPanel ? D − Tb : D
```

Проверено тестом: при `D = 500`, `Tb = 3`, `depthIncludesBackPanel = true`
боковина имеет глубину `497` и стоит на `z = 3`.

Для вкладной стенки корпус занимает всю глубину (`z ∈ [0, D]`), а внутренняя
граница смещается на толщину стенки.

ASSUMPTION(T-CAR-04): монтаж и вхождение стенки в габарит не подтверждены;
оба варианта реализованы и выбираются параметром.

## 4. ВНУТРЕННИЙ ОБЪЁМ

`GeometryResult.innerVolume` — пространство, в котором раскладывается дерево
секций. Для схемы `sides-through` при `W=1000, H=2000, D=500, T=16`:

```
min  = (16, 16, 3)
size = (968, 1968, 497)
```

Внутренний объём **не совпадает** с габаритом за вычетом толщины: он зависит
от схемы стыка, наличия верха и низа и монтажа задней стенки. Поэтому он
вычисляется движком, а не выводится в UI формулой.

---

## 5. ЛОКАЛЬНЫЕ КООРДИНАТЫ ДЕТАЛИ

Для раскроя, кромки и присадки деталь рассматривается как плоский
прямоугольник. Соответствие задаёт `Part.orientation`
(`src/geometry/parts.ts`, функция `rawCutSize`):

| Ориентация | Толщина | Длина | Ширина | Примеры |
| --- | --- | --- | --- | --- |
| `vertical-yz` | по `x` | по `y` (высота) | по `z` (глубина) | боковина, перегородка |
| `horizontal-xz` | по `y` | по `x` (ширина) | по `z` (глубина) | полка, верх, низ |
| `frontal-xy` | по `z` | по `y` (высота) | по `x` (ширина) | фасад, задняя стенка |

В локальной системе детали:

```
        ширина (width)
          ↑ front
          │
  left ───┼─── right      длина (length) идёт слева направо
          │
          ↓ back
```

Отсюда правило кромки: `left` и `right` уменьшают **длину**,
`front` и `back` — **ширину**. Толщину кромка не меняет.

```ts
length = raw.length − edge.left − edge.right
width  = raw.width  − edge.back − edge.front
```

Вычитание применяется только при `EdgeSizingPolicy.subtractFromPartSize`.
ASSUMPTION(T-EDG-03): правило не подтверждено, обе ветки реализованы
и покрыты тестами.

## 6. КООРДИНАТЫ ОТВЕРСТИЙ

`DrillHole.u` и `DrillHole.v` — координаты в локальной системе детали,
от её минимального угла, на грани `face`. Ось `u` идёт вдоль `length`,
`v` — вдоль `width`.

Присадка (этап 28 плана) ещё не реализована; тип зафиксирован сейчас,
чтобы позже не переопределять систему отсчёта задним числом.

---

## 7. ЧТО ЗАПРЕЩЕНО

| Запрещено | Почему |
| --- | --- |
| Отрицательные размеры | «Вывернутая» деталь — всегда ошибка расчёта, а не валидное состояние |
| Позиция как центр детали | Неустойчива при изменении габарита |
| Инверсия `y` внутри домена | Экранная система координат не должна протекать в модель |
| Локальные оси, не выведенные из `orientation` | Иначе кромка и присадка расходятся с геометрией |
| Смешение локальных и глобальных координат в одном значении | Источник зеркальных деталей |

## 8. ПРОВЕРКИ

- `sliceAlong` меняет только одну ось — тест `coordinates.test.ts`.
- Детали каркаса не пересекаются — тест `carcass.test.ts`.
- Ни одна координата не является NaN или бесконечностью — `isFiniteBox3`,
  проверяется и в `GeometryContext.addPart`, и тестом.
- Правая боковина стоит на `x = W − T` — тест фиксирует конкретное число.
