# Порядок реализации

PROMPT 65-B §10. Пробелы, выстроенные по шести критериям задания:
мешает ли производству · закрывает ли ключевую возможность референса ·
портит ли производственный результат · готовы ли правила · велик ли
архитектурный риск · открывает ли дорогу другим возможностям.

База: коммит `f4ea61f`. Изменений в коде продукта в этом промпте — **0**.

## Приоритет 1 — `PM-18`. Корпусный крепёж

| | |
| --- | --- |
| **Возможность референса** | не наблюдалась отдельно, но подразумевается любым изделием |
| **Почему важно** | **Из выдаваемой спецификации фурнитуры изделие невозможно собрать.** Обычный шкаф с дверями и полками даёт сегодня «Полкодержатель 16 шт» и больше ничего конструктивного. Это относится к КАЖДОМУ изделию, а не к особому случаю |
| **Состояние доказательств** | `L2`. Стыки уже находятся и считаются (`findCarcassJoints`); не хватает **одного числа** — крепежа на стык |
| **Реализация разрешена?** | **НЕТ.** `CARCASS_FASTENERS_PER_JOINT` остаётся `undefined`, пока число не подтверждено |
| **Зависимости** | `T-HW-03`. Ветка расчёта уже написана и включится сама, как только константа перестанет быть `undefined` |
| **Ожидаемое влияние** | спецификация фурнитуры становится пригодной к закупке на всех изделиях сразу |
| **Что нужно достать** | правило количества крепежа на стык: справка референса, либо техкарта сборки корпусной мебели |

Почему первым, хотя это не самая заметная функция: критерии 1 и 3
выполняются сильнее, чем у любого другого пробела, а объём работы —
наименьший из всех (одна константа при готовом алгоритме).

## Приоритет 2 — `PM-06`. Петли распашных дверей

| | |
| --- | --- |
| **Возможность референса** | двери выбираются в конструкторе; справка описывает регулировку петель (`D2`) |
| **Почему важно** | дверь **строится**, петли **не считаются вовсе** — единственный случай класса D (геометрия есть, производства нет) среди основных возможностей. Дверь без петель не навесить |
| **Состояние доказательств** | `L2`. Створки находятся; неизвестны пороги «сколько петель на какую высоту» |
| **Реализация разрешена?** | **НЕТ** |
| **Зависимости** | `T-DOOR-05`; крепёж петли (`HW-02`) включится следом автоматически |
| **Ожидаемое влияние** | закрывает вторую по массовости дыру спецификации; вместе с приоритетом 1 делает корпус с дверями собираемым |
| **Что нужно достать** | таблицу порогов по высоте створки — каталог петель или справка референса |

## Приоритет 3 — `PM-17`. Крепёж задней стенки

| | |
| --- | --- |
| **Возможность референса** | задняя стенка видна как опция (`D2`) |
| **Почему важно** | третья и последняя дыра в крепеже корпуса. Деталь строится, крепления нет |
| **Состояние доказательств** | `L2`. Периметр уже считается; неизвестен шаг |
| **Реализация разрешена?** | **НЕТ** |
| **Зависимости** | `T-HW-03`, тот же источник, что у приоритета 1 |
| **Ожидаемое влияние** | вместе с 1 и 2 — полный крепёж корпуса |
| **Что нужно достать** | шаг крепления по периметру и отступ от края |

> Приоритеты 1–3 закрываются, скорее всего, **одним документом**: справка
> референса по сборке либо любая техкарта корпусной мебели содержит все
> три правила разом. Поэтому они и стоят подряд.

## Приоритет 4 — `PM-12`. Штанга для одежды

| | |
| --- | --- |
| **Возможность референса** | «штанги» перечислены среди наполнения; есть готовое изделие «2 штанги + штанга/полки» (`D2`) |
| **Почему важно** | основное наполнение платяного шкафа, а раздел референса называется «гардероб». В домене `LeafFill.kind: 'rod'` существует, интерфейс её не предлагает, геометрия не строит |
| **Состояние доказательств** | `L1` — известна только категория |
| **Реализация разрешена?** | **НЕТ** |
| **Зависимости** | `T-HW-05`; нужны позиции реестра для `rod` и `rod-flange`, которых нет |
| **Ожидаемое влияние** | новая возможность наполнения: 1 деталь + 2 позиции фурнитуры на отделение |
| **Что нужно достать** | профиль и ряд; формулу длины; крепление; минимальную глубину; максимальный пролёт |

Почему выше ящика: штанга проще (одна труба и два фланца против короба
из пяти панелей), а разрыв с референсом — полный, тогда как у ящика
частичный.

## Приоритет 5 — `FR-04`. Короб ящика

| | |
| --- | --- |
| **Возможность референса** | «выдвижные ящики»; страница сборки называет состав: две боковины, передняя и задняя стенка, фасад, тонкое дно (`D2`, частично) |
| **Почему важно** | пользователь добавляет ящик и получает в деталировке одну панель |
| **Состояние доказательств** | подтверждены **2 величины из 8** |
| **Реализация разрешена?** | **НЕТ** — `OUTCOME B` по §8 |
| **Зависимости** | `T-DRW-07`, `T-DRW-03`, `T-DRW-01` |
| **Ожидаемое влияние** | +4 детали на ящик; направляющие получают узел, к которому крепятся |
| **Что нужно достать** | монтажную инструкцию конкретной модели направляющей ЛИБО страницы референса `/sborka_yashika` и `/178-vidvijnie_yashiki` целиком |

Понижен с первого места (где он был после PROMPT 65-A) не потому, что
стал менее важен, а потому, что аудит нашёл три пробела, которые бьют по
**каждому** изделию, а не только по изделиям с ящиками, и стоят дешевле.

## Что НЕ является следующей задачей

| Соблазн | Почему нет |
| --- | --- |
| Реализовать короб ящика «наконец-то» | шесть размеров из восьми пришлось бы выдумать |
| Проставить крепёж «по здравому смыслу» (4 на стык) | это ровно тот случай, который запрещает §0 |
| Добавить штангу цилиндром в сцену | §2 D прямо запрещает: «Do not add a rail merely as a visual cylinder» |
| Убрать предупреждения, раз они портят статус | скрыть реальный производственный риск |
| Нарисовать обувницу по числам из поисковой сводки | источник чисел не атрибутирован |

## Единственное действие, которое разблокирует всё

Открыть и прочитать целиком **справку референса** (`/help`) и три
страницы: `/sborka_yashika`, `/178-vidvijnie_yashiki`,
`/376-obuvnica_kakie_razmeri_vibrat`.

Сегодня они недоступны: сетевая политика среды отвечает `403` на
`CONNECT` к домену референса — проверено четырежды за четыре разные
даты. Содержимое, приложенное к задаче текстом или файлом, снимает
блокировку сразу по нескольким пунктам этого списка.

Альтернатива для приоритетов 1–3, не зависящая от референса: любая
техкарта сборки корпусной мебели с правилами крепежа. Для приоритета 5 —
монтажная инструкция модели направляющей.

## Дополнение: что изменилось после разбора официальных страниц (PROMPT 65)

Пункт «открыть и прочитать справку референса» выполнен **наполовину** и
уточняется, а не вычёркивается.

| Что оказалось | Подробности |
| --- | --- |
| Прямая загрузка по-прежнему невозможна | но причина шире, чем считалось: прокси отвечает `403` на `CONNECT` **к любому домену**, а не только к референсу — проверено на постороннем адресе |
| Страницы существуют и читаются через поиск | найдено и разобрано 8 запросов, около 20 адресов; тексты извлечены |
| Уровень полученного — **L1** | это пересказ индекса, а не дословный текст страницы; по правилу доказательств L1 не обосновывает числовое производственное правило |

**Приоритеты не изменились.** Ни один пункт списка не закрыт.

Что теперь известно точнее о том, чего искать:

1. Для PM-17 искать нужно **не «шаг»**: официальная инструкция
   предписывает «как можно больше точек», то есть шага как проектной
   величины, по-видимому, нет. Количество (125 гвоздей в заказе)
   считает конструктор, и этот расчёт на сайте не опубликован.
2. Для PM-18 источник сам называет место, где количества напечатаны, —
   **схема сборки, приходящая с заказом**. Это самый короткий путь.
3. Для FR-04 опубликованная формула полезной глубины оказалась
   планировочной оценкой: она не воспроизводит ни один измеренный размер
   изделия A.

Самое дешёвое действие осталось прежним и стало конкретнее: **дословный
текст `/10-kak_sobrat`, `/440-kak_pravilno_krepit_zadnyuyu_stenku_shkafa`
и `/sborka_yashika`, либо схема сборки из любого заказа.**
