# Где что делать: пути к действиям сборки

PROMPT 59 §10. Таблица существует затем, чтобы на вопрос «куда идти
новичку за этим действием» был **ровно один** ответ.

| | |
| --- | --- |
| Repository | `ArtemU1453/FurnityreBuilder` |
| Branch | `claude/furniture-designer-audit-cjvvuf` |

## Правило

| Область действия | Первичный путь |
| --- | --- |
| **Отделение** — то, что человек выбрал щелчком | у самого отделения: кнопки инспектора |
| **Изделие целиком** | шаг конструктора |
| **Параметр уже поставленного** | шаг конструктора |

Основание — PROMPT 54: «увидеть изделие → щёлкнуть отделение → увидеть
действия». Решение измерено (0 из 9 против 9 из 9) и здесь не
отменяется.

## Действия над отделением

### Поставить полки

| | |
| --- | --- |
| **Намерение** | «пусть здесь будут полки» |
| **Первичный путь** | выбрать отделение → «Добавить полки» |
| **Вторичный путь** | шаг 6 «Наполнение» → переключатель «полки» |
| **Почему первичный** | действие принадлежит конкретному отделению, и делается там, где на него смотрят |
| **Почему вторичный** | на телефоне лист шага закрывает лист инспектора; без кнопки в шаге человек остался бы без действия. Плюс шаг показывает все варианты наполнения разом |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'shelves' }` |

### Сколько полок

| | |
| --- | --- |
| **Намерение** | «пусть их будет четыре» |
| **Первичный путь** | шаг 5 «Полки» → поле «Полок в выбранной ячейке» |
| **Вторичный путь** | нет |
| **Почему первичный** | это **параметр**, а не действие; числа в инспекторе нет и не заводится |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'shelves', shelves: n }` |

### Поставить ящики

| | |
| --- | --- |
| **Первичный путь** | выбрать отделение → «Добавить ящики» |
| **Вторичный путь** | шаг 7, панель «Фасады ящиков» → «Добавить ящик» |
| **Почему вторичный** | там же задаётся способ открывания ящиков — параметр, которого в инспекторе нет |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'drawers' }` |

### Поставить дверь

| | |
| --- | --- |
| **Первичный путь** | выбрать отделение → «Добавить дверь» |
| **Вторичный путь** | шаг 7 «Фасады» → «Добавить дверь» |
| **Почему вторичный** | рядом стоят сторона петель, накладной/вкладной, материал, кромка и открывание — всё, чего в инспекторе нет |
| **Область** | отделение |
| **Команда** | `AddFacade` |

### Убрать дверь

| | |
| --- | --- |
| **Первичный путь** | выбрать отделение → «Убрать дверь» |
| **Вторичный путь** | шаг 7 → «Убрать дверь» |
| **Область** | отделение |
| **Команда** | `RemoveFacade` |

### Очистить отделение

| | |
| --- | --- |
| **Первичный путь** | выбрать отделение → «Очистить ячейку» |
| **Вторичный путь** | шаг 6 → «Пусто» |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'empty' }` |

### Настройка двери: сторона петель, накладной/вкладной, материал, кромка, открывание

| | |
| --- | --- |
| **Первичный путь** | шаг 7 «Фасады» |
| **Вторичный путь** | нет |
| **Почему первичный** | параметры уже поставленной двери; нигде больше не задаются |
| **Область** | отделение |
| **Команда** | `UpdateFacadeLeaf` |

## Одна реализация на операцию

Каждое действие над отделением вызывает **один обработчик**, независимо
от того, нажата кнопка инспектора или кнопка шага. До PROMPT 59 три из
пяти действий инспектора собирали свой вызов, и «Добавить полки» ставила
ровно одну полку, затирая заданное число, — та же подпись, другое
поведение.

| Действие | Обработчик |
| --- | --- |
| Добавить дверь | `addDoor` |
| Убрать дверь | `removeDoor` |
| Добавить ящики | `addDrawer` |
| Полки / очистить | `setCellFillKind` |
| Число полок | `setCellShelfCount` |

## Цель действия — одна на всё приложение

`selectedCellId` **выводится** из выделения; `setSelectedCellId` вызывает
тот же `selectNodes`. Инспектор, схема, сцена и селектор шага «Фасады»
смотрят на одно состояние. Второй модели выделения нет и не заводится.
