## Правило

| Область действия | Первичный путь |
| --- | --- |
| **Отделение** — то, что человек выбрал щелчком | у самого отделения: кнопки инспектора |
| **Изделие целиком** | шаг конструктора |
| **Параметр уже поставленного** | шаг конструктора |

Основание — PROMPT 54: «увидеть изделие → щёлкнуть отделение → увидеть
действия». Решение измерено (0 из 9 против 9 из 9) и здесь не
отменяется.

## Действия над отделением

### Сделать отделение полочным (0 → N)

| | |
| --- | --- |
| **Намерение** | «пусть здесь будут полки» |
| **Первичный путь** | выбрать отделение → «Добавить полки» |
| **Вторичный путь** | шаг 6 «Наполнение» → переключатель «полки» |
| **Почему первичный** | действие принадлежит конкретному отделению, и делается там, где на него смотрят |
| **Почему вторичный** | на телефоне лист шага закрывает лист инспектора; без кнопки в шаге человек остался бы без действия. Плюс шаг показывает все варианты наполнения разом |
| **Когда предлагается** | только пока полок нет. С PROMPT 60 это переход 0 → N и ничего больше: на отделении с полками кнопка сохраняла прежнее число, то есть молча не делала ничего |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'shelves' }`, одна полка |

### Сколько полок (N → M, N → 0)

| | |
| --- | --- |
| **Намерение** | «пусть их будет четыре» |
| **Первичный путь** | шаг 5 «Полки» → поле «Полок в выбранном отделении» |
| **Вторичный путь** | нет |
| **Почему первичный** | это **параметр**, а не действие: единственное место, где задаётся число |
| **Где видно число** | в инспекторе и в сводке шага «Ячейки» — строкой «Наполнение: полки, 3 шт». Показывается, но не правится: узнать количество можно не уходя на другой шаг (PROMPT 60 §8) |
| **Где поля нет** | на отделении с другим наполнением. Там количества полок не существует, и `0` читался бы как «полок нет», хотя стоит ящик |
| **Область** | отделение |
| **Команда** | `SetFill` → `{ kind: 'shelves', shelves: n }`, при `n = 0` — `{ kind: 'empty' }` |

## Одна реализация на операцию

Каждое действие над отделением вызывает **один обработчик**, независимо
от того, нажата кнопка инспектора или кнопка шага. До PROMPT 59 три из
пяти действий инспектора собирали свой вызов, и «Добавить полки» ставила
ровно одну полку, затирая заданное число, — та же подпись, другое
поведение.

| Действие | Обработчик |
| --- | --- |
| Добавить дверь | `addDoor` |
| Убрать дверь | `removeDoor` |
| Добавить ящики | `addDrawer` |
| Полки / очистить | `setCellFillKind` → `makeShelvesFill` |
| Число полок | `setCellShelfCount` → `shelfCountFill` |

Решение о том, ЧТО именно означает каждый из этих двух путей, лежит в
одном месте — `src/app/editor/shelf-model.ts` (PROMPT 60). Обработчики
его не дублируют: `makeShelvesFill` отвечает за действие 0 → N,
`shelfCountFill` — за параметр N → M и N → 0, и обе зовут одну доменную
фабрику `createShelvesLeaf`, так что геометрия полок от пути не зависит.

## Ответственность шагов 5 и 6 (PROMPT 60 §15)

| Шаг | Вопрос, на который он отвечает | Чего в нём нет |
| --- | --- | --- |
| **5 «Полки»** | сколько полок в выбранном отделении | выбора вида наполнения: сделать отделение полочным — дело кнопки у изделия или шага 6 |
| **6 «Наполнение»** | чем занято выбранное отделение: пусто, полки или ящики | количества: сколько полок — вопрос шага 5, и только его |

Два шага не соперничают за один вопрос: у каждого свой, и подпись
каждого называет чужой. До PROMPT 60 оба выглядели местом, где
задаётся число полок.

## Цель действия — одна на всё приложение

`selectedCellId` **выводится** из выделения; `setSelectedCellId` вызывает
тот же `selectNodes`. Инспектор, схема, сцена и селектор шага «Фасады»
смотрят на одно состояние. Второй модели выделения нет и не заводится.
