# Производственный пакет

Реализация: `src/workflow/package.ts`, `src/workflow/fingerprint.ts`.
Сценарий — `docs/PRODUCTION_WORKFLOW.md`, проверки —
`docs/PRODUCTION_READINESS.md`.

---

## 1. Что это

`buildProductionPackage(project, {generatedAt, calculation?})` →
`ProductionPackage`: всё, что нужно, чтобы запустить изделие в работу, в
одном объекте.

```ts
interface ProductionPackage {
  projectId; projectName;
  fingerprint;                 // отпечаток входа
  calculation: ProductionCalculationResult;  // расчёт целиком
  readiness: ProductionReadinessResult;      // готовность
  exports: ProductionExportData;             // данные документов
  status: ProductionStatus;
  warnings; errors;
}
```

## 2. Композиция, а не копия

Спецификация, раскрой, присадка и фурнитура доступны через
`calculation` — отдельных полей `bom`/`cutting`/`drilling`/`hardware` в
пакете нет. Копировать их «для удобства» значило бы завести второй BOM,
что §9 запрещает прямо, и получить два ответа на вопрос «сколько
деталей», которые однажды разойдутся.

Тест проверяет это буквально: `pkg.calculation.bom.hardware` — тот же
объект, что и `pkg.calculation.hardware`, а среди ключей пакета нет
`bom`.

**Конвейер прогоняется один раз.** Расчёт выполняется однажды и
передаётся и в проверку готовности, и в подготовку документов. Иначе
сборка пакета трижды прогоняла бы одни и те же правила и могла бы
собрать пакет из трёх разных расчётов.

## 3. Отпечаток и устаревание

Расчёт производный, поэтому устареть не может. Но ПАКЕТ — снимок: его
сохраняют, печатают, уносят в цех, а проект после этого правят.
Устаревший пакет — это распечатка, по которой соберут не тот шкаф.

Поэтому пакет несёт `fingerprint` — детерминированную сериализацию
всего, от чего зависит производственный расчёт: габаритов, корпуса,
дерева секций с наполнением, фасадов, реестра материалов и настроек
проекта.

`isPackageCurrent(pkg, project)` сравнивает отпечаток с текущим
состоянием и отвечает точно, а не «кажется, ничего не менялось».

**Что в отпечаток не входит:** имя проекта, имя изделия, время
изменения, версия приложения. Переименование не меняет ни одной детали,
ни одного отверстия и ни одного листа раскроя; если бы оно объявляло
напечатанный пакет устаревшим, предупреждение об устаревании перестали
бы читать.

**Почему сериализация, а не хеш.** Хеш требует выбора хеш-функции и даёт
коллизии, а выигрыш — только в длине строки, которая никому не
показывается. Отпечаток даёт доказуемый ответ, а не вероятный.

**Тест.** `tests/unit/workflow/package.test.ts` Test 20–23: девять видов
изменения конструкции инвалидируют пакет, переименование — нет.

## 4. Воспроизводимость

Единственное значение, зависящее от момента времени, — `generatedAt`, и
оно передаётся параметром, а не читается из часов. Один и тот же проект
даёт побайтово один и тот же пакет.

Проверено: повторная сборка совпадает; сборка после
сохранения-загрузки совпадает; правка командой и отмена возвращают
исходный пакет.

## 5. Документы

`pkg.exports` — готовые данные для PDF и XLSX. Генераторы вызываются
напрямую (`createProductionPdf`, `createProductionXlsx`) и ничего не
пересчитывают: второго PDF- или XLSX-движка не появляется (§9).

**Тест.** Test 27: из одного пакета собираются оба файла, и оба
начинаются правильными сигнатурами.

## 6. Пакет непригодного проекта

Собирается всегда — и при `INVALID` тоже. Пакет нужен ровно затем, чтобы
увидеть, ЧТО не так: список ошибок и чеклист находятся в нём. Отказ
собрать пакет оставил бы пользователя без единственного внятного отчёта.

**Тест.** Test 28.
