# UX Flow

Полный сценарий: от открытия приложения до производственных файлов.
Для каждого шага: действие пользователя → отклик UI → изменение состояния →
изменение домена → пересчёт геометрии → валидация → обратная связь → движение → ошибки.

Сквозной принцип: **пользователь работает с мебелью, а не с формами.**
Формы — второе представление той же модели, а не путь к ней.

---

## 0. КАРТА СЦЕНАРИЯ

```
Открытие
  → Новый проект (или продолжение последнего)
  → Габариты
  → Каркас
  → Сетка (колонки/строки)
  → Ячейки
  → Наполнение
  → Фасады
  → Материалы
  → Кромка
  → Фурнитура
  → Проверка
  → Сохранение (явное; см. docs/EDITOR_UI.md §5)
  → Экспорт
```

Порядок — рекомендуемый, а не обязательный. К любому шагу можно вернуться в
любой момент; ничего не «запирается» (Agency). Мастера-пошаговика с блокировкой
шагов в приложении нет.

## 1. ОТКРЫТИЕ ПРИЛОЖЕНИЯ

| Аспект | Содержание |
| --- | --- |
| Действие | Пользователь открыл адрес |
| Отклик UI | Оболочка отрисована сразу; асинхронно читается IndexedDB |
| Состояние | `session.boot = 'loading' → 'ready'` |
| Домен | Есть проекты → открывается последний. Нет → создаётся черновик по умолчанию |
| Геометрия | Пересчёт после загрузки документа |
| Валидация | Полный прогон, тихо; проблемы попадают в счётчик статус-бара |
| Обратная связь | Скелет схемы вместо пустого экрана; без спиннера на весь экран |
| Движение | Только кроссфейд появления содержимого |
| Ошибки | IndexedDB недоступен (приватный режим) → работа в памяти + постоянная плашка «изменения не сохраняются автоматически, экспортируйте проект в файл». Повреждённая запись → предлагается восстановление из `revisions` |

**Никакой регистрации, входа, приветственного опроса, cookie-баннера
и запроса разрешений.** Приложение сразу пригодно к работе.

Что видит пользователь через секунду: готовое изделие по умолчанию на схеме
и панель габаритов. Первое действие возможно немедленно.

| Аспект | Содержание |
| --- | --- |
| Действие | «Новый проект» → выбор типа: шкаф / стеллаж / тумба / комод / пустой |
| Отклик UI | Плитки с схематичным превью; выбор мгновенно строит изделие |

Тип влияет только на стартовое наполнение и подсказки — переключение типа позже

## 3. ГАБАРИТЫ

Два равноправных пути.

### 3.1 Через поле

| Аспект | Содержание |
| --- | --- |
| Действие | Пользователь правит «Ширина» |
| Отклик UI | Схема перестраивается **на каждом валидном промежуточном значении**, без debounce |
| Состояние | Транзакция истории открыта на `focus` |
| Домен | `SetDimension` |
| Геометрия | Полный пересчёт (< 5 мс) |
| Валидация | Пролёт полок, минимальные размеры ячеек — в реальном времени |
| Обратная связь | Размерная линия на схеме подсвечена и меняется синхронно |
| Движение | Нет: значение точное, анимировать нечего |
| Ошибки | Нечисловой ввод игнорируется. Значение вне рекомендуемого диапазона → предупреждение, не блокировка |
| Undo | Вся серия правок в одном фокусе — один шаг истории |

### 3.2 Через схему

| Аспект | Содержание |
| --- | --- |
| Действие | Перетаскивание габаритного маркера |
| Отклик UI | Маркер следует 1:1 с точкой захвата; изделие в preview-режиме; число в поле меняется в тот же кадр |
| Состояние | Interaction state в ref; домен не трогается |
| Домен | Одна команда на `pointerup` |
| Геометрия | Preview не чаще кадра, вне истории; полный расчёт на commit |
| Валидация | Предупреждения в реальном времени, поверх схемы |
| Обратная связь | Метка размера у курсора; линии привязки к круглым значениям |
| Движение | Доводка `move` к привязке, если она в 6 px |
| Ошибки | `Esc` — отмена; предел минимума — жёсткий стоп с объяснением |

Оба пути изменяют одно и то же. Значения совпадают всегда — они читаются из
одной модели.

### 3.3 Толщина материала

Изменение `T` перестраивает **все** детали. Показывается сводка последствий:
«изменится 42 детали». Отменяется одним undo.

## 4. КАРКАС

| Аспект | Содержание |
| --- | --- |
| Действие | Переключение: верх, низ, задняя стенка, цоколь/ножки, столешница; выбор схемы стыка |
| Отклик UI | Деталь появляется/исчезает на схеме немедленно |
| Домен | Изменение `CarcassSpec` / `ConstructionScheme` |
| Геометрия | Смена схемы стыка меняет размеры боковин и горизонталей — деталировка обновляется целиком |
| Валидация | Отсутствие задней стенки при большой ширине → предупреждение о жёсткости |
| Обратная связь | Изменившиеся детали кратко подсвечиваются (250 мс) — видно, что затронуто |
| Ошибки | Нет |

Схема стыка — видимая настройка с наглядной иллюстрацией, а не скрытая
константа. Это прямой ответ на `UNKNOWN T-CAR-01`: пока конвенция референса
неизвестна, выбор остаётся за пользователем, и это честно.

## 5. СЕТКА: КОЛОНКИ И СТРОКИ

| Аспект | Содержание |
| --- | --- |
| Действие | Выбор ячейки → «Разделить по вертикали / по горизонтали», указание количества |
| Отклик UI | Перегородки появляются с равномерным делением |
| Домен | `SplitNode` заменяет `LeafNode`; дети получают `mode: 'flex', weight: 1` |
| Геометрия | Перерасчёт поддерева |
| Валидация | Ячейка меньше `minCellSize` → предупреждение с предложением уменьшить количество |
| Обратная связь | Новые размеры показываются на каждой ячейке |
| Движение | Нет. Появление перегородки — это факт конструкции, не переход |
| Ошибки | Нельзя разделить ячейку с наполнением без подтверждения; наполнение сохраняется в первой из новых ячеек, откат — undo |

Альтернативный путь: перетащить перегородку из палитры прямо в схему.
Приложение поддерживает оба — и «через панель», и «прямо на изделии».

## 6. ЯЧЕЙКИ: РАЗМЕРЫ И ВЫБОР

| Аспект | Содержание |
| --- | --- |
| Действие | Перетаскивание перегородки |
| Отклик UI | Перегородка следует 1:1; **обе** соседние ячейки показывают свои размеры одновременно |
| Состояние | Транзакция; interaction state в ref |
| Домен | `MoveDivider` на `pointerup` |
| Геометрия | Preview на кадр, полный расчёт на commit |
| Валидация | Достижение `minCellSize` → жёсткий стоп, метка краснеет |
| Обратная связь | Магниты: равные доли, кратность 32 мм, выравнивание с перегородкой выше/ниже |
| Движение | Доводка `move` к привязке |
| Ошибки | `Esc` — отмена жеста |

**Фиксация размера.** На размерной линии каждой ячейки есть замок:
закрыт — `mode: 'fixed'`, ячейка держит размер при изменении габарита;
открыт — `mode: 'flex'`, тянется. Это делает поведение при росте изделия
предсказуемым и управляемым, а не магическим.

**Выделение.** Одиночное — клик. Диапазон — `Shift+click`. Произвольный набор —
`Ctrl/Cmd+click`. При множественном выделении панель свойств показывает общие
параметры; изменение применяется ко всем, различающиеся значения показаны как «—».

**Очистка.** `Delete` очищает наполнение. **Диалога подтверждения нет** —
действие обратимо, показывается тост «Очищено · Отменить».

## 7. НАПОЛНЕНИЕ

| Аспект | Содержание |
| --- | --- |
| Действие | Перетаскивание элемента (полки / ящики / штанга) из палитры в ячейку, либо выбор ячейки → выбор наполнения в панели |
| Отклик UI | Призрак следует за указателем с точкой захвата; ячейка-кандидат подсвечена; виден контур будущего результата |
| Домен | `SetFill` |
| Геометрия | Расчёт полок, коробов ящиков, положения штанги |
| Валидация | Пролёт полки (`CONFIRMED`-правило, см. функциональную спецификацию §1.3); глубина ящика против глубины корпуса; высота ячейки против высоты фасада ящика |
| Обратная связь | Каждая полка подписана размером; ящики показывают высоту фасада |
| Движение | Посадка призрака пружиной с передачей скорости; возврат в палитру при промахе |
| Ошибки | Недопустимая цель — нейтральная подсветка и `no-drop`, без красного. Красный зарезервирован за ошибками, а не за «сюда нельзя» |
| Клавиатура | Ячейка → `Enter` → список наполнения. Drag не единственный путь |

**Количество полок** правится числом или перетаскиванием отдельной полки.
Перетаскивание полки переводит её в `mode: 'manual'` — это видно по индикатору
на размерной цепочке, чтобы пользователь понимал, почему полка перестала
распределяться равномерно.

## 8. ФАСАДЫ

| Аспект | Содержание |
| --- | --- |
| Действие | Выбор секции → добавить фасад → тип, число створок, сторона петель, ручка |
| Отклик UI | На схеме появляются фасады; вид «фасад» показывает их, вид «разрез» — прячет |
| Домен | `AddFacade` / изменение `FacadeGroup` |
| Геометрия | Размер створок по `OverlaySpec`; количество петель по высоте |
| Валидация | Слишком широкая створка → предупреждение; слишком высокая при 2 петлях → предложение добавить петлю |
| Обратная связь | Направление открывания показано штриховым «уголком» на фасаде |
| Движение | Открывание двери в предпросмотре — по `ui`; прерываемо |
| Ошибки | Фасад на секцию, уже закрытую другим фасадом → предупреждение о пересечении |

Формулы зазоров — `ASSUMPTION` до теста T-DOOR-02. Значения зазоров вынесены
в настройки проекта, а не зашиты: пользователь может привести их к практике
своего цеха.

## 9. МАТЕРИАЛЫ

| Аспект | Содержание |
| --- | --- |
| Действие | Назначение материала по ролям: корпус, фасады, полки, задняя стенка, ящики |
| Отклик UI | Заливка деталей на схеме меняется немедленно |
| Домен | `SetMaterial` |
| Геометрия | Пересчёт только если у материала другая толщина; тогда — предупреждение о влиянии на все размеры |

текстуры, формат листа. Никаких брендовых каталогов и внешних источников —
это и требование автономности, и вопрос прав.

## 10. КРОМКА

| Аспект | Содержание |
| --- | --- |
| Действие | Правило по умолчанию (видимые торцы 2 мм / внутренние 0.4) либо ручная настройка по сторонам детали |

| Ошибки | Нет |

`T-EDG-03` не проверен, а разные производства считают по-разному.

## 11. ФУРНИТУРА

| Аспект | Содержание |
| --- | --- |
| Действие | Выбор крепежа корпуса, петель, направляющих, ручек, полкодержателей |
| Отклик UI | Спецификация пересчитывается немедленно; точки присадки появляются на схеме |
| Домен | `HardwareLibrary` + правила количества |
| Геометрия | Координаты отверстий (`DrillHole[]`) |

## 12. ПРОВЕРКА

| Аспект | Содержание |
| --- | --- |
| Действие | Открытие панели «Проблемы» (счётчик виден в статус-баре постоянно) |
| Отклик UI | Список сгруппирован по важности; клик — переход и подсветка объекта |
| Домен | Не меняется |
| Валидация | Полный прогон правил |
| Обратная связь | Ошибка = цвет + иконка + текст. Никогда только цвет |
| Движение | Плавная прокрутка к объекту, `ui`; при reduced motion — мгновенный переход |
| Ошибки | Часть проблем имеет однозначное исправление в один клик («добавить перегородку»), остальные — только объяснение |

Ошибки **не блокируют редактирование**. Они блокируют только экспорт
производственных файлов, и приложение прямо говорит, что именно мешает.

## 13. СОХРАНЕНИЕ

| Аспект | Содержание |
| --- | --- |
| Действие | Кнопка «Сохранить». Реализовано иначе, чем задумано: см. ниже |
| Отклик UI | Четыре состояния в тулбаре и строке состояния |
| Домен | `updatedAt` обновляется — и только здесь |
| Хранилище | Явная запись; вместе с проектом сохраняется превью для библиотеки |
| Обратная связь | Состояние видно всегда — пользователю без аккаунта нужна уверенность |
| Ошибки | Хранилище недоступно → постоянная плашка и настойчивое предложение экспорта |

**Изменено против замысла (PROMPT 22, подтверждено PROMPT 25 §24).**
Непрерывного сохранения нет: молчаливая запись поверх сохранённого
теряет работу, если пользователь экспериментировал. Раз механизма
автосохранения в приложении нет, PROMPT 25 предписывает его и не
вводить. Несохранённые правки видны постоянно, и библиотека отдельно
предупреждает о них перед открытием другого проекта.

Сценарий из задания проверяется E2E-тестом:
создать → закрыть браузер → открыть → продолжить → экспортировать → импортировать.

## 14. ЭКСПОРТ

| Аспект | Содержание |
| --- | --- |
| Действие | «Экспорт» в библиотеке (файл проекта) или PDF/XLSX в тулбаре |
| Отклик UI | Предпросмотр каждого формата до скачивания |
| Домен | Не меняется |
| Геометрия | Используется актуальный `Part[]` |
| Валидация | Есть ошибки → список с предложением исправить; выгрузка «как есть» доступна, но помечена |
| Обратная связь | Прогресс по этапам (для раскроя он ощутим); тост с именем файла |
| Ошибки | Сбой генерации → сообщение с указанием формата; остальные форматы выгружаются |

Всё формируется в браузере. Ни один байт проекта не уходит в сеть — сервера нет.

## 15. ИМПОРТ

| Аспект | Содержание |
| --- | --- |
| Действие | «Импорт из файла» в библиотеке |
| Отклик UI | Открывается импортированный проект; библиотека закрывается |
| Домен | Разбор → схема → миграция → нормализация → запись в библиотеку |
| Обратная связь | Проект появляется карточкой в библиотеке |
| Ошибки | Невалидный файл — понятное сообщение (`role="alert"`), текущий проект не затронут. Версия новее поддерживаемой — отказ с объяснением, без частичного применения |

**Изменено против замысла.** Расширение — `.json`, а не
`.furniture.json`: второе не даёт браузеру ничего нового и мешает
открыть файл текстовым редактором. Приёма перетаскиванием нет: выбор
файла кнопкой доступен с клавиатуры, а перетаскивание было бы вторым
способом того же действия.

Импорт **никогда не перезаписывает** открытый проект молча. Файл с тем
же идентификатором обновляет СВОЙ проект в библиотеке — это тот же
проект, вернувшийся с диска, а не новый.

## 16. СКВОЗНЫЕ ПРАВИЛА

| Правило | Реализация |
| --- | --- |
| Undo везде | `Ctrl/Cmd+Z`, глубина 200, восстанавливает и выделение |
| Ничего не теряется | Явное сохранение + постоянно видимое «есть несохранённые изменения» + восстановление последнего проекта + экспорт в файл |
| Ни одного тупика | На любом экране понятно, где я и как выйти |
| Ни одного обязательного диалога | Подтверждение — только для действительно необратимого |
