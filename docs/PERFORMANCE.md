# Performance

Измеренные величины, а не ожидания. Каждое число получено прогоном,
метод указан рядом.

---

## 1. РАЗМЕР СБОРКИ

`npm run build`, Vite 7, production:

| Чанк                   | Когда загружается         | Raw     | gzip       |
| ---------------------- | ------------------------- | ------- | ---------- |
| `index.js`             | всегда                    | 648 КБ  | **194 КБ** |
| `index.css`            | всегда                    | 45 КБ   | 8 КБ       |
| `pdf.js`               | при первом «Скачать PDF»  | 1158 КБ | 512 КБ     |
| `xlsx.js`              | при первом «Скачать XLSX» | 10 КБ   | 3 КБ       |
| `memory-repository.js` | если IndexedDB недоступен | 0.5 КБ  | 0.3 КБ     |

Реально передано при первой загрузке: **199 КБ**.

### Что было исправлено

До PROMPT 30 главный чанк весил **1809 КБ (695 КБ gzip)**: pdf-lib и
fontkit попадали в него всегда. Причина — не отсутствие `import()`, а
барредь: `export/index.ts` реэкспортировал `pdf.ts` и `xlsx.ts`, а
`workflow/readiness.ts` импортировал из этого барреля
`buildProductionExportData` и вычислялся на каждое изменение модели.
Динамический импорт в `app/export-actions.ts` при этом делить было уже
нечего.

Исправление: генераторы документов убраны из барреля и импортируются
напрямую и динамически. Главный чанк уменьшился на **64 %** (1809 → 648
КБ), gzip — на **72 %** (695 → 194 КБ). Пользователь, который не
выпускает документы, больше не платит за pdf-lib.

Правило на будущее: **`export/pdf.js` и `export/xlsx.js` импортируются
только через `await import()`**. Статический импорт любого из них
вернёт мегабайт в главный чанк.

## 3. РАСЧЁТ

Node 22, среднее по 20 прогонам, фикстуры из
`tests/unit/integration/fixtures.ts`:

| Проект           | Деталей | Геометрия | Производство | Готовность |
| ---------------- | ------- | --------- | ------------ | ---------- |
| Простой корпус   | 5       | 0.16 мс   | 0.53 мс      | 0.41 мс    |
| Корпус с полками | 8       | 0.09 мс   | 0.25 мс      | 0.48 мс    |
| Секции с дверью  | 7       | 0.10 мс   | 0.28 мс      | 0.35 мс    |
| Секции с ящиками | 11      | 0.14 мс   | 0.53 мс      | 0.56 мс    |
| Сложный проект   | 27      | 0.39 мс   | 1.03 мс      | 0.86 мс    |

Полный производственный конвейер — геометрия, детали, фурнитура,
присадка, раскрой, спецификация — укладывается в **одну миллисекунду** на
проекте из 27 деталей.

### Почему нет шкалы прогресса

Расчёт заканчивается быстрее, чем успевает отрисоваться индикатор.
Показывать этапы конвейера значило бы выдумать процесс (`PRODUCTION_UI.md`
§4).

### Почему нет виртуализации таблиц

Деталировка сложного проекта — 12 строк. Виртуализация нужна на тысячах;
вводить её на десятках значит усложнить код и сломать поиск по странице
ради воображаемой нагрузки.

## 4. ЧТО СЧИТАЕТСЯ И КОГДА

```
Проект изменился
   ↓
buildGeometry            ← useMemo по ссылке на изделие
   ↓
calculateProduction      ← useMemo, ОДИН раз на всё приложение
   ↓
статус · чеклист · восемь разделов производства · экспорт
```

`calculateProduction` вызывается один раз за изменение модели. До
PROMPT 29 результат считался и выбрасывался, а экспорт запускал конвейер
заново.

Что расчёт **не** запускает (проверено `tests/e2e/resources.spec.ts`):

- выбор детали в производстве;
- переключение раздела производства;
- масштабирование чертежа;
- перемещение мебели по комнате (зависимости `useMemo` сужены на
  PROMPT 26);
- переключение вида холста.

## 6. РЕСУРСЫ

Проверяется в браузере (`tests/e2e/resources.spec.ts`):

| Что                      | Проверка                   | Результат                        |
| ------------------------ | -------------------------- | -------------------------------- |
| Контекст WebGL           | 10 полных обходов разделов | холст один, контекст не теряется |
| Слушатели `window`       | те же 10 обходов           | не растут                        |
| Объектные URL            | два экспорта               | ровно по одному на документ      |
| Загрузки геометрии в GPU | переключение вида 6 раз    | остаётся 1                       |

Освобождение объектного URL отложено на 60 секунд намеренно
(`app/export-actions.ts`): браузер читает blob асинхронно, и ссылка,
отозванная сразу после клика, обрывает ещё не начавшееся сохранение.

## 7. КАК ПЕРЕИЗМЕРИТЬ

```bash
npm run build                     # размеры чанков
npx playwright test --project=chromium tests/e2e/resources.spec.ts
```

с `performance.now()`. Величины в этом документе обновляются вместе с
кодом: устаревшая таблица хуже отсутствующей.
