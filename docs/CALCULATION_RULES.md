# Правила расчёта: вход и указатель

PROMPT 49 §6. Единая точка входа в правила, по которым проект
превращается в детали.

**Это указатель, а не пересказ.** Формулы живут в пяти документах, и
переписывать их сюда значило бы завести шестой источник правды, который
разойдётся с остальными при первой же правке. Здесь — что где лежит,
какие правила сквозные и где документация расходится с кодом.

## Где какие правила

| Что считается | Канонический документ | Реализация |
| --- | --- | --- |
| Корпус, секции, ячейки, полки, фасады, задняя стенка, цоколь | `docs/GEOMETRY_RULES.md` | `src/geometry/` |
| Доменная модель: что вообще можно описать | `docs/DATA_MODEL.md` | `src/domain/` |
| Единицы и округление | `docs/UNITS_AND_PRECISION.md` | `src/domain/units.ts` |
| Фурнитура | `docs/HARDWARE_RULES.md` | `src/hardware/` |
| Раскрой листов | `docs/CUTTING_RULES.md` | `src/production/` |
| Присадка | `docs/DRILLING_RULES.md` | `src/drilling/` |
| Спецификация и сведение | `docs/PRODUCTION_BOM.md` | `src/bom/` |
| Порядок расчёта целиком | `docs/PRODUCTION_CALCULATION_PIPELINE.md` | `src/geometry/engine.ts` |

## Порядок расчёта

```
Project (источник истины)
   ↓
normalize   — габариты приводятся к допустимым, нарушения становятся Issue
   ↓
carcass     — боковины, крышка, дно, задняя стенка, цоколь
   ↓
layout      — дерево секций раскладывается в области; перегородки
   ↓
fill        — наполнение ячеек: полки, фасады ящиков, способ открывания
   ↓
facades     — распашные двери
   ↓
Part[]  → фурнитура → раскрой → присадка → спецификация → PDF / XLSX
```

Каждый этап получает результат предыдущего и **ничего не хранит**:
повторный вызов на том же проекте даёт тот же результат.

## Сквозные правила

Их стоит знать до чтения формул — из них следует почти всё остальное.

1. **Источник истины — `Project`.** Деталировка, фурнитура, раскрой и
   присадка не хранятся никогда: они выводятся при каждом обращении.
   Поэтому в приложении нет кнопки «Пересчитать» — устаревшего
   результата не бывает.
2. **Ячейка — это пространство, а не деталь.** В деталировку она не
   попадает. Деталь появляется только там, где есть физическая плита.
3. **Толщина корпуса — `Dimensions.panelThickness` (T).** От неё зависят
   внутренние габариты (`W − 2T`), положение горизонталей и координаты
   присадки.
4. **Толщина полки — `Shelf.thickness ?? material.thickness ?? T`.**
   Материал здесь сильнее общей толщины (PROMPT 13 §9). См. расхождение
   ниже.
5. **Всё в миллиметрах**, округление — в одном месте
   (`docs/UNITS_AND_PRECISION.md`). Смешения единиц в модели нет.
6. **Неподтверждённое правило не выдумывается.** Если правила нет, оно
   заводится в `docs/UNKNOWNS.json` с идентификатором, а приложение
   честно сообщает, что результата по нему не даёт. Проверяется
   `npm run check:assumptions`.

## Расхождение документации и кода

§6 требует не прятать такие места, а называть источник истины.

### Толщина детали против названия материала

**Расхождения между документом и кодом здесь нет** — оба правила
задокументированы и оба реализованы. Расходятся между собой **сами
правила**:

| Что | Откуда берёт толщину |
| --- | --- |
| Корпус (боковины, крышка, дно) | `panelThickness`, всегда (`carcass.ts` передаёт `thicknessOverride: T`) |
| Полка | `Shelf.thickness ?? material.thickness ?? T` |

Следствие видно в документах: деталь может быть 18 мм и при этом
подписана материалом «Корпусная плита 16 мм».

**Источник истины — код**, и он не менялся сознательно: `T` несёт
внутренние габариты и присадку, переписать корпус на толщину материала
значит изменить геометрию всех существующих проектов.

Что сделано вместо: правило проверки `THICKNESS_MATERIAL_MISMATCH`
(`src/validation/rules/thickness.ts`) называет расхождение обоими
числами и предлагает два выхода. Разбор — `docs/ACCEPTANCE_GAP_REGISTER.md`,
строка G-01.

## Как проверить, что правило действительно такое

Документ мог устареть; тест — нет. Для любого правила:

```bash
npx vitest run tests/unit/geometry     # корпус, секции, полки, фасады
npx vitest run tests/unit/production   # раскрой
npx vitest run tests/unit/drilling     # присадка
npx vitest run tests/unit/hardware     # фурнитура
npx vitest run tests/unit/bom          # спецификация
```

Если тест и документ расходятся — прав тест: он выполняется, а документ
читают. Расхождение при этом чинится в обе стороны, а не замалчивается.
