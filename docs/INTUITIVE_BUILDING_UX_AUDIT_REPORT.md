# Intuitive Building UX Audit Report

PROMPT 53. Может ли человек, впервые открывший приложение, сам дойти от
«хочу шкаф» до данных, по которым шкаф изготовят.

## Предмет аудита

| | |
| --- | --- |
| Repository | `ArtemU1453/FurnityreBuilder` |
| Branch | `claude/furniture-designer-audit-cjvvuf` |
| Commit | `8867f0f` |
| Version | `0.1.0` |
| Production URL | `https://artemu1453.github.io/FurnityreBuilder/` |
| Дата | 2026-09-10 |

Все выводы относятся к этому коммиту. Наблюдения сняты с **собранного**
приложения (`npm run build` → `vite preview`), окно 1440 × 900; там, где
размер окна меняет вывод, указаны также 1280 × 800, 1920 × 1080 и
390 × 844.

**Это аудит.** Ни одна строка кода приложения не изменена (§28).

## Короткий ответ

**Дойти можно. Предложенным путём — нет.**

Целевой объект — шкаф 1800 × 2200 × 600, три секции, полки, ящик, дверь,
материалы, производственные данные — построен полностью: 13 деталей,
8 позиций деталировки, 4 листа раскроя, 0 неразмещённых, 18 позиций
фурнитуры, использование листа 75.3 %, PDF и XLSX доступны.

Но чтобы его построить, пришлось:

1. прокрутить боковую колонку, чтобы увидеть первое поле;
2. **не** нажимать кнопку по умолчанию на шаге 4, иначе три секции
   превращаются в одну;
3. **не** выполнять инструкцию шагов 5 и 6 буквально: выбрать ячейку «в
   сцене» невозможно — нужно переключить вид на «Схему», о чём
   инструкция не говорит;
4. выбирать ячейку по строке вида
   `184c6b41-fb86-42ab-b1d4-b5716ca6a0a0 (578.7 × 2168)`.

Каждое из четырёх — измерено, не предположено.

## Что измерено

### Первое открытие

`h1` — «Новый проект». Заготовка 1000 × 2000 × 500, 5 деталей,
существует до первого действия. Поиск по всему видимому тексту не даёт
ни одного вхождения слов «шкаф», «тумба», «комод», «кухня», «шаблон»,
«тип изделия», «с чего начать», «начните», «подсказка», «как это
работает», «обучение», «тур». Выбора того, **что** строим, нет.

Положение первого поля:

| Окно | `Ширина` top | Видно без прокрутки |
| --- | --- | --- |
| 1440 × 900 | 888 px | **нет** |
| 1280 × 800 | 888 px | **нет** |
| 1920 × 1080 | 888 px | да |
| 390 × 844 (телефон) | в выдвижном листе | да, лист открывается кнопкой «Размеры» |

Лестница из одиннадцати шагов занимает y 125 … 760 — 635 px. Прокрутка
принадлежит боковой колонке (scrollHeight 1406 / clientHeight 708), а не
странице: `documentElement.scrollHeight === clientHeight === 900`.

### Создание базовой мебели

Ввод в «Ширина / Высота / Глубина» меняет сцену и «Результат расчёта»
немедленно, без применения. Это работает хорошо и без вопросов.

### Создание секций

Шаг 3: поле «Секций», кнопка меняет подпись на «Применить секций: 3».
После применения — 7 деталей, 3 секции, 2 перегородки, 3 ячейки. Верно.

### Шаг 4 отменяет шаг 3

| Действие | Деталей | Секций | Перегородок | Ячеек |
| --- | --- | --- | --- | --- |
| после «Применить секций: 3» | 7 | 3 | 2 | 3 |
| нажата кнопка по умолчанию «Применить сетку 1×1» | **5** | **1** | **0** | **1** |
| Ctrl+Z | 7 | 3 | 2 | 3 |

Диалог предупреждает поимённо («Будет заменено: 3 секции») и отмена
работает полностью. Но разрушительное действие — значение по умолчанию
следующего по счёту шага пронумерованной лестницы.

### Взаимодействие с пустым пространством

Вид по умолчанию — «Сцена». Девять кликов по разным точкам изделия:

| Что выбралось | Сколько раз из 9 |
| --- | --- |
| Задняя стенка (деталь) | 5 |
| Изделие 1 (весь объект) | 4 |
| **Ячейка** | **0** |

В виде «Схема» ячейки — `rect[role="button"]`, три цели по 160 × 600 px,
клик даёт ячейку сразу.

Пустое пространство внутри шкафа не является объектом взаимодействия в
том виде, который открыт по умолчанию.

### Добавление полок, ящиков, дверей

После выбора ячейки в «Схеме» всё работает:

| Действие | Результат |
| --- | --- |
| Шаг 5, «Полок в выбранной ячейке» = 4 | 11 деталей, полок 4 |
| Шаг 6, «ящики» | 12 деталей, фасадов ящиков 1 |
| Шаг 7, «Добавить дверь» | 13 деталей, дверей 1 |

Ящик даёт **только фасад**: короб не строится, и приложение говорит об
этом прямо и в панели, и в «Проверке» (`T-DRW-02`). Штанги в списке
наполнения нет (`Пусто / полки / ящики`) — намеренно, правило не
подтверждено.

### Модель выделения

Разбор выделения — чистая функция (`src/app/editor/selection.ts`),
порядок «деталь → ячейка → секция», выделение не попадает ни в
документ, ни в отмену. Модель хорошая. Проблема не в ней, а в том, что
в виде по умолчанию до ячейки не дотянуться.

### Контекстные действия

При выбранной ячейке инспектор даёт «Добавить дверь», «Добавить ящики»,
«Добавить полки» — прямо у объекта. Это **лучший путь в приложении**, и
он единственный, который нигде не предложен: лестница ведёт мимо него,
и ни одна подпись о нём не упоминает.

### Терминология

Слова, которые приложение употребляет и которые человек, покупающий
шкаф, не обязан знать. Кандидаты **перечислены, не изменены** (§28):

| Термин | Где | Чем сейчас объясняется |
| --- | --- | --- |
| Секция | шаг 3, инспектор | «Вертикальное деление корпуса перегородками» |
| Ячейка | шаги 4–7, инспектор | «Ячейка — пространство, а не деталь: в деталировку она не попадает» |
| Наполнение | шаг 6 | «Что стоит внутри выбранной ячейки» |
| Фасад | шаг 7 | «Фасад — деталь, механизм открывания — фурнитура» |
| Царга, антресоль, фальшпанель, свес | шаг 9 | подписью, без объяснения |
| Присадка | производство | разделом |
| Кромка | материалы, производство | «2/0/0.4/0.4 мм» |
| Деталировка, спецификация | производство | подписями |
| Накладной / вкладной | корпус, фасады | подписью |
| `Bounding box` | «Результат расчёта» | ничем |
| `Push-to-open` | метрика, открывание | ничем |
| `edges`, `drilling` | «Результат расчёта» | «Этапы конвейера геометрии, ещё не реализованные» |
| `back` | инспектор детали | «Деталь · back» |

Показательно, что первые четыре термина приложение **объясняет прямо в
подписи**. Это честно — и это же признак: интерфейс, которому
приходится определять собственные слова на месте, говорит на языке
модели, а не на языке человека.

### Навигация

Четыре экрана — `LABEL` с радиокнопкой, без `role="tab"`. Одиннадцать
шагов — кнопки со слипшимся доступным именем (`●1Размерытекущий шаг`).
Вкладка экрана «Производство» открывает шаг 10 «Проверка», а не
одноимённый шаг 11.

### Завершённость конструкции и переход к производству

Переход не требует ни подтверждения, ни пересчёта: производные величины
не хранятся. «Сводка» отвечает на вопрос «что получится, если выпустить
документы прямо сейчас» и называет ровно те числа, что уйдут в файл.
Готовность разложена по разделам (Геометрия, Материалы, Кромка, …) со
статусами и с идентификаторами неподтверждённых правил. Документы
формируются в браузере: «Ни один байт проекта не уходит в сеть».

Это самая понятная часть приложения. Претензий к переходу
конструкция → производство аудит не имеет.

### Иерархия информации

На каждом шаге под панелью параметров стоит блок «Результат расчёта» из
14 строк, где рядом соседствуют «Деталей», «Дверей», «Ручек»,
«Push-to-open», «Внутренняя ширина», «Bounding box» и сообщение о
нереализованных этапах конвейера. Величина, которая нужна человеку
(«получится 13 деталей»), лежит в одном ряду с величиной, которая
нужна разработчику.

## Что работает хорошо

Перечислено, чтобы перестройка это не сломала.

- Потеря работы называется **поимённо до того, как случится**, и
  полностью отменяется Ctrl+Z.
- Неподтверждённое правило не подменяется числом: `T-DRW-02` доходит от
  геометрии через BOM до статусной строки.
- Пересчёт производный — кнопки «Пересчитать» нет и не нужно.
- Инспектор предлагает действия по месту.
- Производственные данные полны и сходятся между разделами.
- Документы формируются офлайн, без единого сетевого запроса.
- **Телефон удобнее настольного окна.** На 390 × 844 холст занимает
  экран, шаг компактен («← Шаг 1 из 11 Размеры →»), параметры — в
  выдвижном листе, видимых органов 15. Мобильная раскладка решает ровно
  ту задачу, на которой спотыкается настольная.

## Вывод

Приложение **умеет** всё, что нужно для целевого объекта, и делает это
честно: не врёт о неподтверждённых правилах, не теряет работу молча, не
требует пересчёта, не ходит в сеть.

Непонятность у него не от бедности, а от того, что **лучшие пути в нём
не предложены**. Прямое взаимодействие с ячейкой существует — но в виде,
который не открыт по умолчанию. Контекстные действия существуют — но
лестница ведёт мимо них. Компактная раскладка существует — но только на
телефоне.

Из восьми требований интуитивного пути шесть уже где-то в продукте
выполнены. Разрыв — между «есть» и «предложено», и закрывается он
перестановкой предложенного, а не новой функциональностью.
