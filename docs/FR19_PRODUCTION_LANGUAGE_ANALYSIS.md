## Главное, что нашёл обход

Словарь не один. Их **четыре**, они в разных слоях, частью приватные, и
два из них **расходятся в словах для одного и того же**.

| Где | Что покрывает | Виден ли снаружи |
| --- | --- | --- |
| `src/app/vocabulary.ts` | `PartRole`, `HardwareKind`, `ObstacleKind` | экспортируется, но **слой `app` недоступен экспорту** |
| `src/production/parts.ts:92` `TYPE_NAMES` | `ProductionPartType` | **приватный**; используется только как запасное имя позиции |
| `src/export/part-drawing.ts:160,167` `EDGE_LABELS`, `GRAIN_LABELS` | стороны кромки, текстура | **приватные**; используются только чертежом |
| `src/export/data.ts:41` `PURPOSE_LABELS` | `HardwareKind` — **тот же перечень** | приватный |

Расхождение слов для одного и того же значения:

| `HardwareKind` | `app/vocabulary.ts` | `export/data.ts` |
| --- | --- | --- |
| `confirmat` | конфирмат | **корпусный крепёж** |
| `eccentric` | эксцентриковая стяжка | **эксцентрик** |
| `back-nail` | гвоздь задней стенки | **крепёж задней стенки** |

Это ровно то, что §4 запрещает: одно доменное понятие — один
авторитетный термин.

### Почему словарь нельзя оставить в `app`

`eslint.config.js`, `boundaries/element-types`:
`{ from: 'export', allow: ['export', 'bom', 'drilling', 'production', 'hardware', 'geometry', 'domain'] }`.
Слоя `app` в списке нет и быть не должно. Значит требование §12 — один
источник терминов для экрана, PDF и XLSX — **не может** выполняться
словарём из `app`. Он обязан лежать в `domain`, откуда его видят все.

То же ограничение в PROMPT 58 уже заставило `BACK_MOUNT_WORDS` жить в
`hardware/rules/fasteners.ts`, а не в `app/vocabulary.ts`.

## Что значит `none` на самом деле (§7)

```ts
/** Направление текстуры. Влияет на разрешённый поворот детали при раскрое. */
export type Grain = 'none' | 'along-length' | 'along-width';
```

`src/domain/materials/types.ts:29`. Смысл прослежен до места, где
значение **работает**, а не до словаря:

```ts
export function rotationAllowedFor(part, grain, settings): boolean {
  if (part.grainLocked) return false;
  if (settings.rotationPolicy === 'never') return false;
  return grain === 'none';
}
```

`src/production/parts.ts`. `none` означает: **у материала нет
направленной текстуры, поэтому деталь при раскрое можно поворачивать**.
Это не «не задано» и не «неизвестно» — это свойство материала, которым
раскрой пользуется прямо сейчас.

Отсюда и слово: **«без направления»**, а не «не задана» и не «нет».
«Нет текстуры» было бы неточно — декор у плиты может быть, направленным
он при этом не является. Чертёж уже говорит «Текстуры нет.» при
`none` — эту формулировку надо привести к той же, чтобы словарь остался
один.

## Почему в спецификации фурнитуры стоит цепочка UUID (§9)

Прослежено: `HardwareItem` (`src/hardware/types.ts:48`) несёт
`sourcePartId?: PartId`, `sourceNodeId?: NodeId`, `ruleId` и **`reason` —
готовую человеческую фразу**:

> `2 держателя на съёмную полку: по одному на каждый угол пласти`

`PartId` собирается как
`part:{furnitureId}/{nodeId}/{role}/{index}` (`src/domain/part/id.ts:23`)
— отсюда четыре UUID подряд.

Экран уже умеет большее, чем показывает: `itemOfSourcePart()` переводит
`sourcePartId` в `PartBOMItem`, у которого есть `name` — «Полка 2».
То есть **человеческое имя доступно из существующей модели**, выдумывать
сопоставление UUID → слово не требуется.

Выбор по §9: **B + C**. Человеческое объяснение происхождения —
основное; компактная ссылка на деталь — рядом; сам `PartId` остаётся в
`title` и в переходе, то есть прослеживаемость никуда не девается.

## Позиции без расчёта (§10)

Пять позиций не рассчитаны, и приложение уже говорит об этом честными
фразами — но называет позицию машинным ключом:

> Петли не рассчитаны: … Позиция **«hw-hinge»** ждёт таблицы порогов.

Правило верное, число не выдумано. Менять надо **имя позиции в фразе**,
а не смысл: «Позиция „петля“ ждёт таблицы порогов». Сами фразы живут в
`src/hardware/rules/*.ts` и являются текстом для человека, а не расчётом.

## План (§4, §11, §12)

| Решение | Почему так |
| --- | --- |
| Один словарь в **`src/domain/vocabulary.ts`** | единственный слой, видимый и `app`, и `export`, и `production`. Слова переносятся **дословно** из `app/vocabulary.ts` — новых синонимов не заводится |
| `src/app/vocabulary.ts` **реэкспортирует** доменный | ни один существующий импорт не ломается, определение остаётся одно |
| `PRODUCTION_PART_TYPE_LABELS` — рядом со своим перечислением, в `production` | `ProductionPartType` объявлен там; §2 запрещает двигать перечисления. Слова берутся из существующего `TYPE_NAMES` |
| `PART_CATEGORY_LABELS` — в `bom` | то же: `PartCategory` объявлен там |
| `PURPOSE_LABELS`, `EDGE_LABELS`, `GRAIN_LABELS` — **удаляются** | их работу принимает доменный словарь. Расхождение слов исчезает вместе с вторым определением |
| Домен, схема, сериализация, расчёты | **не трогаются** (§2). В файлах проектов и в моделях остаются `back`, `hw-hinge`, `none` |
