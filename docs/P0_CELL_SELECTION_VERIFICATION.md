## Remaining Limitations

Названы прямо, а не умолчаны.

1. **В трёхмерной сцене ячейка по-прежнему не выбирается.** Это не
   недосмотр, а решение. Наивное `includeVolumes: true` сделало бы
   некликабельной полку: передняя грань коробки ячейки ближе к камере,
   чем полка внутри неё, а `pick()` разводит только совпадающие
   расстояния. Правило, различающее «пустой объём» и «деталь внутри
   него», — это новая система выбора, которую PROMPT 54 §2 запрещает
   строить, пока работает существующая. Интерфейс теперь об этом не
   врёт: текст говорит «Отделения выбираются на схеме», а пустое
   состояние даёт кнопку «Открыть схему».

2. **Имена отделений позиционные, а не смысловые.** «Секция 2», а не
   «отделение для рубашек». Переименование отделения человеком
   потребовало бы поля в домене, схеме и миграции — за пределами P0.

3. **Штанги в списке наполнения нет** (`P-05`, `T-FILL-01`), и ящик даёт
   только фасад без короба (`T-DRW-02`). Оба — пробелы возможностей, а не
   понятности; PROMPT 54 §8 прямо запрещает показывать неподдержанное.

4. **Зависимость, потребовавшая правки за пределами P0** (§16):
   `Scene3D` вызывал `host.setPointerCapture(event.pointerId)` без
   защиты. Когда указателя с таким id уже нет, метод бросает, и на весь
   экран поднималась полоса «Приложение столкнулось с непредвиденной
   ошибкой» — из-за неудавшегося захвата в одном холсте. Обнаружено
   проверкой P0 на телефоне. Вызов обёрнут в `try/catch`: без захвата
   жест просто закончится на краю холста. Другие пункты аудита PROMPT 53
   (P1 «кнопка по умолчанию стирает шаг», P1 «поле габарита за экраном»)
   **не тронуты** — §16.
