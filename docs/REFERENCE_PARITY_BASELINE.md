## Статус аудита референса: НЕ ВЫПОЛНЕН

**Референс недоступен из среды выполнения.** Это не оговорка на будущее
и не осторожность — это результат проверки, проведённой сегодня заново.

### Что проверено в этой сессии

| Способ доступа | Хост | Результат |
| --- | --- | --- |
| `curl https://privetmaket.ru/garderob` | `privetmaket.ru` | код `000`, CONNECT-туннель обрывается |
| `curl https://privetmaket.ru/` | `privetmaket.ru` | код `000` |
| `curl http://privetmaket.ru/` | `privetmaket.ru` | код **403** от шлюза |
| `WebFetch` | `privetmaket.ru` | `EGRESS_BLOCKED: Access to privetmaket.ru is blocked by the network egress proxy` |
| Веб-архив, страница | `web.archive.org` | код `000` |
| Веб-архив, API доступности | `archive.org` | `Host not in allowlist: archive.org` |
| Поиск | — | отдаёт только маркетинговые описания: «бесплатный онлайн-конструктор», «3D-визуализация», «список материалов». **Ни одного наблюдения интерфейса** |

Диагностика шлюза подтверждает отказ на уровне политики, а не сбой сети:

```
kind: connect_rejected
detail: gateway answered 403 to CONNECT (policy denial or upstream failure)
```

То же самое было зафиксировано при составлении
`PRIVETMAKET_FUNCTIONAL_SPEC.md` (дата 2026-08-29) и повторно на
PROMPT 33. Три независимые проверки за три разные даты дали один
результат.

### Что это означает для PROMPT 52

Пункты §5–§9 требуют пройти референс **как пользователь** и записать
наблюдаемые экраны, зоны, органы управления и сценарий. Пункт §24
требует для каждого утверждения о референсе — наблюдение, и прямо
запрещает «probably», «likely», «seems» как основание для плана.

Наблюдений нет. Следовательно:

* `REFERENCE_SCREEN_MAP.md` — **не создан**;
* `REFERENCE_CONTROL_INVENTORY.md` — **не создан**;
* `REFERENCE_USER_FLOW.md` — **не создан**.

Создать их «по здравому смыслу» было бы **выдумыванием эталона**.
Дальше по этим документам строился бы rebuild plan, приложение
переделывалось бы под воображаемую структуру, и расхождение с настоящим
референсом обнаружилось бы только тогда, когда переделывать пришлось бы
второй раз.

Пятьдесят один PROMPT в этом проекте держались правила «не объявлять
проверенным то, что не проверено». Здесь оно применяется к самому
основанию задачи.

### Что доступно как evidence

| Источник | Что даёт | Класс |
| --- | --- | --- |
| `docs/PRIVETMAKET_FUNCTIONAL_SPEC.md` | спецификация от 2026-08-29 со статусами `CONFIRMED` / `INDUSTRY` / `UNKNOWN` по каждому пункту | вторичный, сам помечен «ЧАСТИЧНО ЗАБЛОКИРОВАН» |
| `docs/FUNCTIONAL_PARITY_MATRIX.md` | графа «Эталон» заполнена только `CONFIRMED` и `INDUSTRY`; догадки в неё не попадали | вторичный |
| `docs/UNKNOWNS.json` | 21 правило, не подтверждённое референсом, с идентификаторами | вторичный |
| Поисковая выдача | продукт существует, бесплатный конструктор, 3D, список материалов | маркетинговый, **не поведение интерфейса** |

Ни один из них не описывает **расположение зон, порядок панелей,
инвентарь органов управления и модель работы с ячейками** — то есть
ровно то, ради чего затеян PROMPT 52.

## Что сделано вместо

Половину работы, не зависящую от референса, можно выполнить честно —
и она выполнена полностью:

| Документ | Статус |
| --- | --- |
| `CURRENT_APP_SCREEN_MAP.md` | **готов** — геометрия зон снята со собранного приложения в пикселях |
| `CURRENT_APP_CONTROL_INVENTORY.md` | **готов** — 93 органа управления по четырём экранам плюс разбивка по 11 шагам |
| `CURRENT_APP_USER_FLOW.md` | **готов** — сценарий пройден целиком |
| `REFERENCE_PARITY_MATRIX.md` | **каркас готов**, колонка референса — `NOT VERIFIED` |
| `REFERENCE_OBSERVATION_PROTOCOL.md` | **готов** — что именно снять, когда доступ появится |

Когда референс станет наблюдаемым, останется заполнить одну колонку —
вторая половина матрицы уже собрана и измерена.

## Как разблокировать

Нужен доступ к `privetmaket.ru` **или** наблюдения, снятые человеком.
Достаточно любого из:

1. добавить `privetmaket.ru` в список разрешённых хостов среды;
2. приложить снимки экрана конструктора в разных состояниях —
   начальное, выбранная ячейка, несколько ячеек, открытые двери,
   ящики, дополнительные настройки;
3. приложить запись экрана прохождения сценария;
4. приложить сохранённую HTML-страницу конструктора.

Что именно нужно снять и в каком порядке —
`docs/REFERENCE_OBSERVATION_PROTOCOL.md`.

## Границы, зафиксированные до начала работ (§2, §3)

Разрешено анализировать: публично наблюдаемую структуру интерфейса,
расположение зон, сценарии, параметры, поведение элементов, паттерны.

**Запрещено и не будет использоваться:** исходный код референса, его
API и backend, логотипы, название бренда, фирменные тексты, фотографии,
графические материалы, платёжные механизмы.

Коммерческое завершение сценария (корзина, заказ, оплата) **не
копируется**: продукт остаётся бесплатным, без регистрации и без
серверной части. Локальный аналог финального действия — сохранение
проекта и выгрузка документов; он уже реализован.

Проверку самостоятельности продукта (`npm run check:brand`) это не
ослабляет: упоминание референса допустимо **только** внутри `docs/`, и
ни одна строка отсюда не попадает в собранное приложение.
