## Что вообще можно выбрать

Модель выделения — `src/app/editor/selection.ts`, чистая функция
`resolveSelection`. Четыре вида цели:

```
{ kind: 'part';      partId }   деталь
{ kind: 'cell';      nodeId }   ячейка — пространство
{ kind: 'section';   nodeId }   секция — область
{ kind: 'furniture' }           изделие целиком
```

Приоритет разбора: **деталь → ячейка → секция → изделие**. Выделение
хранится в сессии (`src/state/session-store.ts`), в документ не попадает
и в отмену не входит.

## Почему ячейка не выбирается в 3D — точная причина

Не недоделка и не ошибка. Это **сознательное решение, у которого не
построена вторая половина**.

`src/scene/raycast.ts`:

```ts
export interface PickOptions {
  /**
   * Разрешено ли попадать в невидимые объекты — ячейки и секции.
   *
   * По умолчанию нет: щелчок должен выбирать то, что человек видит.
   * Ячейка выбирается отдельным действием, иначе указатель всегда
   * попадал бы сначала в невидимую коробку ячейки, накрывающую полки
   * внутри неё (§21: «не выделять случайно весь корпус»).
   */
  readonly includeVolumes?: boolean;
```

`candidates()` отбрасывает объект, если `!object.visible` и
`includeVolumes !== true`. В `src/scene/adapter.ts` ячейки и секции
создаются с `visible: false` — они и есть пустой объём. `Scene3D`
вызывает `hitAt(x, y)` **без опций**, значит `includeVolumes` не задан,
значит ячейка не попадает в кандидаты **никогда**.

**«Ячейка выбирается отдельным действием» — этого отдельного действия в
интерфейсе нет.** Обещание в комментарии не выполнено ни одним органом
управления. Отсюда измеренные PROMPT 53 «9 кликов → 0 ячеек».

Опасение, ради которого это сделано, — настоящее: коробка ячейки
охватывает полки внутри себя, и её передняя грань ближе к камере, чем
полка. Включить объёмы «в лоб» — значит сделать полку некликабельной.
`pick()` разводит только совпадающие расстояния («при равном расстоянии
побеждает меньший объём»), а здесь расстояния разные.

## Как выделение меняет интерфейс

`describeSelection` возвращает `InspectorModel` со строками и
**действиями**, уже зависящими от состояния ячейки:

```ts
...(kind === 'drawers' ? [] : [{ kind: 'add-door', nodeId }]),
...(facade === undefined ? [] : [{ kind: 'remove-door', facadeId }]),
...(kind === 'empty' ? [{ kind: 'add-drawers', nodeId }] : []),
...(kind === 'empty' || kind === 'shelves' ? [{ kind: 'add-shelves', nodeId }] : []),
...(kind === 'empty' ? [] : [{ kind: 'clear-fill', nodeId }]),
```

Несовместимые действия не показываются вовсе. Это ровно то, чего просит
PROMPT 54 §8, — и оно уже написано.

Шаги 5 «Полки» и 6 «Наполнение» без выбранной ячейки показывают
`EmptyState` и, соответственно, 1 и 0 органов управления.

## Что уже есть для человекочитаемого имени

Всё необходимое **уже посчитано движком** и не требует ни нового поля в
домене, ни хранения:

```ts
interface CellBox { nodeId; box; sectionId; row; column; fill }
interface SectionBox { nodeId; index; box }
```

`sectionId`, `row`, `column`, `index` — этого достаточно, чтобы назвать
ячейку «Секция 2 · ряд 1, колонка 1», не заводя ни одной сущности.
Имя — производная величина, как и всё остальное в этом проекте.

## Решение, принятое на основании этого

По критерию PROMPT 54 §4 — «в каком режиме новый пользователь быстрее и
надёжнее выбирает нужное пространство» — ответ измерен: **«Схема»,
3 из 3 против 0 из 9**.

PROMPT 54 §2 запрещает строить новую систему выбора, когда рабочая уже
есть, и требует сделать существующую возможность очевидным основным
взаимодействием. Поэтому:

1. **«Схема» становится основным видом построения** и открывается по
   умолчанию. 3D остаётся на месте, в одном щелчке, без изменений.
2. Ячейка получает человекочитаемое имя, выводимое из геометрии, и это
   имя показывается везде одинаково; UUID остаётся внутренним.
3. Пустые состояния перестают обещать невозможное и дают **действие**, а
   не только совет.
4. Действия по выбранной ячейке (они уже есть) становятся видны там же,
   где ячейка выбрана.

Что **не** делается и почему: выбор ячейки в 3D не включается. Наивное
`includeVolumes: true` отняло бы возможность щёлкнуть полку — то самое,
от чего защищались авторы `pick()`. Правило, различающее «пустой объём»
и «деталь внутри него», — это новая система выбора, которую §2 прямо
запрещает строить, пока работает существующая. Ограничение записано в
`P0_CELL_SELECTION_VERIFICATION.md`.
