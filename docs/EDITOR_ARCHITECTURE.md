# Архитектура редактора

Документ описывает, как экран редактора устроен внутри и почему он
устроен именно так (PROMPT 22). Разметку и панели описывает
`docs/EDITOR_UI.md`, жесты — `docs/EDITOR_INTERACTION.md`, выделение —
`docs/EDITOR_SELECTION.md`.

---

## 1. Главное правило

**Интерфейс — потребитель движка, а не второе место, где считается
мебель.** Ни одна мебельная формула не живёт в React-компоненте: ни
толщина панели, ни ширина секции, ни количество петель. Компонент
получает уже посчитанный результат и показывает его.

Правило не декларативное. Оно проверяется:

* `eslint-plugin-boundaries` запрещает движку импортировать `app`
  (`tests/unit/architecture/boundaries.test.ts`, зонд `geometry → app`);
* чистые модули редактора (`selection.ts`, `resize.ts`) не импортируют ни
  React, ни CSS-модули — это проверяется чтением исходника, потому что
  случайный `import { useMemo }` компилируется молча;
* оба модуля покрыты тестами в окружении `node` без DOM
  (`tests/unit/app/`).

## 2. Поток данных

```
Project (документ)                 src/state/document-store.ts
  ↓ buildGeometry
GeometryResult                     src/geometry/
  ↓ buildDebugView
DebugSchemaView (прямоугольники)   src/render/debug-view.ts
  ↓
EditorCanvas                       src/app/editor/EditorCanvas.tsx
```

```
selectedNodes / selectedParts      src/state/session-store.ts
  + GeometryResult
  ↓ resolveSelection
SelectionTarget
  ↓ describeSelection
InspectorModel (строки + действия) src/app/editor/selection.ts
  ↓
Inspector                          src/app/editor/Inspector.tsx
```

Обратный поток — единственный и односторонний:

```
Жест / поле / кнопка
  ↓
Command                            src/state/commands.ts
  ↓ execute()
Project → пересчёт всего производного
```

Прямой записи в модель в интерфейсе нет. `SetDimension`, `SetFill`,
`AddFacade` и остальные команды существуют с PROMPT 2–15; редактор не
завёл ни одной новой.

## 3. Что было переиспользовано, а не написано заново

PROMPT 22 почти не добавил архитектуры — он подключил уже написанное и
до тех пор не использованное:

| Что | Появилось | Использовано редактором |
| --- | --- | --- |
| `session-store` (выделение, hover, панели) | PROMPT 2 | выделение объектов |
| `DragController` (захват указателя, порог, отмена) | PROMPT 2 | жест изменения габарита |
| `snapToStep` / `snapToCandidates` / `stepForModifiers` | PROMPT 2 | шаг и магниты жеста |
| `ProjectRepository` (IndexedDB + память) | PROMPT 2 | сохранение и восстановление |
| `buildDebugView` | PROMPT 4 | модель вида холста |
| `Button`, токены дизайн-системы | PROMPT 3 | тулбар, инспектор |
| `validateProductionReadiness` | PROMPT 21 | статус в тулбаре и строке состояния |

Второго хранилища, второго контроллера жеста и второго построителя вида
не появилось.

## 4. Три уровня состояния

Разделение, заведённое на PROMPT 2, редактор соблюдает буквально:

| Уровень | Где живёт | Отменяется по Ctrl+Z | Сохраняется в проект |
| --- | --- | --- | --- |
| Документ | `document-store` | да | да |
| Сессия (выделение, hover) | `session-store` | нет | нет |
| Жест (предпросмотр размера) | локальный `useState` холста | нет | нет |

Предпросмотр во время перетаскивания живёт на третьем уровне намеренно:
пока указатель движется, домен не меняется, геометрия не пересчитывается
и в историю ничего не пишется.

## 5. Производный результат не кэшируется

Геометрия, спецификация, раскрой, присадка и готовность считаются от
проекта в момент отрисовки. Кнопки «пересчитать» нет и быть не может:
кэша нет, значит нет и устаревшего результата. Это то же решение, что и
в `docs/PRODUCTION_WORKFLOW.md` §1, и именно оно закрывает требование
§27 «статус производства никогда не показывается устаревшим».

## 6. Границы

`src/app/**` вправе импортировать любой слой — это верхний слой. Все
остальные направления запрещены конфигурацией линтера и проверены
зондами. В частности:

* `geometry → app` — запрещено;
* `render → state` — запрещено: рендерер получает готовое и не отправляет
  команд;
* `interaction → domain` — разрешено (жест знает про миллиметры), но
  `interaction → geometry` не нужно и не используется.
