## Почему тег не опубликован

Не из осторожности и не потому, что процедура не готова. Отправка тега
отклоняется шлюзом:

```
$ git push origin refs/tags/v0.1.0:refs/tags/v0.1.0
error: RPC failed; HTTP 403
send-pack: unexpected disconnect while reading sideband packet
```

Четыре попытки с выдержкой 2, 4, 8 и 16 секунд — один и тот же ответ.
При этом **push веток в этой же сессии работает**: за сегодня их прошло
больше десяти. Отказ приходит именно на ссылки `refs/tags/*`.

**LOCAL PROCEDURE VERIFIED. REMOTE RELEASE EXECUTION NOT VERIFIED.**

Тег `v0.1.0` создан локально и указывает на `b619924` — коммит, прошедший
CI и опубликованный. Владельцу репозитория, чтобы завершить выпуск,
достаточно:

```bash
git tag -a v0.1.0 -m "Furniture Builder 0.1.0" b619924
git push origin v0.1.0
```

Дальше `release.yml` сделает остальное.

## Цепочка ворот показала себя на настоящем отказе

Не подстроенном. Коммит `8a733df` (тот же выпуск, до правки бюджета
времени) не прошёл E2E, и прогон №48 закончился так:

| Задача | Итог |
| --- | --- |
| `verify` | **failure** — «экспорт PDF и XLSX работает без сети» |
| `build-pages` | **skipped** |
| `deploy` | **skipped** |
| `smoke` | **skipped** |

**Сломанный коммит до production не дошёл.** До этого связь «красные
ворота → нет публикации» была подтверждена только устройством `needs`;
теперь она подтверждена происшествием.

Причина отказа разобрана, а не списана на нестабильность: у самого
тяжёлого сценария набора был бюджет по умолчанию — тридцать секунд,
столько же, сколько у теста с одним щелчком. Он ждёт догрузку полутора
мегабайт, затем строит PDF с вложенным шрифтом и книгу XLSX, и всё это
без сети. Локально — 2,5 секунды; на загруженном раннере не уложился.
`test.slow()` утраивает лимит; ни одно утверждение не тронуто, повтор
прогона не добавлен.

## Выкладка и выпуск

Оба механизма работают одновременно и не мешают друг другу:

| | Непрерывная выкладка | Выпуск |
| --- | --- | --- |
| Запускает | push в ветку по умолчанию | тег `vX.Y.Z` руками |
| Что даёт | свежее приложение по адресу | номер, тег, заметки, опознаваемость |

Коммит ≠ выпуск. Тег ставится **последним** — на коммит, который уже
прошёл CI и уже опубликован. Тег не выкладывает версию, он даёт имя
тому, что в production уже стоит и проверено.

## Откат по версии

Документирован и не требует поиска неизвестного коммита:
`git tag -l 'v*' --sort=-v:refname` → выбрать предыдущую стабильную →
вернуть её состояние обычным `revert` → цепочка ворот и выкладка
отработают сами.

Отдельно записано: **номер после отката не уменьшается.** Возврат кода —
это новый выпуск, а не воскрешение старого номера: две разные сборки под
одним номером невоспроизводимы.

Проверить откат на живом выпуске сегодня нельзя — выпущенных версий пока
ноль. Процедура описана, механика (revert → ворота → выкладка →
дымовая проверка) работает и подтверждена обычными прогонами.
