# Critical Regression Map

PROMPT 47 §15. Какой пользовательский путь чем сторожится, где это
выполняется и чем доказано.

Карта отвечает на один вопрос: **если этот путь сломается молча, кто
закричит?** Строка без ответа — это не покрытие, а надежда.

## Обозначения

| Тип | Что означает |
| --- | --- |
| E2E (prod) | сценарий Playwright на **production-сборке**, проект `chromium` |
| E2E (dev) | сценарий на dev-сервере, проект `chromium-dev` |
| E2E (live) | сценарий по **опубликованному адресу**, проект `production-smoke` |
| Unit | модульный или интеграционный тест `vitest` |
| Script | проверка-скрипт в `verify` |

Все перечисленные выполняются в CI на каждый push и **блокируют**
выкладку: `verify → build-pages → deploy → smoke`, задачи связаны
`needs`, красная проверка останавливает публикацию.

## Что НЕ покрыто автоматически — и почему

Пустая клетка честнее выдуманной. Полный разбор — в
`docs/ACCEPTANCE_GAP_REGISTER.md`.

| Что | Почему не автоматизировано |
| --- | --- |
| Отрисовка корневой границы ошибки на живой сборке | нужен аварийный люк в продукте; такой люк однажды выполнится у пользователя (G-05) |
| Время выполнения в браузере | абсолютный порог на общем железе CI измеряет раннер, а не продукт (G-06) |
| Настоящее устройство и мобильная сеть | устройства в CI нет, и заявлять его наличие нельзя (G-07) |
| Общее правило «разрушающее действие предупреждает» | правила такого в продукте пока нет; выдумывать его при закрытии пробелов нельзя (G-04) |

## Как проверить всю карту одной командой

```bash
npm ci
npm run verify                                   # скрипты, unit, сборка, бюджеты
npx playwright test --project=chromium           # E2E на production-сборке
npx playwright test --project=chromium-dev       # технический режим
PLAYWRIGHT_BASE_URL=<адрес> npm run smoke        # опубликованное приложение
```

Два проекта E2E запускаются по отдельности намеренно: вместе они
поднимают два сервера и мешают друг другу.
