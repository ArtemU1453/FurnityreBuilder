# Операции: всё одной таблицей

PROMPT 49 §11. Быстрый справочник для того, кто пришёл поддерживать
проект.

**Каждая команда здесь запущена и проверена**, а не переписана из
`package.json`. Дата проверки и её результат — в
`docs/MAINTAINABILITY_AUDIT_REPORT.md`.

Этот документ — указатель, а не второй источник правды. Подробности
живут в канонических документах, и ссылки на них стоят рядом с каждой
строкой.

## Требования среды

| | |
| --- | --- |
| Node.js | **20 или новее** (`package.json` → `engines`); проверено на 22.22 |
| Менеджер пакетов | **npm** (в репозитории `package-lock.json`) |
| Браузер для разработки | любой современный; приложению нужны WebGL 2 и IndexedDB |
| Браузер для E2E | Chromium, ставится `npx playwright install --with-deps chromium` |
| Переменные окружения | **обязательных нет.** Единственная читаемая — необязательная `APP_BASE` (сборка под подкаталог) |
| Сервер, база данных, ключи | не нужны: у продукта нет серверной части |

Файла `.env` в проекте нет и заводить его не требуется.

## Ежедневная работа

| Задача | Команда | Примечание |
| --- | --- | --- |
| Установить зависимости | `npm install` | для точного воспроизведения — `npm ci` |
| Запустить локально | `npm run dev` | http://localhost:5173 |
| Проверить типы | `npm run typecheck` | `vitest` типы НЕ проверяет — шаг обязателен отдельно |
| Линтер и границы слоёв | `npm run lint` | он же роняет сборку при импорте через границу слоя |
| Автоисправление линтера | `npm run lint:fix` | |
| Тесты | `npm run test` | модульные, property и интеграционные одним прогоном |
| Тесты в watch-режиме | `npm run test:watch` | |
| Один файл тестов | `npx vitest run tests/unit/geometry/fill.test.ts` | |

## Сборка и просмотр

| Задача | Команда | Примечание |
| --- | --- | --- |
| Production-сборка | `npm run build` | типы → Vite → манифест → service worker → `404.html` |
| Сборка под подкаталог | `APP_BASE=/репозиторий/ npm run build` | `docs/DEPLOYMENT.md` §2 |
| Посмотреть собранное | `npm run preview` | http://localhost:4173 |
| Перегенерировать значки | `npm run build:icons` | детерминирована: повторный запуск не меняет файлы |

## Проверки

| Задача | Команда | Что доказывает |
| --- | --- | --- |
| **Всё сразу** | `npm run verify` | девять проверок подряд, до первой упавшей |
| Реестр предположений | `npm run check:assumptions` | нет правила, придуманного без записи в `UNKNOWNS.json` |
| Самостоятельность продукта | `npm run check:brand` | ни одного внешнего запроса и упоминания референса |
| Бюджеты производительности | `npm run check:bundle` | семь метрик размера в пределах базы |
| Готовность пакета | `npm run check:release` | состав `dist/`, базовый путь, версия в бандле |
| Целостность публичного входа | `npm run check:public` | ссылка в README = фактический адрес публикации |
| E2E: продукт | `npx playwright test --project=chromium` | на production-сборке |
| E2E: технический режим | `npx playwright test --project=chromium-dev` | на dev-сервере |
| Дымовая по живому адресу | `PLAYWRIGHT_BASE_URL=<адрес> npm run smoke` | доехало ли то, что выложили |

Два проекта E2E запускаются **по отдельности**: вместе они поднимают два
сервера и мешают друг другу.

Порядок ворот, что чем блокируется и почему — `docs/CI_QUALITY_GATES.md`.

## Выпуск

| Задача | Команда / действие |
| --- | --- |
| Поменять версию | `package.json` → `version` — единственный источник |
| Записать изменения | `CHANGELOG.md`, раздел под номером версии |
| Выложить | push в ветку по умолчанию: CI сам проходит ворота, собирает и публикует |
| Отметить выпуск | `git tag vX.Y.Z && git push origin vX.Y.Z` — запускает `release.yml` |
| Проверить production | `PLAYWRIGHT_BASE_URL=<адрес> npm run smoke` |

Полностью, включая правила номера и откат — `docs/RELEASE_PROCESS.md`.

## Форматирование: чего здесь нет

`npm run format` и `npm run format:check` существуют, но **репозиторий не
отформатирован Prettier**: `npm run format:check` сообщает о 302 файлах.

Это не поломка и не долг, который нужно закрыть одним `--write`.
Обязательный стилевой рубеж в проекте — **ESLint** (`npm run lint`), он
в `verify` и в CI. Prettier настроен (`.prettierrc.json`), но ни в одни
ворота не входит и никогда не входил.

Запускать `npm run format` на всём репозитории **не нужно**: это дало бы
многотысячный diff, не изменив ни строчки поведения, и переписало бы
комментарии, набранные под конкретную ширину. Для нового файла — на
здоровье.

Записано здесь именно потому, что команда есть и выглядит как обязанность.
