# Присадка: почему семь правил дают ноль операций

PROMPT 66 §8. Короткий технический аудит. **Присадка не реализуется** —
задача в том, чтобы определить, отдельный это дефект или следующий этап
после крепежа.

Базовый коммит `20c40d0`. Кода не менялось.

## FACT — блокеров ДВА, и они разной природы

Это главный вывод аудита. Правила останавливаются не по одной причине.

### Блокер 1 — конструктивная связь не выражена в модели

`src/drilling/rules/relations.ts`:

> Присадка полкодержателей идёт не в полку, а в боковину, которая её
> держит. Присадка направляющей — не в ящик, а в стенку ячейки. Модель
> этого не знает: дерево секций описывает ПРОСТРАНСТВО, а не стыки.

Решать соседством запрещено намеренно: при вложенных секциях и
фальшпанелях рядом оказываются детали, ничем не соединённые, а лишнее
отверстие — брак, видимый только после сверления.

Диагностика: `DRILLING_RELATION_NOT_MODELLED`.

### Блокер 2 — параметры отверстий не подтверждены

```ts
export const EMPTY_DRILLING_PARAMETERS: DrillingParameters = {};
```

Ни диаметра, ни глубины, ни отступов, ни шага — ни для одного вида.
Диагностика: `DRILLING_PARAMETERS_NOT_CONFIRMED`.

### Какое правило чем заблокировано

| Правило | Связь | Параметры |
| --- | --- | --- |
| Петли | **есть** (створка известна) | **нет** |
| Ручки | **есть** (фасад известен) | **нет** |
| Push-механизмы | **есть** | **нет** |
| Корпусный крепёж | «нет» — **но см. находку ниже** | **нет** |
| Крепёж задней стенки | есть (панель известна) | **нет** |
| Полкодержатели | **НЕТ** | **нет** |
| Направляющие | **НЕТ** | **нет** |

**Пять правил из семи упираются только в параметры.** Настоящая нехватка
связи — у двух: полкодержателей и направляющих.

## Находка: один заявленный блокер устарел

`src/drilling/rules/fasteners.ts`, присадка корпусного крепежа:

```
не выбран тип крепежа … и в модели нет перечня стыков
«боковина ↔ горизонт»
```

**Перечень стыков есть.** `findCarcassJoints` в
`src/hardware/rules/fasteners.ts` строит его и находит все 8 стыков
контрольного изделия. Правило присадки его не видит, потому что живёт в
слое `drilling`, а `DrillingRuleContext` передаёт результат фурнитуры
(`ctx.hardware: HardwareBOM`) — позиции, но не стыки.

То есть блокер здесь не «модель не знает», а «слой не получает». Это
**не дефект расчёта** — ни одного лишнего или неверного отверстия не
возникает, — но формулировка вводит в заблуждение: она называет
недостающим то, что уже вычислено.

Тип крепежа, вторая половина той же фразы, действительно не выбирается:
`ConstructionScheme.jointType` существует и правилами не читается (см.
`CARCASS_FASTENER_RULE_ANALYSIS.md`).

## Ответ на вопрос §8: A или B

**И то и другое, в зависимости от правила.** Единого ответа нет, и это
результат, а не уклонение.

### B — зависимый следующий этап после крепежа

| Правило | Почему зависимый |
| --- | --- |
| Присадка корпусного крепежа | пока не подтверждено количество и не выбран тип (`PM-18`), сверлить нечего. Связь уже вычислена — надо лишь передать её в слой |
| Присадка крепежа задней стенки | зависит от шага (`PM-17`): точки крепления и есть точки сверления |

Для этих двух присадка — **прямое продолжение** `PM-18` и `PM-17`: один
и тот же источник даёт и количество, и, как правило, схему отверстий.

### A — отдельный дефект, от крепежа не зависящий

| Правило | Почему независимый |
| --- | --- |
| Присадка полкодержателей | нужна связь «боковина держит эту полку» — **новое понятие домена**, к `PM-18` отношения не имеющее |
| Присадка направляющих | нужна связь «стенка ячейки принимает направляющую» + `FR-04` + модель направляющей |
| Присадка петель | нужны параметры чашки; створка уже известна. От `PM-06` зависит лишь тем, что без петель нечего сверлить |
| Присадка ручек и push | нужны только параметры |

### Итог

```
PM-18 ──→ присадка корпусного крепежа      (B, зависимая)
PM-17 ──→ присадка задней стенки           (B, зависимая)
PM-06 ──→ присадка петель                  (B по количеству, A по параметрам)

Независимо: присадка полкодержателей       (A, нужна связь)
      присадка направляющих                (A, нужна связь + FR-04)
      присадка ручек и push                (A, нужны параметры)
```

## CONFIRMED RULE

**Нет ни одного параметра присадки.**

## UNCONFIRMED

Диаметры, глубины, отступы, шаги — для всех семи видов.

## DESIGN DECISION

| Решение | Обоснование |
| --- | --- |
| Присадку не реализовывать | §8 запрещает прямо |
| Связь «деталь-приёмник» не вводить | новое понятие домена, вводится под подтверждённое правило, а не заранее |
| Стыки в слой присадки не передавать | изменение продуктового кода без правила, которое им воспользуется |
| Формулировку устаревшего предупреждения не править | §12 запрещает менять продуктовый расчёт; текст предупреждения — часть выдачи. Зафиксировано здесь и в очереди |

## IMPLEMENTATION GAP

| Что | Когда осмысленно |
| --- | --- |
| Передать перечень стыков в `DrillingRuleContext` | вместе с реализацией `PM-18` |
| Поправить текст предупреждения корпусной присадки | тогда же |
| Ввести связь «деталь ↔ деталь-приёмник» | отдельная задача, после крепежа |
| Параметры присадки по видам | отдельный источник на каждый вид |

**Присадка не может стать следующей задачей.** Две трети её правил ждут
крепежа, а оставшаяся треть — собственного источника.
