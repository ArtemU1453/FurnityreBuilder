# Product Gap Register

PROMPT 51 §13. Пробелы продукта на коммите **`e10be44`**, версия
**0.1.0**.

Каждый пункт **воспроизводим**: рядом стоит, что сделать, чтобы увидеть
его своими глазами. Пунктов вида «улучшить расчёты», «улучшить UX» здесь
нет — они не проверяются, а значит и не закрываются.

**Пробел продукта и улучшение качества не смешиваются.** Здесь только
первое: функция, которая соответствует продуктовой цели и отсутствует
или не завершена. Качество живёт в `ACCEPTANCE_GAP_REGISTER.md`.

## Классификация

| Класс | Значение |
| --- | --- |
| `RELEASE BLOCKER` | без функции текущий выпуск заявлен неверно |
| `PRODUCT GAP` | соответствует продуктовой цели, отсутствует |
| `PARTIAL IMPLEMENTATION` | существует, не завершена |
| `FUTURE FEATURE` | для текущего выпуска не обязательна |
| `UNVERIFIED` | доказательств недостаточно, чтобы назвать правильное поведение |

## Реестр

### P-01 — задняя стенка не делится по размеру листа

| | |
| --- | --- |
| **Area** | Раскрой, задняя стенка |
| **Requirement** | Пользователь получает пригодный раскрой для обычного шкафа |
| **Current behavior** | Односекционный шкаф шире рабочей области листа даёт **неразмещённую деталь**: «Деталь 2260×1830 мм не помещается в рабочую область 2730×1810 мм», статус расчёта `INVALID` |
| **Expected behavior** | Задняя стенка, не влезающая в лист, делится на части — либо это прямо предлагается пользователю |
| **Evidence** | 1830 × 2260 × 580, одна секция → «Не размещено деталей: 1». Воспроизводится за минуту |
| **Classification** | `PRODUCT GAP` |
| **Severity** | HIGH — шкаф шириной 1830 мм это обычная мебель, а не крайний случай |
| **Recommended next action** | Делить заднюю стенку по размеру листа, а не только по секциям. **Обходной путь проверен и работает:** две секции + сегментация «По секциям» → неразмещённых 0. Но в интерфейсе он ничем не подсказан |

Сегментация в продукте есть (`BackPanelSpec.segmentation`: `single` /
`per-section`) и вынесена в интерфейс. Пробел именно в критерии деления:
он **по секциям**, а не по вместимости листа.

### P-02 — присадка не выдаёт ни одной операции

| | |
| --- | --- |
| **Area** | Присадка |
| **Requirement** | Производственные данные включают присадку |
| **Current behavior** | Раздел открывается, объясняет, чего не хватает, и даёт **0 операций** при любом проекте |
| **Expected behavior** | Координаты отверстий под петли, направляющие, полкодержатели, крепёж |
| **Evidence** | Сводка выгрузки: «Операций присадки: 0»; семь предупреждений `T-DRILL-01…05`, `T-HW-03`, `T-HW-07` |
| **Classification** | `UNVERIFIED` |
| **Severity** | HIGH для полноты производственных данных |
| **Recommended next action** | Подтвердить пять правил (диаметр чашки петли, шаг системы 32, отступы направляющих, межцентровое ручек, шаг крепежа задней стенки) из отраслевого источника и снять статус в `UNKNOWNS.json` |

Не `PRODUCT GAP`, а `UNVERIFIED`: код правил написан, не хватает не
реализации, а **подтверждённых чисел**. Выдумать их нельзя — присадка по
выдуманному шагу испортит деталь.

## Release blockers

**НЕТ НИ ОДНОГО.**

Ни один пункт не делает выпуск заявленным неверно: `RELEASE_NOTES.md` и
`PRODUCT_CAPABILITY_TRUTH.md` перечисляют ровно то, что работает, а
неподтверждённые правила продукт называет сам — предупреждением в
интерфейсе и в каждом выгруженном документе.

Единственная найденная неточность заявления — в
`FINAL_RELEASE_REPORT.md`, и она исправлена в этом же PROMPT (§17).

## Возможно неиспользуемый код (§7)

Механический поиск нашёл **37 экспортов**, чьё имя не встречается ни в
одном другом файле проекта, включая тесты. Примеры: `translate` и
`ORIGIN` в `domain/coordinates.ts`, `countNodes` и `replaceNode` в
`domain/furniture/tree.ts`, `DEFAULT_DIMENSIONS`, `resetSharedRepository`.

**Классификация: `Possibly unused`. Не `Confirmed dead`.** Метод имеет
известные ограничения: он не видит обращения через реэкспорт по
вычисляемому имени и совпадения имён. §7 прямо запрещает удалять код по
имени файла или по одному такому списку.

Ничего не удалено. Проверять — по одному символу: убрать экспорт,
прогнать `npm run typecheck && npm run test`, вернуть, если что-то
упало. Это работа на отдельный PROMPT, не на аудит.
