# Responsive Architecture

Как одно приложение работает на телефоне, планшете и десктопе — и почему
второго приложения для этого не заводится.

Мобильный UX подробно — `MOBILE_UX.md`. Жесты и указатель —
`TOUCH_INTERACTIONS.md`. Компоненты — `UI_SYSTEM.md`. Экраны —
`UX_ARCHITECTURE.md`.

---

## 1. ОДИН СЛОЙ РЕШЕНИЙ

```
Domain → Geometry → Production → Persistence → Renderer
                                                   ↓
                                            Responsive UI
```

Ниже линии никто не знает, какой сейчас экран, и знать не должен.
Изделие шириной 1800 мм остаётся изделием шириной 1800 мм при повороте
телефона; деталировка не зависит от того, каким пальцем её открыли.

Не существует и не может появиться:

- `MobileDomain`, `MobileProject` — вторая модель изделия;
- `MobileGeometry` — второй расчёт;
- `MobileRenderer` — второй рендерер;
- отдельного mobile-состояния приложения;
- отдельного mobile-хранилища.

Единственное место, где ширина окна превращается в решение, —
`src/app/layout.ts`. Он чистый: ни React, ни DOM, ни `window`, поэтому
разбор размеров на режимы проверяется обычным тестом
(`tests/unit/app/layout.test.ts`).

## 2. ТРИ РЕЖИМА

| Режим     | Когда                                                | Раскладка конструктора                                   |
| --------- | ---------------------------------------------------- | -------------------------------------------------------- |
| `mobile`  | ширина ≤ 600 px, **или** ширина ≤ 900 и высота ≤ 600 | холст на весь экран, параметры листом снизу              |
| `tablet`  | 601–900 px при высоте > 600                          | параметры │ холст                                        |
| `desktop` | > 900 px                                             | параметры │ холст │ инспектор (третья колонка с 1200 px) |

Значения не выдуманы: 600 / 900 / 1200 px живут в
`design-system/tokens.css` с PROMPT 26 и уже управляли раскладкой в CSS.
`layout.ts` их не заводит заново, а называет — одни и те же числа в
`@media` и в TypeScript, иначе CSS считал бы экран телефоном, а React в
тот же момент планшетом.

### Почему высота тоже решает

Телефон в альбомной ориентации — это 844×390. По одной ширине это
«планшет», и до PROMPT 28 он его и получал: две колонки, страница
1879 px при экране 390 px. Планшет в той же ориентации (1024×768) давал
958 px. Разница не в ширине, а в высоте — боковая колонка не помещается
по вертикали.

Поэтому «телефон» — это узкий экран **или** низкий и не широкий. Третьего
режима из этого не появляется: раскладка та же, что у телефона в
портрете. Широкое низкое окно на мониторе остаётся десктопом — там для
колонок место есть.

Замеры после изменения (высота страницы / высота экрана):

| Экран    | Конструктор | Помещение | Производство |
| -------- | ----------- | --------- | ------------ |
| 320×568  | 760         | 650       | 1577         |
| 390×844  | 884         | 844       | 1436         |
| 844×390  | 834         | 737       | 1203         |
| 768×1024 | 1251        | 1349      | 3164         |
| 1024×768 | 958         | 1325      | 3096         |
| 1440×900 | 900         | 900       | 2960         |

Горизонтального выхода за экран нет ни на одном из размеров.

## 3. ГДЕ ЖИВЁТ РЕШЕНИЕ О РЕЖИМЕ

| Что                       | Где                                 | Чем решает                      |
| ------------------------- | ----------------------------------- | ------------------------------- |
| Разбор размеров на режимы | `src/app/layout.ts`                 | `layoutModeOf(width, height)`   |
| Текущий режим в React     | `src/app/use-layout-mode.ts`        | `matchMedia` на границы режимов |
| Колонка или лист          | `src/app/screens/WorkspaceSlot.tsx` | `usesSheets(mode)`              |
| Лестница шагов или полоса | `src/app/App.tsx`                   | `usesFullStepRail(mode)`        |
| Плотность контролов       | `design-system/tokens.css`          | `@media (pointer: coarse)`      |
| Сама раскладка            | `*.module.css`                      | `@media` с теми же числами      |

`matchMedia`, а не слушатель `resize`: `resize` приходит на каждый
пиксель — при повороте телефона и при появлении экранной клавиатуры это
десятки событий подряд, и каждое перерисовывало бы дерево. `matchMedia`
сообщает ровно о том, что важно: пересечении границы режима.

Режим — состояние ИНТЕРФЕЙСА. Он не попадает ни в проект, ни в историю,
ни в сохранение, ни в экспорт.

---

## 4. ПЛОТНОСТЬ РЕШАЕТ УКАЗАТЕЛЬ, А НЕ ШИРИНА

Размер контролов задаётся `@media (pointer: coarse)`, а не контрольной
точкой ширины: планшет с пальцем и ноутбук с мышью бывают одной ширины, а
решает здесь именно указатель.

```css
@media (pointer: coarse) {
  :root {
    --h-control-sm: 2.25rem;
    --h-control-md: 2.75rem; /* 44 px */
    --h-control-lg: 2.75rem;
  }
}
```

Поднимается одно значение — и вслед за ним растут кнопка, значковая
кнопка, поле числа, список, ссылка пропуска навигации. Отдельных
мобильных компонентов для этого не заводится, а плотность десктопа не
меняется.

## 5. ЧТО НЕ РАЗДВАИВАЕТСЯ

| Вещь                    | Одна на все режимы                   |
| ----------------------- | ------------------------------------ |
| Модель проекта          | `FurnitureProject`                   |
| Команды                 | те же 44                             |
| Геометрия               | `buildGeometry`                      |
| Производственный расчёт | `calculateProduction`                |
| Хранилище               | IndexedDB через `persistence/`       |
| Рендерер                | собственный WebGL 2 над одним кубом  |
| События указателя       | Pointer Events + `setPointerCapture` |
| Привязка                | `room/snap.ts`                       |
| Компоненты              | одна design system                   |
| Лист и диалог           | один `Dialog`                        |
| Модель шагов            | один `workflow/steps.ts`             |

Меняется только **место** панелей и **плотность** контролов.
