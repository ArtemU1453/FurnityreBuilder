# Что каждый шаг конструктора делает с моделью

PROMPT 55 §9. Таблица существует затем, чтобы ошибка `FR-02` — когда
разрушительная операция оказалась действием по умолчанию созидательного
шага — не повторилась на другом шаге незамеченной.

| | |
| --- | --- |
| Repository | `ArtemU1453/FurnityreBuilder` |
| Branch | `claude/furniture-designer-audit-cjvvuf` |
| Порядок шагов | `src/app/workflow/steps.ts` |

## Три типа действий

| Тип | Что делает | Может ли быть действием по умолчанию |
| --- | --- | --- |
| `SAFE` | меняет только состояние интерфейса | да |
| `CONSTRUCTIVE` | добавляет или правит конструкцию | да |
| `DESTRUCTIVE` | удаляет или заменяет существующее | **нет** |

**Правило.** Действие по умолчанию шага никогда не `DESTRUCTIVE`.
Разрушительное действие обязано: называться тем, что делает; стоять
отдельно от созидательных; и спрашивать, когда есть что терять.

## Шаги

### 1. Размеры

* **Purpose:** габарит изделия и толщина плиты.
* **Default action:** ввод в поле — применяется немедленно.
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SetDimension`, `SetPanelThickness`.
* **Can remove previous work?** Нет. Дерево не трогается.
* **Expected user intention:** «сделать шкаф такого размера».

### 2. Корпус

* **Purpose:** задняя стенка и цоколь.
* **Default action:** переключатели и поля, применяются немедленно.
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SetBackPanel`, `SetPlinth`, `SetCarcassFlags`.
* **Can remove previous work?** Только собственные: «Задняя стенка → Нет»
  убирает деталь, которую сам же и добавляет. Дерево секций не трогается.
* **Expected user intention:** «из чего собран короб».

### 3. Секции

* **Purpose:** вертикальное деление корпуса перегородками.
* **Default action:** «Применить секций: N».
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SetSectionCount` — правит **хвост** списка секций.
* **Can remove previous work?** При уменьшении числа секций — да, и
  ровно настолько, насколько попросили. Идентичность оставшихся секций
  сохраняется (PROMPT 7 §14–15), поэтому наполнение нетронутых секций
  переживает изменение.
* **Expected user intention:** «сделать N отделений по ширине».

### 4. Ячейки

* **Purpose:** ряды и колонки **внутри выбранного отделения**.
* **Default action:** «Разделить «имя отделения» на R×C».
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SplitNode` (+ `SetFill` для полок) внутри
  транзакции — один шаг истории.
* **Can remove previous work?** Только внутри выбранного отделения, и
  только когда там уже что-то есть — тогда спрашивает. За пределами
  отделения не меняется ничего.
* **Expected user intention:** «поделить это отделение на полки/колонки».

**Отдельное `DESTRUCTIVE` действие этого шага:** «Пересобрать всё
изделие сеткой R×C» (`SetRoot`). Стоит за собственным раскрытием
«Начать внутреннее устройство заново», подписано тем, что делает, и
спрашивает, называя потерю поимённо.

> **Здесь и был `FR-02`.** До PROMPT 55 действием по умолчанию этого
> шага была именно пересборка всего изделия, под подписью «Применить
> сетку N×M». Три секции предыдущего шага исчезали при значениях по
> умолчанию: 7 деталей / 3 секции / 2 перегородки → 5 / 1 / 0.

### 5. Полки

* **Purpose:** число полок в выбранном отделении.
* **Default action:** поле «Полок в выбранной ячейке», немедленно.
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SetFill` на одном узле.
* **Can remove previous work?** Уменьшение числа убирает полки — то, что
  и просят. Соседние отделения не трогаются.
* **Expected user intention:** «столько полок здесь».

### 6. Наполнение

* **Purpose:** что стоит внутри выбранного отделения.
* **Default action:** переключатель «Пусто / полки / ящики».
* **Safe?** `CONSTRUCTIVE`, кроме «Пусто».
* **State changes:** `SetFill`.
* **Can remove previous work?** «Пусто» очищает отделение — но это и
  есть выбранный пункт, а не побочный эффект перехода на шаг.
* **Expected user intention:** «пусть здесь будут ящики».

### 7. Фасады

* **Purpose:** двери и фасады ящиков.
* **Default action:** выбор отделения в списке — `SAFE`.
* **Safe?** `SAFE` (выбор) и `CONSTRUCTIVE` («Добавить дверь»).
* **State changes:** `AddFacade`, `RemoveFacade`, `UpdateFacadeLeaf`, `SetFill`.
* **Can remove previous work?** «Убрать дверь» — по прямой просьбе.
* **Expected user intention:** «закрыть это отделение дверью».

### 8. Материалы

* **Purpose:** плита и кромка по ролям.
* **Default action:** поля и списки, немедленно.
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `UpsertMaterial`, `SetMaterialAssignment`, `SetDefaultMaterial`.
* **Can remove previous work?** Нет. Дерево не трогается.
* **Expected user intention:** «из чего это сделано».

### 9. Конструкция

* **Purpose:** свесы, столешница, антресоль, крепление, фальшпанели.
* **Default action:** поля и переключатели, немедленно.
* **Safe?** `CONSTRUCTIVE`.
* **State changes:** `SetOverhang`, `SetCountertop`, `SetMezzanine`, `SetMounting`, `AddFalsePanel`, `RemoveFalsePanel`.
* **Can remove previous work?** «Убрать фальшпанель» — по прямой просьбе.
* **Expected user intention:** «добавить надстройку к готовому коробу».

### 10. Проверка

* **Purpose:** готовность к производству по разделам.
* **Default action:** нет — раздел только читает.
* **Safe?** `SAFE`.
* **State changes:** никаких.
* **Can remove previous work?** Нет.
* **Expected user intention:** «всё ли в порядке».

### 11. Производство

* **Purpose:** деталировка, чертежи, присадка, раскрой, фурнитура, документы.
* **Default action:** просмотр; «Скачать PDF / XLSX» — выгрузка.
* **Safe?** `SAFE`. Экспорт документ не меняет.
* **State changes:** никаких. Всё производное и не хранится.
* **Can remove previous work?** Нет.
* **Expected user intention:** «забрать данные для изготовления».

## Разрушительные действия и где они живут

| Действие | Где | Спрашивает |
| --- | --- | --- |
| Пересобрать всё изделие сеткой | шаг «Ячейки», за раскрытием «Начать внутреннее устройство заново» | да, называя потерю поимённо |
| Разделить занятое отделение | шаг «Ячейки», то же главное действие | да, когда внутри уже есть деление или наполнение |
| Уменьшить число секций | шаг «Секции» | нет — уменьшение и есть просьба |
| «Пусто» в наполнении | шаг «Наполнение» | нет — это выбранный пункт |
| Убрать дверь / фальшпанель | шаги «Фасады», «Конструкция» | нет — это отдельные кнопки «убрать» |

Все они отменяются через Ctrl+Z.

## Как проверять новый шаг

1. Назвать намерение человека одной фразой.
2. Выписать команды, которые выполняет действие по умолчанию.
3. Есть ли среди них `SetRoot`, `CollapseNode`, `SetRoom(undefined)`,
   `replaceProject` или `SetFill` на узле, который человек не выбирал?
   Если да — действие `DESTRUCTIVE` и по умолчанию быть не может.
4. Проверить тестом, что после действия по умолчанию число секций,
   перегородок и деталей не уменьшилось
   (`tests/e2e/construction-safety.spec.ts`,
   `tests/unit/app/divide-cell.test.ts`).
