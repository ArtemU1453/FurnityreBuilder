# Доступность

PROMPT 26 §29. Что проверено, как устроено и почему именно так.

Смежные документы: `UI_SYSTEM.md`, `UX_ARCHITECTURE.md`,
`MOTION_GUIDELINES.md` §8.

## 1. Принцип

Доступность не добавляется в конце. Она встроена в компоненты design
system, поэтому её не нужно помнить в каждом месте использования:
`Field` сам связывает сообщение с полем, `IconButton` не существует без
имени, `SegmentedControl` — это настоящая радиогруппа.

## 2. Клавиатура

Всё управление доступно без указателя.

| Элемент | Клавиши |
|---|---|
| Ссылка пропуска навигации | Первый Tab на странице |
| Разделы приложения | Tab на группу, стрелки между разделами |
| Вид холста, вид камеры | То же: радиогруппа |
| Поля и переключатели | Tab, ввод, пробел |
| Объекты на схеме | Tab между объектами, Enter — выбрать |
| Размеры на сцене | Правятся полями инспектора, а не только ручками |
| Диалог | Esc закрывает, фокус заперт внутри, по закрытии возвращается |

Сцена и планировщик — не единственный способ управления: всё, что
делается перетаскиванием, делается и числом в инспекторе. Без этого
планировщик был бы недоступен с клавиатуры вовсе.

## 3. Фокус

`:focus-visible`, а не `:focus`: рамка появляется при работе с
клавиатуры и не мешает при работе мышью. Толщина —
`--border-focus` (2px), отступ 1–2px, цвет `--focus-ring`.

Отдельного внимания потребовали составные элементы: у сегмента
переключателя фокус получает спрятанная радиокнопка, а рамка рисуется
вокруг видимой подписи.

Найдено аудитом и исправлено: радиокнопки сегментов имели нулевой
размер. Нажатие доходило до них через подпись, но сам элемент управления
был недостижим — ни для автоматизации, ни для вспомогательных
технологий, которые целятся в него, а не в текст рядом. Теперь кнопка
перекрывает сегмент целиком и вытянута до 44px по высоте.

## 4. Имена и роли

* Кнопка-иконка: `aria-label` обязателен и совпадает с подсказкой.
* Панель: `aria-labelledby` на видимый заголовок — одно и то же слово
  читают и глазами, и скринридером.
* Инспектор: имя ориентира ПОСТОЯННОЕ («Свойства объекта»,
  «Свойства помещения»), а заголовок внутри меняется с выделением.
  Область, которая переименовывается при каждом щелчке, в списке
  ориентиров ненаходима.
* Холст, сцена и планировщик: `role="img"` с описанием, включающим
  габариты, число деталей и число ошибок. Картинка, о которой нечего
  сказать, для скринридера не существует.
* Списки — настоящие `<ul>`/`<dl>`, а не `<div>` с отступами.

## 5. Цвет и контраст

Цвет никогда не единственный носитель смысла:

* у состояния всегда есть подпись словами;
* точка состояния различается формой — сплошная у ошибки, кольцо у
  «нужно подтверждение»;
* пункт чеклиста готовности несёт значок `✓ ! ? ✕` помимо тона;
* сообщение поля начинается со знака, а не только окрашивается.

Тона состояний переопределены для тёмной темы отдельно. До этого этапа
пять мест использовали захардкоженные `#1c7c40` и `#b3261e`, которые в
тёмной теме оставались тёмными пятнами на тёмном фоне.

## 6. Движение и прозрачность

`prefers-reduced-motion: reduce` — пружины заменяются коротким
переходом, отскок снимается, прямое перетаскивание сохраняется
(`MOTION_GUIDELINES.md` §8).

Полупрозрачная поверхность в приложении одна — верхняя строка. Панели
непрозрачны: под ними ничего нет, и размытие было бы декорацией.
Стопки «полупрозрачное на полупрозрачном», при которых текст перестаёт
читаться, в приложении нет по построению.

## 7. Размер текста

Все размеры в `rem`. Системное увеличение текста масштабирует раскладку,
а не ломает её: панели тянутся, сетка карточек перестраивается,
горизонтальной прокрутки не появляется.

Исключение — текст внутри SVG-чертежей: там единица измерения
миллиметр чертежа, и подпись масштабируется вместе с чертежом.

## 8. Касание

* Минимальная зона попадания 44×44 px у всех интерактивных элементов.
  Достигается прозрачным расширением, а не увеличением рисунка: кнопка
  остаётся 32px, попасть в неё можно с 44.
* `touch-action: none` на всех холстах: иначе браузер начинает
  прокручивать страницу и жест срывается на первом движении пальца.
* Захват указателя (`setPointerCapture`) на время жеста: палец может
  уйти за границы элемента.
* Никаких действий по наведению: подсказка кнопки-иконки появляется и по
  фокусу, а не только под курсором.

## 9. Что проверяется автоматически

| Проверка | Где |
|---|---|
| Ссылка пропуска навигации работает | E2E |
| Объект холста выбирается с клавиатуры | E2E |
| Ошибка объясняется текстом и не блокирует ввод | E2E |
| Кнопки отключены, когда действие недоступно | E2E |
| Размеры правятся без мыши | E2E |
| Разделы переключаются с клавиатуры | E2E |
| `planMotion` уважает reduced motion | Модульный тест |
| Слои не импортируют React и DOM | Архитектурный тест |

## 10. Что НЕ проверено автоматически

Честно: контраст токенов измерен вручную по формуле WCAG при их
введении (PROMPT 5), но автоматической проверки контраста в CI нет.
Скринридером интерфейс не проверялся — только разметка и роли. Это
остаётся известным ограничением, а не выполненным пунктом.
